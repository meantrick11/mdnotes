# 标准 Transformer：一个句子从输入到输出经历了什么？

> 本笔记以 **2017 年论文《Attention Is All You Need》中的
> Encoder--Decoder Transformer**
> 为主线，解释一个句子如何从文本变成向量，经过编码器与解码器，最终逐
> token 生成输出。
>
> 先建立一个重要认识：Transformer
> 并不是把一句话整体"塞进模型，再整体吐出另一句话"。它会先把文本转换为
> token 序列，再把 token
> 转换为向量；模型在这些向量上进行注意力计算与特征变换；最后将解码器当前位置的隐藏状态映射为词表上的概率分布，逐步生成
> token。

------------------------------------------------------------------------

## 1. 全流程总览

假设输入句子是：

``` text
我 喜欢 机器 学习
```

为了说明流程，假设分词后得到 4 个 token，模型隐藏维度
`d_model = 512`。这里的分词结果仅作示例，真实 tokenizer
不一定按汉字或词语这样切分。

``` mermaid
flowchart TD
    A["输入文本<br/>我喜欢机器学习"] --> B["Tokenizer 分词 / 子词切分"]
    B --> C["Token IDs<br/>[101, 203, 305, 407]"]
    C --> D["Embedding 查表<br/>[L, 512]"]
    D --> E["加入位置编码<br/>词义信息 + 位置信息"]
    E --> F["Encoder × N 层<br/>Self-Attention + FFN"]
    F --> G["Encoder 输出 H_enc<br/>[L, 512]"]
    G --> J["Decoder 的 Cross-Attention"]
    K["目标序列右移输入<br/>训练时为真实前缀；推理时为已生成前缀"] --> L["目标 Embedding + 位置编码"]
    L --> M["Decoder × N 层<br/>Masked Self-Attention"]
    M --> J
    J --> N["Feed Forward + 残差 / 归一化"]
    N --> O["Linear 映射到词表维度"]
    O --> P["Softmax 得到下一个 token 的概率分布"]
    P --> Q["选择 / 采样下一个 token"]
    Q --> R{"是否生成 EOS？"}
    R -- "否：追加 token，继续下一步" --> K
    R -- "是" --> S["输出 token 序列"]
    S --> T["Tokenizer Decode"]
    T --> U["最终文本"]
```

### 阶段速览

  -------------------------------------------------------------------------------------------------
  阶段              输入              主要操作                             输出状态
  ----------------- ----------------- ------------------------------------ ------------------------
  1\. 文本输入      原始字符串        接收文本                             字符串

  2\. Tokenization  字符串            切分 token                           token 序列

  3\. 数字化        token             映射到词表 ID                        整数序列

  4\. Embedding     token ID          查 embedding 矩阵                    向量矩阵

  5\. 位置编码      token 向量        注入位置信息                         带位置信息的向量

  6\. Encoder       源序列向量        自注意力、前馈网络等                 源序列上下文表示

  7\. Decoder       已有目标前缀 +    掩码自注意力、交叉注意力、前馈网络   当前目标位置的隐藏状态
                    Encoder 输出                                           

  8\. 输出层        隐藏状态          Linear + Softmax                     词表概率分布

  9\. 解码          概率分布          贪心、采样或 Beam Search 等          下一个 token

  10\. 文本还原     token 序列        Decode                               最终字符串
  -------------------------------------------------------------------------------------------------

------------------------------------------------------------------------

## 2. 阶段一：输入文本（Raw Text）

模型接收到的是一段原始文本，例如：

``` text
我喜欢机器学习
```

此时它还不是模型可以直接进行矩阵运算的输入。计算机当然可以处理字符串，但
Transformer 的核心计算需要数值张量，因此必须先进行 Tokenization
和数字化。

**这一阶段的状态：**

-   数据类型：字符串（String）。
-   内容：人类可读的自然语言文本。
-   尚未形成模型内部的向量表示。

------------------------------------------------------------------------

## 3. 阶段二：分词（Tokenization）

### 3.1 作用

Tokenizer 根据词表和切分规则，把原始文本切分成 token。

例如，为了便于理解，假设：

``` text
输入：我喜欢机器学习

Tokens：
["我", "喜欢", "机器", "学习"]
```

但实际模型可能使用 BPE、WordPiece、Unigram 等子词算法，切分结果可能是：

``` text
["我", "喜", "欢", "机器", "学习"]
```

也可能将某个词拆成多个子词。Tokenizer
的具体行为取决于模型使用的词表和算法。

### 3.2 为什么不直接以整句话为单位？

如果把每一种完整句子都作为一个独立词汇，词表会非常庞大，而且遇到新词、新组合时难以处理。

子词切分可以在词表规模与文本表达能力之间取得平衡：

-   常见词可以作为整体 token。
-   低频词可以拆成多个子词。
-   未登录字符串也有机会通过更小的单位表示。

### 3.3 Token ID：将 token 转换成整数

Token 本身仍然是符号，需要映射到词表中的整数 ID。

例如：

  Token     Token ID（示例）
  ------- ------------------
  我                     101
  喜欢                   203
  机器                   305
  学习                   407

最终得到：

``` python
token_ids = [101, 203, 305, 407]
```

这里的 ID 只是索引，不代表词语之间存在大小、距离或语义关系。ID 为 407 的
token 并不比 ID 为 101 的 token "更大"或"更重要"。

**这一阶段的状态：**

-   Token 序列：`[我, 喜欢, 机器, 学习]`
-   Token ID 序列：`[101, 203, 305, 407]`
-   张量形状（单句、未计入 batch）：`[L]`，本例 `L = 4`。

------------------------------------------------------------------------

## 4. 阶段三：词嵌入（Token Embedding）

### 4.1 作用

Token ID 只是整数索引，无法直接表达词语的语义。Embedding
层通过一个可学习的嵌入矩阵，把每个 token ID 映射成一个高维稠密向量。

假设：

-   词表大小为 `V`。
-   模型隐藏维度为 `d_model = 512`。
-   Embedding 矩阵为 `E ∈ R^(V×512)`。

每个 Token ID 对应矩阵中的一行：

``` text
ID 101 → E[101] → 512 维向量
ID 203 → E[203] → 512 维向量
ID 305 → E[305] → 512 维向量
ID 407 → E[407] → 512 维向量
```

于是，原来的整数序列：

``` text
[101, 203, 305, 407]
```

变成一个向量矩阵：

``` text
X_emb ∈ R^(4×512)
```

可以把它理解为：

``` text
token 1 → [0.12, -0.31, ..., 0.08]  # 512 维
token 2 → [0.27,  0.15, ..., 0.42]  # 512 维
token 3 → [-0.11, 0.62, ..., 0.19]  # 512 维
token 4 → [0.38, -0.05, ..., 0.21]  # 512 维
```

上面的数值只是示意，不是某个真实模型的 embedding。

### 4.2 Embedding 到底表示什么？

Embedding
是模型学习到的向量表示。训练过程中，模型会调整嵌入矩阵，使其能够支持后续任务。

注意：Embedding 不等于已经理解了整个句子。

例如，"苹果"在不同语境下可能表示水果或公司。初始 Token Embedding 是
token 对应的基础向量；后续经过多层上下文计算后，该位置的表示才会融入周围
token 的信息。

**这一阶段的状态：**

-   输入：`[L]` 的整数 ID 序列。
-   输出：`[L, d_model]` 的浮点向量矩阵。
-   本例：`[4, 512]`。

------------------------------------------------------------------------

## 5. 阶段四：位置编码（Positional Encoding）

### 5.1 为什么需要位置编码？

Self-Attention 本身并不天然知道 token 的先后顺序。

例如：

``` text
我 喜欢 机器 学习
机器 喜欢 我 学习
```

如果只考虑 token
向量之间的注意力关系，而没有任何位置信息，模型就缺少明确的序列顺序线索。

因此，Transformer 需要向表示中注入位置信息。

### 5.2 如何加入位置？

原始 Transformer 使用固定的正弦、余弦位置编码：

\[
PE(pos,2i)=`\sin`{=tex}`\left`{=tex}(`\frac{pos}{10000^{2i/d_{model}}}`{=tex}`\right`{=tex})
\]

\[
PE(pos,2i+1)=`\cos`{=tex}`\left`{=tex}(`\frac{pos}{10000^{2i/d_{model}}}`{=tex}`\right`{=tex})
\]

其中：

-   `pos`：token 在序列中的位置。
-   `i`：向量维度相关的索引。
-   `d_model`：模型隐藏维度。

每个位置会得到一个与 token embedding
维度相同的位置向量，然后逐元素相加：

\[ X = X\_{emb} + PE \]

例如：

``` text
位置 0：Embedding("我")   + PE(0)
位置 1：Embedding("喜欢") + PE(1)
位置 2：Embedding("机器") + PE(2)
位置 3：Embedding("学习") + PE(3)
```

### 5.3 位置编码后的状态

``` text
X ∈ R^(4×512)
```

形状没有变化，但向量的含义发生了变化：

-   之前：主要是 token 的基础嵌入表示。
-   现在：包含 token 基础表示和序列位置信息。

> 补充：原始 Transformer 使用正弦位置编码；现代 Transformer
> 也常见可学习绝对位置编码、RoPE（旋转位置编码）、相对位置偏置等方案。不要把所有
> Transformer 的位置编码都理解成正弦函数。

------------------------------------------------------------------------

## 6. 阶段五：编码器（Encoder）

Encoder 的核心任务是：**让源序列中的每个 token 能够结合其他相关 token
的信息，形成上下文相关的表示。**

原始 Transformer 的 Encoder 由 N 个相同结构的层堆叠而成。每层主要包括：

1.  Multi-Head Self-Attention（多头自注意力）。
2.  Feed Forward Network（前馈神经网络）。
3.  残差连接（Residual Connection）。
4.  Layer Normalization（层归一化）。

原论文采用 Post-LN 结构：子层输出与输入做残差相加，再进行
LayerNorm。其他 Transformer 变体可能使用 Pre-LN 等不同结构。

### 6.1 Self-Attention：自注意力

**核心问题：当前 token 应该从句子中的其他 token 获取哪些信息？**

例如：

``` text
我 喜欢 机器 学习
```

当模型处理"喜欢"这个位置时，它可以关注：

-   "我"：谁喜欢？
-   "机器"：喜欢什么领域？
-   "学习"：动作或对象的语义补充。

注意力机制会为不同位置之间的关联计算权重。

#### 第一步：生成 Q、K、V

输入矩阵 `X` 经过三个不同的线性变换：

\[ Q=XW_Q,`\quad `{=tex}K=XW_K,`\quad `{=tex}V=XW_V \]

可以先用直觉理解：

  向量         直观含义
  ------------ ---------------------------------
  Q（Query）   当前 token 想寻找什么信息
  K（Key）     当前 token 可以提供什么匹配线索
  V（Value）   当前 token 实际提供的信息内容

Q、K 用于计算相关性，V 用于按注意力权重汇总信息。

#### 第二步：计算注意力分数

\[ Attention(Q,K,V)=
softmax`\left`{=tex}(`\frac{QK^T}{\sqrt{d_k}}`{=tex}`\right`{=tex})V \]

计算过程：

1.  `QK^T`：计算 Query 与各个 Key 的匹配分数。
2.  除以 `√d_k`：缩放分数，避免数值过大。
3.  `Softmax`：把分数转换成权重。
4.  乘以 `V`：根据权重汇总各 token 的信息。

举一个纯示意的例子，假设"喜欢"这个位置对各 token 的注意力权重为：

  被关注的 token     注意力权重（示意）
  ---------------- --------------------
  我                               0.35
  喜欢                             0.10
  机器                             0.30
  学习                             0.25

这些权重表示当前计算中信息聚合的相对比例，并不是人工定义的词性或语法规则，也不应直接当作严格的人类解释。

#### 第三步：多头注意力（Multi-Head Attention）

为什么不只做一次 Attention？

不同的注意力头可以在不同的表示子空间中学习不同的关联模式。例如，某些头可能更关注局部邻近关系，另一些头可能更关注较远位置的依赖关系。

原论文的 Base 模型使用：

-   `d_model = 512`
-   `h = 8` 个注意力头
-   每个头的维度 `d_k = d_v = 64`

每个头独立计算注意力，随后将各头结果拼接，再通过输出线性层映射回
`d_model` 维度。

``` text
输入 X：[L, 512]
       │
       ├── Head 1：[L, 64]
       ├── Head 2：[L, 64]
       ├── ...
       └── Head 8：[L, 64]
                │
             Concat
                │
           [L, 512]
                │
          输出线性变换
                │
           [L, 512]
```

### 6.2 残差连接与 LayerNorm

注意力子层得到输出后，不是直接覆盖原始输入，而是通过残差连接保留输入信息：

\[ Y=LayerNorm(X+MultiHeadAttention(X)) \]

这样可以改善深层网络的优化和信息传递。

### 6.3 Feed Forward Network（前馈网络）

Attention 负责在不同 token 之间交换和聚合信息；FFN
则对每个位置的表示分别进行非线性变换。

原始 Transformer 中常见的形式是：

\[ FFN(x)=max(0,xW_1+b_1)W_2+b_2 \]

原论文 Base 模型的维度为：

``` text
512 → 2048 → 512
```

这里需要区分：

-   Attention：在序列位置之间进行信息交互。
-   FFN：对每个 token 位置的特征进行变换。
-   两者结合：既能融合上下文，又能提升特征表达能力。

FFN 对每个位置使用相同的参数，但各位置的输入向量不同，因此输出也不同。

### 6.4 Encoder 一层的结构

``` mermaid
flowchart TD
    A["输入 X"] --> B["Multi-Head Self-Attention"]
    B --> C["残差相加 + LayerNorm"]
    A --> C
    C --> D["Feed Forward Network"]
    D --> E["残差相加 + LayerNorm"]
    C --> E
    E --> F["输出 H"]
```

重复 N 层：

``` text
Embedding + Position
        ↓
Encoder Layer 1
        ↓
Encoder Layer 2
        ↓
      ...
        ↓
Encoder Layer N
        ↓
Encoder Output
```

### 6.5 Encoder 输出是什么？

假设输入序列长度为 4，隐藏维度为 512：

\[ H\_{enc}`\in `{=tex}R\^{4`\times512`{=tex}} \]

它仍然是 4 个向量，每个向量对应源序列中的一个位置。

但与最初的 Embedding 不同：

-   初始 Embedding：token 的基础向量表示。
-   Encoder 输出：经过多层上下文交互后的表示。
-   每个位置的向量都融合了源序列中的上下文信息。

例如，"学习"位置的输出表示不再只是"学习"这个 token
的基础信息，还融入了"我喜欢机器学习"这一上下文。

**Encoder 的核心产物不是一个整句向量，而是一组上下文表示。**

------------------------------------------------------------------------

## 7. 阶段六：解码器（Decoder）

Decoder 的任务是：**结合已经生成的目标序列前缀，以及 Encoder
提供的源序列信息，逐步预测下一个 token。**

原始 Transformer 的 Decoder 每层包含三个主要子层：

1.  Masked Multi-Head Self-Attention。
2.  Encoder--Decoder Cross-Attention。
3.  Feed Forward Network。

同样包含残差连接和 LayerNorm。

### 7.1 Decoder 的输入：目标序列右移

以机器翻译为例：

``` text
源句子：I like machine learning.
目标句子：我 喜欢 机器 学习
```

训练时，Decoder 的输入是目标句子右移后的序列：

``` text
Decoder 输入：[BOS] 我 喜欢 机器
预测目标：    我     喜欢 机器 学习
```

`BOS` 表示序列开始标记。

这里的右移很重要：模型在每个位置只能根据之前的目标 token
预测当前位置的目标 token，而不能直接看到未来答案。

推理时没有真实目标句子，因此从 `[BOS]` 开始：

``` text
第 1 步输入：[BOS]
第 1 步预测：我

第 2 步输入：[BOS, 我]
第 2 步预测：喜欢

第 3 步输入：[BOS, 我, 喜欢]
第 3 步预测：机器

第 4 步输入：[BOS, 我, 喜欢, 机器]
第 4 步预测：学习
```

实际模型可能一次并行处理当前已有的整个前缀，但生成仍然是逐 token
自回归的。

### 7.2 Masked Self-Attention：掩码自注意力

Encoder 的 Self-Attention 可以看到源序列中的所有位置；Decoder
则必须防止当前位置看到未来目标 token。

例如目标序列：

``` text
[BOS, 我, 喜欢, 机器, 学习]
```

因果掩码（Causal Mask）会限制每个位置只能关注自身及之前的位置：

  当前位置   可以关注的位置
  ---------- ---------------------------
  BOS        BOS
  我         BOS、我
  喜欢       BOS、我、喜欢
  机器       BOS、我、喜欢、机器
  学习       BOS、我、喜欢、机器、学习

在注意力分数矩阵中，未来位置会被设置为负无穷（或等效的大负数），Softmax
后权重为 0。

例如：

``` text
允许关注：0
禁止关注：-∞
```

这样训练时就不会发生"偷看答案"的问题。

### 7.3 Cross-Attention：交叉注意力

这是 Encoder--Decoder Transformer 的关键连接。

Decoder 不仅要知道自己已经生成了什么，还需要参考 Encoder
对源句子的理解。

Cross-Attention 中：

-   Query（Q）：来自 Decoder 当前层的表示。
-   Key（K）：来自 Encoder 输出。
-   Value（V）：来自 Encoder 输出。

公式可以写成：

\[ Q=H\_{dec}W_Q \]

\[ K=H\_{enc}W_K,`\quad `{=tex}V=H\_{enc}W_V \]

\[
CrossAttention=softmax`\left`{=tex}(`\frac{QK^T}{\sqrt{d_k}}`{=tex}`\right`{=tex})V
\]

直观理解：

``` text
Encoder 输出：
"I like machine learning"
        │
        │ 提供源句子上下文信息（K、V）
        ▼
Cross-Attention
        ▲
        │ 当前目标前缀的表示（Q）
Decoder：
[BOS, 我, 喜欢]
```

例如，Decoder
正在生成"机器"或"学习"时，可以根据当前目标上下文，关注源句子中对应的词语或语义片段。

注意：Cross-Attention 并不是简单地把 Encoder 输出拼接到 Decoder
输入，而是通过注意力机制动态地从源序列中读取信息。

### 7.4 Decoder 的 Feed Forward Network

Cross-Attention 后，Decoder 还会经过
FFN，对各个位置的特征进行非线性变换。

因此，一层 Decoder 的结构可以概括为：

``` mermaid
flowchart TD
    A["目标序列表示"] --> B["Masked Self-Attention"]
    B --> C["残差 + LayerNorm"]
    A --> C
    C --> D["Cross-Attention<br/>Q 来自 Decoder，K/V 来自 Encoder"]
    E["Encoder 输出"] --> D
    D --> F["残差 + LayerNorm"]
    C --> F
    F --> G["Feed Forward Network"]
    G --> H["残差 + LayerNorm"]
    F --> H
    H --> I["本层输出"]
```

### 7.5 Decoder 输出是什么？

假设当前目标前缀长度为 `t`，隐藏维度为 512：

\[ H\_{dec}`\in `{=tex}R\^{t`\times512`{=tex}} \]

其中每个位置的隐藏状态都融合了：

-   目标序列中当前位置之前的历史信息。
-   Encoder 提供的源句子上下文信息。
-   当前 Decoder 各层学习到的特征。

在自回归生成时，通常取最后一个位置的隐藏状态来预测下一个 token。

------------------------------------------------------------------------

## 8. 阶段七：输出层（Linear + Softmax）

Decoder 输出的隐藏状态仍然是 512 维向量，但词表可能有几万甚至更多
token。

因此需要把隐藏状态映射到词表维度。

### 8.1 Linear：映射到词表空间

假设词表大小：

``` text
V = 32,000
```

最后一个位置的隐藏状态：

``` text
h ∈ R^512
```

通过线性层：

\[ logits=hW\_{vocab}+b \]

得到：

``` text
logits ∈ R^32000
```

每个维度对应词表中的一个 token，表示该 token 的未归一化预测分数。

### 8.2 Softmax：转换为概率分布

\[ P(token_i)=`\frac{e^{logit_i}}{\sum_{j=1}^{V}e^{logit_j}}`{=tex} \]

得到：

``` text
P ∈ R^32000
```

例如（仅示意）：

  候选 token     概率
  ------------ ------
  学习           0.72
  研究           0.12
  工作           0.06
  其他 token     0.10

此时模型已经给出了"下一个 token"的概率分布，但还没有完成整句话的生成。

### 8.3 选择下一个 token

常见策略：

-   Greedy Search：每次选择概率最高的 token。
-   Sampling：根据概率分布随机采样。
-   Top-k Sampling：只在概率最高的 k 个 token 中采样。
-   Top-p Sampling：在累计概率达到 p 的候选集合中采样。
-   Beam Search：保留多个候选序列，综合比较序列得分。

选择策略会影响输出的确定性和多样性。

## 9. 阶段八：自回归生成（Autoregressive Generation）

Transformer Decoder 并不是一次就输出完整句子，而是重复执行预测过程。

假设生成过程如下：

  生成轮次   Decoder 已有输入                预测出的下一个 token
  ---------- ------------------------------- ----------------------
  1          `[BOS]`                         我
  2          `[BOS, 我]`                     喜欢
  3          `[BOS, 我, 喜欢]`               机器
  4          `[BOS, 我, 喜欢, 机器]`         学习
  5          `[BOS, 我, 喜欢, 机器, 学习]`   `[EOS]`

`EOS` 表示序列结束。

每次生成后：

1.  将新 token 追加到目标序列。
2.  下一轮 Decoder 把扩展后的序列作为输入。
3.  再次计算下一个 token 的概率分布。
4.  直到生成 EOS 或达到最大长度等停止条件。

### 9.1 为什么叫自回归？

因为当前生成结果依赖之前已经生成的 token：

\[ P(y_1,`\ldots`{=tex},y_T\|x)=
`\prod`{=tex}*{t=1}\^{T}P(y_t\|y*{\<t},x) \]

其中：

-   `x`：源输入序列。
-   `y_<t`：此前已经生成的目标 token。
-   `y_t`：当前要预测的 token。

这就是 Encoder--Decoder Transformer 的自回归生成方式。

### 9.2 最终 Decode

模型最终得到 token ID 序列，例如：

``` python
[101, 203, 305, 407, EOS]
```

Tokenizer 根据词表将 ID 转回文本：

``` text
我喜欢机器学习
```

至此完成从原始输入到输出文本的过程。

## 10. 用张量维度串起整个过程

以下假设：

-   单条样本，不考虑 Batch 维度。
-   源序列长度 `L = 4`。
-   隐藏维度 `d_model = 512`。
-   词表大小 `V = 32,000`。
-   注意力头数 `h = 8`。
-   Encoder、Decoder 各有 N 层。

  位置               阶段             典型张量形状      说明
  ------------------ ---------------- ----------------- -------------------------
  输入               原始文本         字符串            人类可读文本
  分词               Tokens           `[L]`（概念上）   token 序列
  数字化             Token IDs        `[L]`             整数索引
  Embedding          词向量           `[L, 512]`        每个 token 对应一个向量
  位置编码           加位置后的表示   `[L, 512]`        形状不变
  Encoder            中间层表示       `[L, 512]`        多层上下文特征变换
  Encoder 输出       `H_enc`          `[L, 512]`        源序列上下文表示
  Decoder 输入       目标前缀 ID      `[t]`             已有目标 token
  Decoder            隐藏状态         `[t, 512]`        结合目标历史和源句信息
  输出 Linear        Logits           `[t, 32000]`      每个位置对应词表分数
  最后位置 Softmax   概率             `[32000]`         下一个 token 的概率分布
  解码               新 token ID      标量              选择或采样一个 token

> 实际实现通常还会有 Batch 维度，例如
> `[B, L, d_model]`；多头注意力内部还会拆分头维度，例如
> `[B, h, L, d_k]`。上表为了理解主流程，省略了这些实现细节。

## 11. 训练阶段与推理阶段有什么不同？

理解 Transformer 时，必须区分训练（Training）与推理（Inference）。

### 11.1 训练阶段

训练时，模型通常已经拿到了完整的目标句子。

例如：

``` text
源句子：I like machine learning.

Decoder 输入：
[BOS, 我, 喜欢, 机器]

训练目标：
[我, 喜欢, 机器, 学习]
```

通过右移目标序列和 Causal Mask，Decoder
可以在一次前向传播中并行计算多个位置的预测结果。

之后将预测结果与真实目标 token 比较，计算损失（例如 Cross
Entropy），再通过反向传播更新参数。

重点：

-   训练时可以并行计算多个目标位置。
-   仍然使用因果掩码，不能看到未来 token。
-   Encoder 可以一次处理完整源序列。
-   训练过程包含前向传播、损失计算、反向传播和参数更新。

### 11.2 推理阶段

推理时，目标句子未知，必须逐 token 生成：

``` text
[BOS]
  ↓
我
  ↓
我 喜欢
  ↓
我 喜欢 机器
  ↓
我 喜欢 机器 学习
  ↓
EOS
```

重点：

-   每一步依赖之前已经生成的 token。
-   不能提前知道未来目标 token。
-   Encoder 对源输入的计算通常只需要执行一次。
-   Decoder 可以使用 KV Cache 缓存历史 Key、Value，减少重复计算。

### 11.3 对比表

  对比项         训练                               推理
  -------------- ---------------------------------- ---------------------
  目标序列       已知                               未知
  Decoder 输入   右移后的真实目标序列               已生成的目标前缀
  预测方式       多个位置并行计算                   逐 token 自回归生成
  Mask           因果掩码                           因果掩码
  参数更新       有反向传播和优化器更新             通常不更新参数
  停止条件       目标序列长度等                     EOS、最大长度等
  KV Cache       通常不作为标准训练路径的核心优化   常用于加速生成

## 12. 一个容易混淆的问题：标准 Transformer 与 GPT 有什么关系？

前面讲解的是原始的 Encoder--Decoder
Transformer。实际常见的大语言模型并不都采用完整的 Encoder--Decoder
结构。

  -------------------------------------------------------------------------------------------
  架构                    结构特点                          典型用途 / 代表
  ----------------------- --------------------------------- ---------------------------------
  Encoder-only            只有                              BERT：理解、分类、抽取等
                          Encoder，通常使用双向上下文建模   

  Decoder-only            只有带因果掩码的 Decoder，不使用  GPT 系列：自回归文本生成
                          Encoder--Decoder Cross-Attention  

  Encoder--Decoder        Encoder 编码源序列，Decoder       原始
                          结合源信息生成目标序列            Transformer、T5：序列到序列任务
  -------------------------------------------------------------------------------------------

### 12.1 GPT 为什么没有 Cross-Attention？

GPT 这类 Decoder-only 模型没有单独的 Encoder。

它把用户输入的提示词和已生成内容放在同一条序列中，通过 Causal
Self-Attention 读取之前的上下文：

``` text
用户提示词 + 已生成 token
          ↓
Decoder-only Transformer
          ↓
预测下一个 token
          ↓
追加到序列
          ↓
继续预测
```

所以 GPT 中的上下文并不是"Encoder
编码之后的内容"，而是当前序列中模型允许访问的历史 token
表示（以及由它们计算出的隐藏状态）。

### 12.2 三种架构最关键的区别

-   Encoder-only：重点是理解输入序列，允许利用双向上下文。
-   Decoder-only：重点是根据已有上下文预测下一个 token，使用因果掩码。
-   Encoder--Decoder：先编码源输入，再由 Decoder
    结合源信息生成目标序列。

## 13. 最后用一句话理解每个模块

  模块                    最核心的问题
  ----------------------- --------------------------------------------
  Tokenizer               文本应该拆成哪些 token？
  Token ID                每个 token 在词表中的编号是什么？
  Embedding               如何把离散 token 转成稠密向量？
  Position Encoding       token 在序列中的位置是什么？
  Self-Attention          当前 token 应该从其他 token 获取哪些信息？
  Multi-Head Attention    能否从多个表示子空间学习不同的关联？
  Residual + LayerNorm    如何改善信息传递和网络训练？
  FFN                     如何进一步变换每个位置的特征？
  Encoder                 如何形成源序列的上下文表示？
  Masked Self-Attention   Decoder 如何避免看到未来 token？
  Cross-Attention         Decoder 如何从源序列读取相关信息？
  Linear                  如何把隐藏状态映射到词表分数？
  Softmax                 每个候选 token 的概率是多少？
  Decoding                根据概率分布如何选择下一个 token？
  Autoregressive Loop     如何不断追加 token，直到生成结束？

## 14. 建议的学习顺序

如果想真正理解 Transformer，而不是只记住架构图，建议按下面顺序动手：

1.  **Tokenizer**：观察同一句话在不同 tokenizer 下如何切分，查看 token
    ID。
2.  **Embedding**：理解词表矩阵如何通过 ID 查出向量。
3.  **Attention**：手算一个小矩阵的 Q、K、V、Attention Score 和
    Softmax。
4.  **Multi-Head Attention**：理解多头拆分、拼接和输出映射。
5.  **Encoder / Decoder**：分别画出两种结构，明确 Self-Attention、Masked
    Self-Attention 与 Cross-Attention 的区别。
6.  **训练与推理**：用一个小型 Seq2Seq 模型观察 Teacher Forcing 和逐
    token 生成。
7.  **现代架构对比**：再学习 BERT、GPT、T5、LLaMA
    等模型分别采用什么架构，以及位置编码、Norm、FFN 等模块有哪些变体。
