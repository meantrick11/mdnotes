# 模型能力与 NLP 任务映射

> 同一骨干可以接不同输出机制、使用不同训练数据来解决不同任务；“架构上可实现”不等于“原始权重已具备可用效果”。架构信息见[03](03-主要模型架构与原理.md)，训练方法见[06](06-训练微调与推理方法.md)。

## 1. 从底座到可用系统

```mermaid
flowchart LR
    B[基础模型权重] --> H[输出机制：任务头/向量池化/生成]
    H --> T[任务数据与目标函数]
    T --> A[适配后的模型]
    A --> I[推理、约束与评估]
```

**Base Model** 是可供适配的预训练权重，不代表已按某个业务标签体系训练。**Task-specific Model** 则包含了适配后的权重、输入格式、标签定义及输出规则。只换一个任务头通常还不够：新头需训练，底座是否冻结、训练样本和损失函数也会影响结果。[Hugging Face 的任务头说明](https://huggingface.co/docs/transformers/main/tasks_explained)分别展示了序列分类、token 分类和问答跨度头。

| 业务任务         | 输入 → 目标输出                  | 常见实现路径                   | 关键边界                      |
| ------------ | -------------------------- | ------------------------ | ------------------------- |
| 单标签/多标签/层级分类 | 文本 → 一个/多个/层级标签            | 编码器 + 序列分类头；生成模型 + 标签文本  | 多标签需逐标签判定或专门建模；层级一致性要另设约束 |
| NLI          | 前提 + 假设 → 蕴含/矛盾/中立         | 文本对分类头；生成模型输出关系          | 是任务，不是另一种 Transformer 结构  |
| NER          | 文本 → 实体跨度与类型               | token 标签、跨度预测、结构化生成      | 子词标签必须映射回原文字符跨度           |
| 通用信息抽取/UIE   | 文本 + 目标 schema → 实体/关系/事件等 | schema 提示下结构生成或专门抽取头     | “UIE”可能指具体论文框架，需写清目标与实现   |
| 语义检索         | 查询 → 相关候选                  | 独立编码向量 + 近邻检索            | 向量空间需适当训练；相似不等于业务相关       |
| 重排序          | 查询 + 候选 → 相关性分数            | Cross-Encoder 联合编码；生成式打分 | 通常逐候选计算，成本随候选数增长          |
| 问答/摘要/翻译     | 输入 → 答案或目标文本               | 编码器—解码器或自回归生成；抽取式问答可用跨度头 | 生成内容需核验事实、格式和来源           |

## 2. 一个 BERT 骨干如何形成不同模型

以下是**构造路径**，不是声称原始 BERT checkpoint 开箱即用：

| 组合 | 新增能力来自哪里 | 输出 |
| --- | --- | --- |
| BERT + 序列分类头 + 分类标注 | 整段表示上的监督训练 | 每个类别的分数 |
| BERT + 文本对输入 + 分类头 + NLI 标注 | 前提/假设关系监督 | 蕴含、矛盾、中立分数 |
| BERT + token/跨度头 + 实体标注 | 位置级监督 | 实体类型及边界 |
| BERT + 池化 + 句对/检索训练 | 让向量距离与语义目标对齐 | 可索引的文本向量 |
| BERT + 联合文本对输入 + 相关性训练 | 两段文本联合交互并学习排序 | 文本对分数 |

BERT 原论文展示了以少量任务专用输出层适配下游任务；[Sentence-BERT](https://arxiv.org/abs/1908.10084)进一步说明，适合语义相似度的句向量需要相应训练设计。原始 BERT 的池化输出不应直接视为已验证的检索模型。[BERT 原论文](https://arxiv.org/abs/1810.04805)。

## 3. Embedding、Reranker 与文本匹配

**Embedding** 描述“把单段文本编码为向量”及其使用方式。查询和文档分别编码时，文档向量可预先计算，适合在大集合中召回。**Cross-Encoder** 描述“把文本对一起送入模型进行交互编码”，适合给少量候选打分。**Reranker** 是重排环节的角色，常用 Cross-Encoder，也可以采用其他打分机制；不是所有 Cross-Encoder 都必须用于重排。[Sentence Transformers 官方说明](https://www.sbert.net/examples/cross_encoder/applications/README.html)。

典型流水线：`查询 → Embedding 召回前 K 个候选 → Reranker 逐对评分 → 返回排序结果`。此处 K、延迟和收益由真实语料实验决定。文本匹配是上层任务，可由向量相似度、文本对分类或交叉编码打分实现；这几种输出不能当作同一种模型架构。

## 4. Classification 与 NLI 的关系

**Classification** 是将输入映射到类别的预测形式；**NLI** 是判断“前提是否蕴含/矛盾/不确定于假设”的具体文本对任务。NLI 经常用分类实现，因此两者可以同时成立，但不是同义词。例如用“文档内容”作前提、“这是一份保密协议”作假设，可把 NLI 分数用于零样本标签判断；这种转换是否可靠取决于假设模板、标签语义和模型训练范围，仍需业务评估。[BERT 在 NLI 上的适配](https://arxiv.org/abs/1810.04805)。

## 5. NER 与 UIE 的关系

NER 识别文本中的实体边界和类型；信息抽取还可能要求关系、事件、属性、跨句关联及目标 schema。NER 因而可作为更广抽取问题的一部分。[UIE 原论文](https://arxiv.org/abs/2203.12277)提出统一的 text-to-structure 生成框架，将不同抽取目标编码到结构化输出。这里“UIE”特指该论文路线；其他系统也可能使用“通用信息抽取”这个名称，但内部实现不同。

例：对“甲公司于 2025 年 3 月收购乙公司”，NER 可返回组织与日期跨度；关系/事件抽取还要输出“收购方—被收购方—时间”的结构。仅有实体标签并不能自动得到关系。

## 6. 生成式模型怎样做分类或抽取

一个因果语言模型可以把分类转成“阅读文本并生成标签”的任务，或把抽取转成“按 schema 输出 JSON”的任务。指令微调（SFT）提供示例，受约束解码可限制可选标签/语法，后处理再校验结果。也可在生成骨干上接分类头，但需要确认具体模型实现与训练方案。[GPT 原始论文](https://cdn.openai.com/research-covers/language-unsupervised/language_understanding_paper.pdf)同时讨论了预训练后的判别式适配，不能说 GPT 架构只能生成。

以“合同缺少签署日期”为例，序列分类模型给出类别 logits，生成模型给出“日期缺失”这个文本。两者解决同一任务，却有不同的标签约束、概率校准、吞吐和错误处理方式。生成时出现别名、附加解释或无效 JSON 都要纳入评估，不能只看语义上“答对了”。

## 7. “模型支持某任务”分三级

1. **架构可行**：理论上可加任务头或重新组织输入输出。
2. **公开实现支持**：官方模型卡、代码或任务示例给出该 checkpoint 的可用接口和训练方式。
3. **实际效果验证**：在目标语言、文本长度、标签体系和部署环境上评估过，达到业务指标。

模型家族、Base、Instruct、Embedding、Reranker 权重可能共享部分架构，但其目标和权重不同。记录能力时必须指向**具体版本/权重**，不可把一个版本的结论继承给整个家族。
