# NLP 技术发展与模型演进

> 本文沿“遇到什么问题 → 引入什么机制 → 付出什么代价”阅读 NLP 技术史。它是演进线索，不是互斥分类表；判定一个具体模型属于什么，应回到[多维分类体系](02-NLP模型多维分类体系.md)。

## 一张演进图

| 技术线索                   | 当时着重解决的问题          | 关键变化             | 代表例子                            | 今天的工程价值            |
| ---------------------- | ------------------ | ---------------- | ------------------------------- | ------------------ |
| 规则与语言资源                | 显式描述词形、语法、领域约束     | 人写模式、词典和解析规则     | 词典匹配、正则、语法规则                    | 高确定性字段、校验和可解释基线    |
| 统计 NLP 与传统机器学习         | 从数据中估计规律，减少手写规则    | 特征工程 + 统计估计或判别学习 | n-gram、TF-IDF + SVM、CRF         | 低资源分类、强基线、可控成本     |
| 静态词向量与浅层网络             | 稀疏词表示难表达相似性        | 语料学习稠密词向量        | word2vec、fastText               | 快速、轻量的文本表示与分类      |
| CNN / RNN / LSTM / GRU | 自动学习局部模式和顺序依赖      | 可学习特征提取与序列状态     | TextCNN、BiLSTM                  | 小模型、特定序列任务和教学基线    |
| Seq2Seq 与 Attention    | 输入输出长度不同；固定上下文形成瓶颈 | 编码—解码与按需关注源位置    | LSTM Seq2Seq、Bahdanau Attention | 理解翻译、摘要及后续架构的基础    |
| Transformer            | 循环计算限制训练并行性        | 以自注意力为核心处理序列     | 原始 Transformer                  | 现代编码、生成与多种变体的骨干    |
| 预训练语言模型（PLM）           | 单任务标注数据昂贵          | 大规模预训练后迁移到下游     | BERT、GPT、T5                     | 复用通用表示，适配特定任务      |
| 大语言模型（LLM）与指令使用        | 希望更广任务共用模型和文本接口    | 扩大训练规模、提示、指令适配   | GPT-3 等                         | 灵活生成、少样本尝试、复杂任务接口  |
| 状态空间与混合架构              | 探索长序列计算和资源取舍       | 选择性状态更新、不同模块混用   | Mamba、Jamba                     | 为特定吞吐、内存和长序列约束提供候选 |


这些阶段在时间和方法上**大量重叠**：例如，预训练不是 Transformer 专有；Seq2Seq 是输入到输出的建模框架，既可由 LSTM，也可由 Transformer 实现；LLM 描述模型规模与使用范式，并不自动指定唯一架构。

## 1. 规则、统计与传统机器学习

**问题。** 早期系统需要把“一个词/句子意味着什么”变成可执行规则。规则与词典直接表达领域知识，但新表达不断出现，维护成本会增加。统计方法转而从语料估计词序列或标签规律；监督学习把文本转成特征，再训练分类器。

**变化。** `TF-IDF + SVM` 的分工是：TF-IDF 把文档变成稀疏特征，SVM 在这些特征上学习分类边界。它不依赖预训练语言模型。序列标注还可使用 CRF 等方法显式建模相邻标签约束。与纯规则相比，这些方法可从样本泛化；但表现受分词、特征和标注质量影响。[早期规则系统 ELIZA](https://doi.org/10.1145/365153.365168)、[统计机器翻译实例](https://aclanthology.org/J93-2003/)、[SVM 文本分类原论文](https://www.cs.cornell.edu/people/tj/publications/joachims_98a.pdf)、[CRF 原论文](https://mlanthology.org/icml/2001/lafferty2001icml-conditional/)。

**今天怎么用。** 明确的字段格式、禁止词、后处理约束可以继续用规则；TF-IDF + 线性分类器适合作为文档分类的低成本基线。它们还可与神经模型组成流水线，是否足够要用真实测试集判断。

## 2. 静态词向量与浅层网络

**问题。** 独热或词频表示高维且稀疏，相近词之间没有直接共享表示。word2vec 等方法从上下文学习稠密词向量，使相似用法的词在向量空间中接近。[word2vec 原论文](https://arxiv.org/abs/1301.3781)。

**变化与边界。** 静态词向量通常给同一个词形一个固定向量，难以根据句子区分不同词义。fastText 文本分类器使用词和词组的表示并做高效汇聚，是轻量的监督分类模型；它不是“一个 BERT 的旧版本”，也不等于所有 fastText 词向量模型。[fastText 分类论文](https://arxiv.org/abs/1607.01759)。

**今天怎么用。** 在 CPU、低延迟或数据与部署成本受限的场景中，它们仍值得作为基线；对上下文歧义要求高的任务，应与上下文化模型比较。

## 3. CNN、RNN 与门控序列模型

**问题。** 固定词向量不能自行建模整句话。CNN 用卷积核捕捉局部片段特征，TextCNN 将不同窗口的特征汇聚用于分类；RNN 则按顺序更新隐藏状态，让前文影响后文。[TextCNN 原论文](https://aclanthology.org/D14-1181/)。

**变化与边界。** 普通 RNN 在长依赖学习上存在困难；LSTM、GRU 用门控机制控制信息保留和更新。双向 RNN 能同时利用左右上下文，适合输入已完整可见的编码任务，但不等于可直接生成任意长文本。[LSTM 原论文](https://www.bioinf.jku.at/publications/older/2604.pdf)、[GRU 所在的 RNN Encoder–Decoder 论文](https://aclanthology.org/D14-1179/)。

**今天怎么用。** 小型 CNN/RNN 可能满足固定任务的资源约束；BiLSTM、CNN 也可作为更大系统的组件。选择依据是目标指标、文本长度和设备条件，而不是年代。

## 4. Seq2Seq 与 Attention

**问题。** 翻译、摘要等任务的输入输出长度不相同。早期 RNN Seq2Seq 用编码器读输入、解码器逐步输出；若把全部输入压入固定长度向量，长序列信息可能损失。[Seq2Seq 原论文](https://arxiv.org/abs/1409.3215)。

**变化。** Attention 让解码器在生成每一步时，按当前需要关注输入的不同位置，缓解固定向量瓶颈。[Bahdanau 等原论文](https://arxiv.org/abs/1409.0473)。这里的 Attention 最初可与 RNN 共用，**不是 Transformer 出现后才有**。Seq2Seq 描述任务组织和编码—解码关系，也不是与 CNN/RNN/Transformer 完全并列的单一网络原件。

**今天怎么用。** 这条线索帮助理解“条件生成”：解码器为什么要读取输入、为什么输出位置会关注不同源片段。翻译、摘要和结构化文本生成都沿用这一思想。

## 5. Transformer

**问题。** RNN 的逐步状态更新不易对同一序列的各位置充分并行。原始 Transformer 用自注意力和前馈网络构建编码器—解码器，在机器翻译中展示了更好的并行训练特性。[Transformer 原论文](https://arxiv.org/abs/1706.03762)。

**变化与边界。** Self-Attention 使位置之间能按内容交互，但还需位置相关信息和掩码控制；编码器、因果解码器与编码器—解码器是不同的信息流组织。注意力通常会带来随序列长度增长的计算或内存负担，具体取决于实现和注意力变体。Transformer 是**骨干架构**，不能用它代替“模型、任务、训练目标”的全部分类。

**今天怎么用。** 阅读新模型时，先检查它保留了哪部分 Transformer 结构、使用什么注意力和位置机制，再看权重及训练目标；不要从“Transformer”三个字推断其分类、检索或生成效果。

## 6. 预训练语言模型：从单任务训练到迁移

**问题。** 逐任务从头训练需要较多标注数据。预训练先从大规模文本中学习通用表示或生成能力，再通过任务头、微调或提示适配下游任务。

| 代表路线 | 预训练或使用重点 | 与任务的连接 |
| --- | --- | --- |
| BERT | 双向编码；遮盖语言建模等目标 | 接分类、标注或问答头并微调；也可再训练为向量模型 |
| GPT 类 | 基于前缀的自回归语言建模 | 通过续写、提示或进一步训练完成生成与其他任务 |
| T5 | 把多种任务写成文本到文本；采用去噪式预训练 | 输入任务前缀或文本，输出目标文本 |

这一阶段改变的是**训练与复用方式**，不是另发明了一种与 Transformer 并列的骨干。具体模型的结构、目标和任务支持必须分别查证。[BERT 论文](https://arxiv.org/abs/1810.04805)、[GPT 预训练论文](https://cdn.openai.com/research-covers/language-unsupervised/language_understanding_paper.pdf)、[T5 论文](https://jmlr.org/papers/v21/20-074.html)。

## 7. 大语言模型与指令使用

**问题。** 专门为每个任务训练一个模型，迁移和维护成本较高。规模更大的自回归模型可以把任务说明与少量示例放进输入，直接生成结果；GPT-3 论文系统研究了这种少样本使用方式。[GPT-3 论文](https://arxiv.org/abs/2005.14165)。后续指令训练与人类反馈进一步改变模型遵循任务要求的方式。[InstructGPT 论文](https://arxiv.org/abs/2203.02155)。

**变化与边界。** “LLM”强调规模、训练与通用使用能力，并非严格的参数量阈值，也不是 Decoder-only 的别名。提示、SFT、偏好训练属于不同训练或使用环节。生成模型可以做分类，但标签格式、漏判、成本、延迟仍要验证，不能因为能回答就认为可直接替代专用分类器。

**今天怎么用。** 对开放式、变化快或需要复杂指令的任务，先验证提示与结构化输出；若标签固定、吞吐高或成本敏感，则同时建立专用模型和传统基线。选型依据仍是业务评估。

## 8. 状态空间模型与混合架构

**问题。** 长序列推理的吞吐和内存使用促使研究者探索注意力之外的序列建模机制。Mamba 通过选择性状态空间机制处理序列；Jamba 则把 Transformer 与 Mamba 模块交替组合，说明架构也可以混合。[Mamba 论文](https://arxiv.org/abs/2312.00752)、[Jamba 论文](https://arxiv.org/abs/2403.19887)。

**变化与边界。** 这是一条并行的架构研究路线，不意味着所有 SSM 都具有相同能力，也不意味着它们已普遍替代 Transformer。论文中的长序列、速度或内存结果依赖具体硬件、实现、模型版本和评估任务，工程选型要重新测试。

## 从演进史回到模型识别

遇到一个新名称，可以依次问：

1. 它是**架构机制**（如 CNN、Transformer、Mamba），还是**具体模型或权重**（如 BERT 的某个 checkpoint）？
2. 它解决的是**训练问题**（如预训练、SFT），还是**业务任务**（如 NER、摘要）？
3. 输入怎样变成输出：分类头、向量比较、逐 token 预测，还是自回归生成？
4. 公开资料只说明架构可能性，还是提供具体模型支持？本地数据是否已验证？

例如，`TextCNN` 是 CNN 路线上的文本分类模型；`BERT + 分类头` 是预训练编码器适配分类；`Qwen + 指令微调 + 受约束生成` 可以用于分类，但架构、训练方式和输出机制都不同。它们应在**相同任务数据和业务约束**下比较，而非只按发布时间排优劣。
