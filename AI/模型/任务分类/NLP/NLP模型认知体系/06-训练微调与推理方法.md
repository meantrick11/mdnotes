# 训练、微调与推理方法

> 将三个问题分开：**用什么数据和目标学习**、**更新哪些参数**、**训练后怎样输出答案**。这些问题正交，可以组合。模型架构见[03](03-主要模型架构与原理.md)，任务映射见[05](05-模型能力与NLP任务映射.md)。

## 1. 学习阶段：目标与数据从哪里来

| 阶段/方法 | 训练信号 | 与其他阶段的关系 | 常见用途 |
| --- | --- | --- | --- |
| 从头监督训练 | 带人工标签的输入—目标对 | 不需要先有预训练权重 | 小型分类器、fastText、TextCNN |
| 自监督预训练 | 从未标注数据构造目标，如 MLM、下一 token、片段重建 | 产出可迁移的基础权重 | BERT、GPT、T5 等模型的预训练 |
| 任务微调 | 特定任务的标注样本和损失 | 从已有权重继续训练 | 分类、NER、检索、抽取 |
| SFT（监督微调） | 输入—理想输出示例，常是指令—回答 | 是监督微调的常见形式；不规定参数更新范围 | 指令遵循、结构化生成 |
| 偏好优化/对齐 | 人类或模型偏好、比较或奖励信号 | 通常位于预训练/监督微调之后，具体流程不同 | 改善回答偏好和行为 |
| 蒸馏 | 教师模型的输出、软标签或中间表示 | 可与监督样本、微调结合 | 把能力迁移到较小模型 |

“Pretraining → Fine-tuning”是常见但非唯一流程；传统分类器可以直接从标注数据训练。SFT 不是单独的骨干架构，PEFT 也不是一个训练阶段：SFT 说明**训练目标与数据格式**，PEFT 说明**更新参数的方式**。[BERT 原论文](https://arxiv.org/abs/1810.04805)、[T5 原论文](https://jmlr.org/papers/v21/20-074.html)、[InstructGPT 论文](https://arxiv.org/abs/2203.02155)。

## 2. 参数更新范围：改动模型的哪一部分

| 方法 | 更新内容 | 主要取舍 |
| --- | --- | --- |
| 全参数微调 | 原模型的大部分或全部权重 | 适配自由度高；显存、优化器状态和模型存储成本较高 |
| 冻结骨干 + 任务头 | 只更新新增分类/标注/跨度等头部 | 训练成本低；若底座表示不适合任务，能力受限 |
| Adapter | 在网络中插入小型可训练模块 | 保存的任务参数较少；需对应实现支持 |
| LoRA | 冻结基座权重，在选定线性层学习低秩更新 | 仅训练少量附加参数；目标模块和秩需验证 |
| QLoRA | 量化并冻结基座，在其上训练 LoRA 参数 | 降低训练内存需求；量化与实现会影响数值和兼容性 |
| Prompt / Prefix Tuning | 学习连续提示向量或层内前缀参数 | 少量可训练参数；与“写一段自然语言提示”不同 |

LoRA 可用示意式写为 `W' = W + BA`：原权重 `W` 冻结，只训练低秩矩阵 `B`、`A`。[LoRA 原论文](https://arxiv.org/abs/2106.09685)。QLoRA 把量化的冻结基座与 LoRA 训练结合；它不是“把 LoRA 权重也全部量化后训练”的同义说法。[QLoRA 原论文](https://arxiv.org/abs/2305.14314)。方法支持范围应按具体框架版本、模型结构和模块名称核对；[PEFT 官方文档](https://huggingface.co/docs/peft/en/methods/overview)介绍了不同方法族。

**组合例子**：用标注过的“合同文本 → 风险标签”做监督微调，可以全参数更新，也可以用 LoRA；这两种方案的数据与目标相同，参数更新范围不同。用指令—标准 JSON 训练生成模型时，SFT 同样可以与全量微调或 LoRA 组合。

## 3. 推理阶段：怎样从模型得到结果

| 推理机制 | 结果 | 常见场景 | 需要检查 |
| --- | --- | --- | --- |
| 分类头 | 类别 logits、概率或多标签分数 | 文本分类、NLI | 阈值、校准、类别不平衡 |
| Token/跨度头 | 每个位置标签或起止位置 | NER、抽取式问答 | 子词到原文的对齐、非法跨度 |
| 向量相似度 | 文本向量、距离或相似度 | 检索召回、聚类 | 向量归一化、索引、领域偏移 |
| Cross-Encoder 打分 | 每个文本对的分数 | 候选重排 | 候选数量、延迟、分数可比性 |
| 自回归生成 | 输出 token 序列 | 摘要、问答、生成式分类 | 格式、幻觉、停止条件和成本 |
| 约束解码 | 在指定词表、语法或 schema 内生成 | 标签、JSON 等结构化输出 | 约束是否覆盖全部合法答案、实现支持 |

**训练目标与推理机制不可互换**：MLM 是预训练目标；分类头是输出组件；生成是推理过程；LoRA 是训练参数更新方式。一个端到端系统可以同时含有这四项中的若干项，但它们属于不同层级。

## 4. 从任务反推方法

1. 固定业务输出和指标：类别、多个标签、实体跨度或自由文本？错误成本如何？
2. 确认样本：是否有可靠标注、标签是否稳定、长尾与多语言如何分布？
3. 选择输出机制：分类头、向量召回、重排、跨度预测或生成。
4. 选择起点：传统模型、公开基础权重、已适配的专用权重。
5. 选择训练信号和参数范围：从头训练、任务微调、SFT；再决定全量、冻结头或 PEFT。
6. 在固定数据划分上比较质量、延迟、显存与部署成本；记录 checkpoint、tokenizer、训练配置与阈值。

对于企业文档分类，先用 TF-IDF + 线性模型、现成编码器分类头和生成式分类分别建立可复现基线，再决定是否有必要引入 LoRA、蒸馏或两阶段检索。方法不是越新越好，最终由同一测试集和部署约束判断。
