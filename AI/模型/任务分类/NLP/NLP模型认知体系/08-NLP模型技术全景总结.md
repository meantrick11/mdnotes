# NLP 模型技术全景总结

> 导航与判断卡片。这里汇总各篇结论，不复制详细机制、模型卡和实验流程。

## 1. 六个问题定位一个 NLP 系统

| 问题           | 所属层次     | 例子                                           | 详见                                             |
| ------------ | -------- | -------------------------------------------- | ---------------------------------------------- |
| 信息怎样流动？      | 骨干架构     | TF-IDF + SVM、CNN、RNN、Transformer、Mamba       | [01](01-NLP技术发展与模型演进.md)、[03](03-主要模型架构与原理.md) |
| 哪个具体版本和权重？   | 模型实例     | BERT-base-uncased、T5-base、具体 Qwen checkpoint | [04](04-代表模型知识图谱.md)                           |
| 用什么训练信号学会能力？ | 预训练/任务目标 | MLM、下一 token、span corruption、对比学习            | [02](02-NLP模型多维分类体系.md)、[06](06-训练微调与推理方法.md)  |
| 最终怎样输出？      | 输出机制     | 分类头、token 标签、向量、文本对分数、生成                     | [03](03-主要模型架构与原理.md)、[05](05-模型能力与NLP任务映射.md) |
| 要解决什么问题？     | 业务任务     | 分类、NLI、NER、检索、UIE、摘要                         | [05](05-模型能力与NLP任务映射.md)                       |
| 怎样适配并部署？     | 训练/推理/工程 | 全量微调、LoRA、阈值、约束解码、分块                         | [06](06-训练微调与推理方法.md)、[07](07-NLP模型选型方法论.md)   |

**读法**：一个完整描述至少写明“具体权重 + 输出机制 + 任务 + 适配/训练 + 评估条件”。例如“某 BERT checkpoint + 序列分类头 + 文档多标签分类 + 标注数据微调 + 本地 P95/召回验证”，比“用 BERT 做分类”更可复现。

## 2. 最容易混层的名称

| 名称 | 应放在哪一层 | 不能直接推断 |
| --- | --- | --- |
| Encoder-only / Decoder-only / Encoder-Decoder | Transformer 内部结构 | 全体 NLP 模型只分三类 |
| BERT、T5、Qwen、Llama、Mamba | 模型家族/具体版本；还须指明 checkpoint | 同家族每个版本能力一致 |
| Embedding | 输出表示与使用方式；也常指专门训练的模型 | 任意原始隐藏状态都是高质量检索向量 |
| Cross-Encoder | 文本对联合编码方式 | 一定只能做 Reranker |
| Reranker | 候选重排角色 | 一定采用同一骨干架构 |
| NLI、NER、UIE | 任务或任务框架 | 等于分类头、token 头或模型家族 |
| MLM、CLM、对比学习 | 训练目标 | 等于骨干架构 |
| SFT、LoRA、QLoRA | 训练信号/参数更新方式 | 等于新模型或新推理机制 |

## 3. 从任务到方案的最短路径

```mermaid
flowchart LR
    A[定义任务、输出与错误成本] --> B[建立数据与最低成本基线]
    B --> C[按机制选择候选模型]
    C --> D[决定训练目标和参数更新范围]
    D --> E[同一测试集评估质量与资源]
    E --> F[锁定版本、阈值与回退]
```

分类、抽取、检索和生成可以共享骨干，但输出头和训练目标不同；传统模型也应保留为可解释、低成本基线。一个架构**理论上能做**、官方 checkpoint **声明支持**、业务数据上**实际有效**是三个不同证据等级。工程决策需要最后一级。[具体选型 SOP](07-NLP模型选型方法论.md)。
