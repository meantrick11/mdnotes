# 一次意外触发的粘贴 XSS：从公众号排版到定位与报告

## 一、事情怎么开始的

本意不是挖洞。手头有一份 DVWA「XSS(DOM)」学习笔记，准备发成公众号。笔记里有概念、四个等级、防护，也有练习用的 HTML 示例（失败图片、事件属性、`javascript:` 链接等）。本地 Markdown 看着只是文字。

排版时用了在线「Markdown → 富文本」，点「复制富文本」，贴进 `mp.weixin.qq.com` 文章编辑页。编辑区弹出了 Cookie。当时的直觉是：我在写 XSS 文章，示例怎么在微信后台跑起来了？

第一反应很容易走偏：**这是不是我笔记主题里的 DOM XSS 原样出现在了微信？** 页面 URL 里还有 `appmsg`、`token` 之类参数，Burp 里又有请求，很像「某个接口把输入反射回来了」。后面证明：洞在编辑器怎么处理剪贴板，不在某个 CGI 参数。

## 二、第一个真正有用的对照

同一段内容，两条路，结果完全不同。

- 从转换器「复制富文本」再贴进公众号 → 弹窗。
- 把笔记贴到对话里，再从对话复制回公众号 → 没反应。

当时觉得「内容一样，不应该一个中一个不中」。差别不在字面上的 URL，而在**剪贴板里到底是什么**：

| 复制来源 | 剪贴板 | 编辑器怎么插 | 结果 |
|---|---|---|---|
| 转换器「复制富文本」 | `text/html`（已是标签） | 当节点插入 | 会执行 |
| 聊天 / 记事本 / 源码 | `text/plain` | 当字符插入 | 不执行 |

Markdown 默认允许原文 HTML 直通。练习句如果**没包在代码块里**，转换器会建成真的 `img`、真的 `a`。复制富文本等于把节点带走。对话里复制的只是字，尖括号还是尖括号。

后来又做了一次对照：把那一行源码**单独当纯文本**贴进公众号，编辑器当普通文字，没弹。这坐实了：**漏洞入口是「接受未消毒的 HTML 粘贴」，不是「这一串字符出现就会炸」。**

## 三、Burp 里走了哪些弯路

为了「定位到具体请求」，把流量都翻了一遍。这里最容易把客户端问题当成接口问题。

### 1. 一串 POST：CSP 上报

大量 `POST /mp/fereport?action=csp_report`。内容是：编辑区想加载转换器域名上的笔记截图，`img-src` 不让。这只能证明富文本里的 `<img>` 进过编辑器，和 Cookie 弹窗不是一条因果链。策略还是 report，不是 enforce；`script-src` 里还有 `unsafe-inline`。当作噪音划掉。

### 2. 那条「对得上弹窗」的 GET

真正和弹窗时刻对上的，是：

- `GET /cgi-bin/1`
- `Sec-Fetch-Dest: image`
- 响应 **404**

当时的想法是：路径这么怪，会不会是漏洞接口？Repeater 再发一次，还是 404，页面也不弹。这里卡了很久。

后来才把两件事拆开：

1. **粘贴**已经把带失败回调的图片插进**当前标签页**的 DOM。`src` 写成相对路径 `1`，当前页是 `/cgi-bin/appmsg`，浏览器就去拉 `/cgi-bin/1`。
2. 服务器没有这张图，404。浏览器认为图片失败，执行节点上的回调。读 Cookie 的是**本页 JavaScript**，不是 404 正文。

所以：Burp 能看见这次 GET，是因为浏览器真的向服务器要图；**服务器没执行脚本**。Repeater 另开一条，没有「正在等这张图失败」的那个 DOM，所以弹不出来。`/cgi-bin/appmsg` 同样：它只是文章编辑页，响应里没有这段 payload。

`appmsg` 就是公众号后台图文编辑的 CGI。报告里写这个 URL，是标明**出问题的页面**，不是「请求它就会 XSS」。

### 3. 两次弹窗 Cookie 不一样

`document.cookie` 读的是**执行脚本的那个浏览器、那个页面**里 JS 能看见的 Cookie，不是 Burp `Cookie:` 头全文。Edge 里先贴过一次，和后来走代理的 Chrome 不是同一套。HttpOnly 的（例如部分会话票）不会出现在弹窗里。这反而帮助确认：脚本跑在编辑页源，不是跑在 Repeater 里。

## 四、到 DOM 里找「作案现场」

逻辑上：富文本带了不该解析的标签 → 图片失败 → 回调执行。正常编辑器不该把粘贴进来的事件当代码跑。要找节点，本该在 Elements 里搜相对路径或事件属性。

实际搜 `cgi-bin/1`、`src=1` **没有结果**。这造成一次误判：「笔记里根本没有图片 + 回调」。

其实是**时间差**：

1. 粘贴瞬间节点进过 DOM（否则不会有那次图片 GET）。
2. 回调已经跑过，Cookie 已经弹过。
3. 编辑器随后提示「有 5 个内容插入失败」，把这类危险 `img` 清掉。

所以现在搜不到，不是「从来没有」，是**执行之后被清理**。消毒发生在插入之后，挡不住已经跑过的回调。

同一份 DOM 里还能看到别的残留，过滤并不完整：

- 仍可点击的 `javascript:` 链接（笔记里的 “Click me” 一类）——点了就会在编辑页源执行，不依赖图片请求。
- 包在文本节点里的 `window.location=...` ——只是字，不会跑。
- 被转义的 `&lt;a href=...&gt;` ——已经当文本了。
- 被中和的 `script` 占位（例如变成自定义标签 / 编码进属性）——说明有一层过滤，但事件和伪协议没剥干净。
- 微信自己资源脚本上的 `onerror` ——产品自己的失败上报，和这次无关。

结论：**至少两条独立路径**。一条是失败图片 + 回调（节点可能已删，Burp 里留过痕迹）；一条是 `javascript:` 链接（还在）。旁边加载失败的笔记截图是转换器外链，被 CSP 拦，不是 `/cgi-bin/1`。

## 五、回到原始 Markdown：洞不在「我没写回调」

把源笔记摊开后，Medium 练习里有一行**没进代码块**的 HTML：看起来像 DVWA URL，后半段其实是拆掉 `<select>` 之后的图片标签，并带失败回调。转换器只认「这是不是 HTML」，不认「作者是不是在举例」。

另外还有 `javascript:` 链接、其它失败图写法、本地 `![](./XSSpictures/...)` 被改写成转换器域名（后者只制造 CSP 上报）。

所以不是「笔记里没有」，是**练习句被当成了真标签**。`</option></select>` 只是 DVWA 下拉框的逃逸前缀；在转换器里没有 `<select>`，解析器丢掉这两段，图片照样能建出来。后来精简成后半段，转换器仍然能生成可复制的富文本——说明可执行核心是那张带事件的图，不是整段 DVWA URL。

## 六、为什么「提取文字」就不中，富文本却能带走

让别的模型「把文字提取出来」再试，通常不中，因为输出往往已经不是同一串字节：进了代码块、尖括号被转成实体、加了转义或零宽字符、或复制时只有纯文本。转换器和公众号都不再把它当标签。

「复制富文本之后，贴到别的所见即所得里也会弹」——这是剪贴板 HTML 的可移植性：节点不绑定微信某个参数。贴到哪个源，回调就在哪个源跑，读的是那个源的 Cookie。这能解释一类编辑器通病，**不能**当成可以去扫其它产品的理由；未授权测试别人的线上编辑器不合适。对腾讯 SRC，范围只写公众号文章编辑页。

弹窗读到 Cookie，说明危害真实，但模型是：**受害者（往往是作者自己）把带事件的 HTML 贴进未消毒编辑器**。不是「发一个链接，读者一点就中」。有没有变成已发布文章上的存储 XSS，取决于保存/发布是否还留下这些标签，这次没验证，不能写进已证实危害。HttpOnly 的会话票 JS 读不到，也不能写成「一定接管任意账号」。自评中危是匹配的。

## 七、中间一直卡住的思维误区（后来怎么拆掉）

1. **「一定有一个恶意 HTTP 包」**  
   反射型 XSS 的习惯。这次脚本在粘贴时进 DOM，包只是图片 404 或 CSP 噪音。

2. **「Repeater 打 `appmsg` 或 `/cgi-bin/1` 就能复现」**  
   没有「已贴过 HTML 的那个标签页」，没有事件可跑。

3. **「现在 DOM 里搜不到，就是没有这张图」**  
   忽略了插入 → 执行 → 清理。

4. **「笔记是 Markdown，不会变成标签」**  
   未进代码块的 HTML，对很多转换器就是真 HTML。

5. **「CSP 报了所以是 CSP 的问题」**  
   CSP 在报外链图；真正执行靠内联事件，和 `unsafe-inline` 更相关。

6. **「Cookie 头里有的，弹窗里都该有」**  
   `document.cookie` ≠ 请求头里的 Cookie。

7. **「表单要请求包，所以洞在这个包里」**  
   SRC 表单按反射型设计。客户端粘贴 XSS 只能交旁证包，并在详情里写清 Repeater 复现不了。

## 八、最后怎么收束成报告

不再追求「再打一遍给腾讯看」，用已经发生的证据：

- **名称：** 公众号文章编辑器对粘贴 HTML 过滤不足，编辑页脚本执行并读取登录 Cookie  
- **类型：** Web / 基于 DOM 的 XSS（不要选反射型）  
- **URL：** `https://mp.weixin.qq.com/cgi-bin/appmsg`（不带 token）  
- **请求/响应：** 打码后的 `GET /cgi-bin/1` 与 404，并写明这是图片加载旁证，响应无脚本  
- **自评：** 中危  
- **详情：** 入口是剪贴板 `text/html`；纯文本对照不执行；弹窗、插入失败提示、残留 `javascript:` 链接；修复方向是粘贴白名单、剥事件和伪协议、CSP enforce、去掉不安全的内联脚本策略  

主证据用「纯文本不执行 → 富文本 → 公众号弹窗（Cookie 打码）」。Burp 不是必须；HTTP history 里还有当初那条再打码附一张即可，不必为了补图再贴。不交富文本原件、不交未打码会话、不交其它网站的弹窗。

## 九、这条链最后长什么样

```
本地 MD（练习用 HTML 未进代码块）
        ↓
在线转换器按原始 HTML 渲染
        ↓
复制富文本（剪贴板为 HTML 节点）
        ↓
公众号编辑器原样插入 DOM（事件未剥净）
        ├─ 相对路径图 → GET /cgi-bin/1 → 404 → 失败回调 → 弹 Cookie
        ├─ 随后「插入失败」清理部分 img（现场被擦掉）
        └─ javascript: 链接仍可能残留
```

洞不在 `/cgi-bin/1` 这个 404，也不在 `appmsg` 把参数写回 HTML。洞在：**作者登录态下的编辑器，把不可信的粘贴 HTML 当成了可执行 DOM。**

## 十、事后觉得值的几件事

分析客户端 XSS，先问剪贴板 MIME 和 DOM，再问 HTTP。流量是旁证，不是定义。编辑器会事后消毒，要接受「节点已经消失、请求还在、弹窗已经发生」这种不对称。对照实验（纯文本 / 富文本 / 对话复制）比再构造一次 payload 更安全，也足够写报告。

练习笔记里的 HTML 对转换器和所见即所得都是真代码。以后同类文章：示例进代码块、先转义再排版，不要「整篇转富文本」。会话票已经在分析过程里出现过，提交前打码，并考虑退出后台重新登录。
