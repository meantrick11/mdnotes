# 场景与视觉规则

| 场景 | 节点重点 | 边的含义 | 推荐阅读顺序 |
| --- | --- | --- | --- |
| 系统架构 | 服务、模块、外部系统、存储 | 调用、依赖、消息 | 外部入口 → 核心服务 → 存储与依赖 |
| 业务流程 | 角色、步骤、审批、状态 | 移交、判断、回退 | 主路径 → 分支 → 异常 |
| 数据流 | 来源、加工、落地、消费 | 数据传递、转换 | 来源 → 处理 → 去向 |
| Agent 工作流 | Agent、Tool、State、人工节点 | 消息、工具调用、状态迁移 | 触发 → 推理与工具 → 结果 |
| 代码架构 | 包、模块、类、接口 | 导入、调用、实现 | 入口 → 业务模块 → 底层依赖 |
| RAG 架构 | 解析、切块、Embedding、索引、检索、重排、生成 | 离线构建或在线查询 | 分开看构建链与查询链 |

## 视觉优先级

1. 先让主链路在不点击时可读；动态效果只负责指路。
2. 分组表示责任域、阶段或泳道；颜色表示类型或状态，保持图例一致。
3. 一条边只表达一种关系。多种关系用独立边 ID、图例或视图过滤表达。
4. 点击节点后，选中节点用清晰边框和柔和 Glow，关联边用青蓝色或主题强调色；其余元素保留 10%～20% 透明度，背景与文字仍可辨。
5. 150～250ms 过渡、1.5～2.5s 流光循环；静态偏好下用颜色、线宽和文字保持相同信息。
6. 大图提供搜索、缩放、重置和局部聚焦；小图保持简洁，不为功能密度牺牲阅读。
