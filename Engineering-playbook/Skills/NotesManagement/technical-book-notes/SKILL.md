# 技术书籍学习笔记

把书中的知识组织成可独立阅读、可拼接、可复习的 Markdown 笔记。目标是让读者既记住**是什么**，也能解释**为什么这样设计、怎样运作、何时适用**。用自己的话准确概括原书，保留关键推理链，不以堆砌术语代替解释。

## 1. 确定范围与依据

1. 确认书名、作者、版次、目标章节或页码、语言版本、输出位置，以及用户已有的笔记约定。沿用目标目录的命名和层级；用户未指定时，一个可独立复习的小节保存为一个 Markdown 文件。
2. 优先阅读用户提供的原书材料或有访问权限的来源。核对目标版本的目录和小节顺序；版本不同造成的章节差异，以用户指定版本为准。外部事实易变或来源内容未提供时，查阅出版方、作者、正式文档等可信来源。未能核实的章节标题、页码和原书观点不要编造。
3. 只覆盖用户指定的范围。必要的前置概念用一两句补足，后续章节的详细内容留在其对应章节。记录所依据的书名、版次和章节；需要网页来源时附可打开的出处。

## 2. 提炼知识骨架

先逐小节建立**覆盖清单**，再写正文。清单记录原书该小节的标题、关键术语及定义、机制或算法、分类与例外、图表要表达的结论，以及支撑推理的例子。凡是理解本节推理或区分相近情况所必需的概念，都要在正文中给出解释；只在原书中顺带出现、与目标问题无关的名称不必逐词收录。不能只列术语而省略其作用和适用条件。

每个知识点按适用情况追问：

- **定义与边界**：对象是什么；与邻近概念如何区分；术语的限定条件是什么。
- **动机与设计目标**：原有问题是什么；该机制解决什么问题；代价或限制是什么。
- **机制与过程**：组成、数据流、控制流、状态和转换条件；关键步骤为何按此顺序发生。
- **条件与推导**：公式中的变量、单位、假设、推导方向和适用范围；算法的输入、步骤、结果与复杂度；协议的交互双方、消息和异常路径。
- **易混与易错**：相似术语、前提变化、反例、常见误读；用教材证据解释差异。
- **例子与应用**：选择能检验原理的最小例子；计算题给出代入和结果，机制题给出原因与状态变化。

章节内容不同，不要求每一点都套齐这些项目；但定义、关键原理、产生原因及必要的限制不能因追求简短而丢失。记录每个关键概念最终写入的位置，供成稿时反向核对。

## 3. 编排笔记

1. **保持书的脉络**：以用户指定版本的原书章、节、小节顺序为正文骨架，标题保留编号。正文先讲教材知识，再放与该知识直接相关的理解辅助内容；新增内容标为“理解”“易混”“例题”或“拓展”，避免读者误认是原书原话。
2. **按问题组织方案**：在不打乱原书小节顺序的前提下，先说明原有方案遇到的具体问题和设计目标，再解释新方案的核心机制、成立条件、优点、代价及失效情形。多个方案针对同一问题时，先讲共同问题，再分别解释它们如何解决及取舍；若某方案解决的是另一层问题，要单独标明，避免把相关机制误写成互相替代。优缺点要有机制或例子支撑，不写脱离条件的“更快”“更省内存”。基础概念没有实际方案取舍时，不强行套优缺点模板。
3. **让表达服务理解**：先给准确结论，再解释原因和过程。状态转换写清触发条件；公式写清假设和变量；代码或命令解释其在原理中的作用。重点用加粗突出，不把整段都加粗。
4. **按需要选表现形式**：
   - 关系、差异和判别条件适合表格；表格放在读者需要比较的地方。
   - 状态变化、流程、层次、数据流或协议交互适合 Mermaid；图紧邻对应原理，并配一句说明图的阅读重点。
   - 公式推导、计算示例、简短伪代码适合直接放在相应步骤后。
   - 图表不能替代解释；概念本身用文字更清楚时，只用文字。
5. **保留复习入口**：内容较多时，在节末加入精炼的“核心思想”“高频易混点”或“自测问题”。这些内容概括已讲原理，不另起一套重复正文的长篇总结。用户有固定模板时遵循其模板。
6. **形成可拼接成品**：输出纯 Markdown，标题层级稳定；同一系列沿用术语、编号、表格和图的风格。用户指定文件路径时直接保存；用户要求在对话中输出成品时直接给笔记内容。

## 4. 成稿核对

交付前逐项检查：

- 对照原书目录和覆盖清单逐项反查成稿：小节编号、标题和顺序与指定版本一致；每个关键术语、机制、分类、动机及重要例外都有准确的解释和写入位置。遗漏项先补足，再交付。
- 每个方案能回答“要解决什么问题、怎样起作用、为什么有效、何时适用、代价是什么”；并列方案的共同目标、不同取舍及不能互相替代的边界清楚。每个因果结论能回答“为什么”；图、表、例子与相邻正文一致，能独立帮助理解或复习。
- 原书观点、个人推断和延伸知识可区分；来源不足处明确标示待核实，不把猜测写成教材事实。
- 公式、数值、变量含义、严格不等号、状态箭头和 Mermaid 语法均已核对。
- 文件名与保存位置符合要求；Markdown 为 UTF-8 无 BOM、LF 换行，且未覆盖用户已有的无关内容。

## 简短示例

用户要求“整理《某计算机网络教材》指定版本的可靠传输一节”时，按该版目录写正文，说明设计动机、确认与重传的触发条件、序号和窗口的作用；在状态变化旁放流程图，在易混处比较停等协议与滑动窗口，节末保留适合自测的关键问题。章节名、机制细节和例子均以实际核实到的教材为准。

若原书并列介绍多级页表、倒排页表和 TLB，先识别问题层次：前两者主要处理巨大虚拟地址空间带来的页表空间开销；多级页表尤其适合稀疏地址空间，代价是遍历层数；倒排页表使表项数随物理页框数增长，代价是反向查找困难。TLB 主要缓解频繁地址转换的时间开销。逐项解释机制与代价，并核对术语和例外是否写入正文。
