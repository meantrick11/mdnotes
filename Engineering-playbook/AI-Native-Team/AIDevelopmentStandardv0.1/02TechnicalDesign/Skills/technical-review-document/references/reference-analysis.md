# V1.10 参考评审稿解剖

内置样本：`../assets/reference-review-v1.10.docx`。原文档名为“非结构化数据语义分类分级设计说明书-评审版-V1.10.docx”。这是本 skill 的首要结构与呈现参考；“产权登记”评审稿仅是该版本早期的组织来源。参考稿的业务结论、接口和数据表只属于原需求。

## 读者和问题

样本服务于业务及技术联合评审。它先解释现状为什么不足、目标业务怎样闭环，再将方案取舍、模块职责、数据关系、阶段流程和页面接口逐层展开。每章都让评审人找到可判断的内容，而不是铺陈实施字段。

## 实际组织

| 位置 | 样本中的内容 | 迁移到新需求时的作用 |
|---|---|---|
| 开篇 | 文档名、版本、评审判断、阅读路径 | 先告诉读者本次评审要决定什么 |
| 1 产品使用场景 | 业务现状/目标对照、端到端业务图、范围边界 | 用用户可见结果说明“为何做”和“做到哪” |
| 2 设计关键决策 | 实际模块复用与扩展矩阵、推荐方案与代价 | 明确复用的是哪个模块、哪一层能力，新增边界在哪里 |
| 3 系统设计 | 现状/目标模块架构、现有/目标数据关系、页面兼容矩阵 | 让评审人比较服务组织、表职责和旧功能影响 |
| 4 核心流程设计 | 模板、索引、任务、匹配、人工确认、正式结果六个阶段 | 每阶段用图展示参与者、状态、门禁与反馈 |
| 5 按页面组织的接口地图 | 模板管理、模板导入、配置、任务、执行、候选、结果、目录八个页面小节 | 同一页面的结构化/非结构化 Tab 一起盘点；每条写性质、变化与作用 |
| 6 非功能、实施与验收 | 风险、阶段顺序、验收门禁、待评审问题 | 把风险转为可验证的控制条件 |
| 附录 | 需求/SPEC/仓库证据 | 方便核对现状和目标，避免“看起来正确” |

样本有 14 张嵌入图、30 张表。数字只是该需求的结果：复杂需求应足够完整，小需求应删去无关章节；不要把 14 张图或 30 张表当最低要求。

## 图的分布和职责

| 图源 | 对应内容 | 应保留的表达方式 |
|---|---|---|
| `01-overview.mmd` | 从标准到正式结果/目录的端到端业务 | 正常路径与分支同在一张总览图 |
| `02-current-system.mmd` / `03-target-system.mmd` | 整体服务组织现状与目标 | 同一范围比较入口、业务服务、基础服务、外部服务、存储 |
| `04a-current-data-relations.mmd` / `04-data-relations.mmd` | 现有和目标数据关系 | 非线性 ER；区别复用表、改造表、新表与逻辑关联 |
| `05-template-config.mmd`—`13-important-data.mmd` | 各阶段时序、状态和结果应用 | 一图一个问题；包含门禁、失败、状态回写或人工决策 |

相应 `.mmd` 在 `../assets/diagram-sources/`，用于学习结构、图型和信息密度。生成新文档时应重新从目标代码和 SPEC 建节点/关系清单，再绘图并实际渲染。

## 表格与正文的比例

样本的表主要承担**比较**与**映射**：现状/目标、复用/改造/新增、当前表/目标表、状态/处理、风险/控制。正文只解释取舍的原因、边界和预期效果。不要将连续叙述拆成大表，也不要把接口字段和错误码全文搬进评审稿。

2.1 的关键表头是“页面或能力｜现有模块与可复用内容｜本期改造或新增｜边界与核对点”。这比“能力｜复用/新增”更能点明真实模块。接口表头是“接口｜性质｜变化或复用范围｜页面作用”；每一张表都放在对应页面小节下。模板新增与导入页同时列结构化和非结构化接口。

## 第 5 章的页面拆分样例

| 页面小节 | 样本中盘点的能力 | 为什么单列 |
|---|---|---|
| 5.1 模板管理 | 两个 Tab 的列表、编辑、删除、启停 | 评审默认类型和旧模板兼容 |
| 5.2 模板新增与导入 | 两个 Tab 的下载、行业、附件上传、保存 | 同一个用户操作要同时看见结构化沿用与非结构化新增 |
| 5.3 知识库配置 | 模板下拉、分类树、叶子、级别、节点操作、重建索引及 KB 同步 | 界面操作和内部服务调用在同一能力下相接 |
| 5.4 任务列表与弹窗 | 列表、模板/数据源下拉、创建、编辑、启停、删除、立即执行 | 一次审清调度复用、业务扩展和运行门禁 |
| 5.5 执行历史与文件明细 | 批次、文件分页、内部匹配 | 区分批次统计与逐文件事实 |
| 5.6 候选详情与确认 | 候选详情、全树改选、确认写入 | 明确本地切换候选不产生新接口，确认才写正式结果 |
| 5.7 正式结果 | 数据源、文件、详情三层 | 只读人工确认后的正式事实 |
| 5.8 重要数据目录 | 结构化原接口、非结构化列表与导出 | 同页双 Tab 的旧功能保持与新结果消费 |

新需求应先列出自己的页面/弹窗/Tab 清单，再用这些页的用户操作反查接口，不照抄这八个标题。跨页共享的接口可在首次出现时详述，后续说明复用位置；任何页面都不能只列新增接口而遗漏现有接口改造。

## 样本中需要保留的审慎做法

- 代码现状与目标 SPEC 分开写。样本将任务删除接口的代码方法与 SPEC 方法差异列为待定项，而不悄悄统一。
- 旧知识库的解析组件与目标分类索引属于不同层次；“组件可复用”不等于旧业务链路可复用。
- 机器候选、人工确认和正式结果分开呈现；图、表、接口清单都保持相同边界。
- 结构化与非结构化共用页面时，写清默认 Tab、各自数据源、接口隔离和旧调用兼容。
- 具体接口路径、表名、角色和图中节点只作该样本的证据，不能直接复制到其他系统。

## 版式观察

样本为约 21.6 × 27.9 cm 页面，左右边距约 2.15 cm；正文使用微软雅黑 10 pt，一级标题 15 pt，二级标题 11.5 pt，主标题 22 pt。图宽约 16.9 cm。这些是参考稿的样式数据，不是固定要求；用户给出新模板或印刷要求时以其为准。V1.10 在生成时完成了 DOCX 结构检查，但因本机当时缺少 LibreOffice，没有完成逐页渲染；它不能作为“版面已验收”的证明。生成新稿必须以实际渲染页检查图中文字与表格跨页可读性。
