# 评审稿质量检查表

## 内容与证据

- [ ] 已阅读内置 V1.10 参考稿解剖；借鉴章节与图表组织，没有复制其业务事实或接口。
- [ ] 首页写明需求、目标代码版本、SPEC 版本及评审目的。
- [ ] 现状、目标、差异、处理方式、预期效果形成闭环。
- [ ] 2 章明确实际模块名称、复用内容、改造点、新建内容与边界。
- [ ] 当前架构覆盖相关系统全貌，而非只画分类服务内部小链条。
- [ ] 关键业务流程有正常、阻断、异常和人工处理分支。
- [ ] 数据表对比写出现有、改造、新增，ER 基数和逻辑/物理关系准确。
- [ ] 保持旧功能的路径与兼容策略有证据；不把目标设计写成现状。
- [ ] SPEC 与代码冲突单列，不能无声选边。

## 页面接口盘点

- [ ] 每个受影响页面、弹窗、Tab 都有小节；同页结构化/非结构化接口同处展示。
- [ ] 页面所需列表、详情、下拉、提交、启停、删除、导入、下载、导出和内部调用已检查。
- [ ] 每条接口标明方法与路径、已有/改造/新增/保持、变化点、页面作用。
- [ ] 现有方法与路径已在代码核对；目标接口已在 SPEC 核对。
- [ ] 旧接口沿用和隔离方式清楚，跨模块权限或网关前缀差异清楚。

## 图与阅读体验

- [ ] Mermaid 源码与渲染图一一对应；图题写“现状/目标”及所回答的问题。
- [ ] 架构图有真实模块和调用关系；现状/目标图可直接对照。
- [ ] 时序图包含真实参与者、返回和关键分支；数据关系图不是线性串表。
- [ ] 图和表比正文更快地呈现关系，正文只补因果与决策。
- [ ] 图中文字在文档正常尺寸可读，线与节点不相互遮挡。
- [ ] DOCX 已逐页渲染检查标题、图注、表格跨页、页眉页脚、文字裁切和空白页。

## 交付检查

- [ ] 最终 DOCX/Markdown、图源和渲染图位于明确目录，版本号一致。
- [ ] 正文目录、图号、表号、附录链接与版本一致。
- [ ] 文档中没有 TODO、占位文本、未经证实的“已实现/已通过”。
- [ ] 不附带与本次评审无关的临时文件，也不覆盖原始参考稿。
