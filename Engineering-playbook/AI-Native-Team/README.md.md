**如何让AI全程辅助开发，必须要有足够的上下文阐明业务、需求、项目规范（模块架构、仓库规范、开发规范等等），无论是skill还是AGENTS.md，还是撰写提示词都是在提供足量的上下文给AI，然后进行开发，模型的能力会弥补上下文的不足，所以重中之重是积累对上层的任务，主要包括认知层面、设计层面、常见问题，然后积累AI开发经验包括SKill、AGNETS.md如何撰写，上层业务如何梳理、SPEC接口如何设计、如何实施、如何自测、如何CICD这些完整的AI编码工作流一旦建立，那么一旦有想法，那么将会在AI的帮助下快速形成mvp。最重要的就是培养上层的认知能力、对细枝末节的掌控能力，知道AI所缺上下文，以及哪里存在问题如何解决，而不是研究如何写出优雅代码**

**AI Native 开发的本质，是将人的工程经验、设计决策和质量标准，逐步转化为 AI 可以理解、执行和验证的工程体系。**

主要分为以下阶段：
1. 人工手编代码--主要依赖人对底层语法、业务理解、边界条件、异常处理等等能力的积累&培养
2. 提示词开发--当前主流的开发过程，主要依赖人对上层业务的理解，对所需编码内容的描述，侧重提示词/上下文的数量/质量，是否充足，发现了多少问题？补充了多少上下文？
3. AI-Native--侧重AI的自主性，AI自主实施、自动化验证+交付证据、人工决策、知识回流（持续迭代），真正的AI开发闭环，**需要大量积累这类经验**

主要培养以下意识&积累相应的SOP、skills、AGENTS.md如何撰写都是基于这些意识：
```
## **01**

**契约意识**

描述什么必须成立，而不是把所有实现步骤重新讲一遍。

自问：这次任务的目标、边界、不可违反的规则、成功标准是什么？

## **02**

**上下文意识**

让 AI 自主获取已有事实，而不是由人反复复制接口和字段。

自问：这些信息已经存在于 SPEC、代码、规则或文档中吗？

## **03**

**验证意识**

在实施之前想清楚如何证明做对了，而不是代码完成后才考虑测试。

自问：我应该要求 AI 提供什么可复现的正确性证据？

## **04**

**复用意识**

识别重复工作的共性，沉淀成模板、规则、脚本或 Skill。

自问：下一次出现同类任务，什么内容不应该再次由我解释？

## **05**

**编排意识**

把复杂开发组织为有依赖、有检查点的任务，而非无限延长一个对话。

自问：哪些工作可以自主执行，哪些必须经过决策或验收？

## **06**

**反馈演进意识**

让错误、人工纠偏和验收结果成为工程体系迭代的输入。

自问：这次为什么需要我介入？可以通过什么机制减少下一次介入？
```





此文件夹是用来沉淀一个项目从零到一各个阶段地标准SOP、如何推进等等内容，优先实现从需求-SPEC-coding-review-verification这一条主要AI时代程序员的积累，后续会考虑一个项目开发过程涉及到的所有阶段（通过角色区分，比如PM、产品经理、架构师、开发团队等等）然后尝试建立一套AI开发工作流&Team。

## 主要阶段：

1. **业务目标与问题定义**

用户是谁？解决什么问题？成功标准是什么？

输出：brief.md

2. **需求澄清与范围确定**

功能、非功能需求、边界条件、验收标准

输出：spec.md


3. **架构与技术方案**

模块、数据模型、API、技术约束、风险

输出：plan.md / design.md

4. **任务拆解与依赖规划**

小任务、输入输出、依赖关系、完成标准

输出：tasks.md

5. **Agent 编码与迭代**

读取上下文 → 执行任务 → 测试 → Review → 修复

输出：代码、测试和变更记录

6. **验收、交付与反馈**

需求覆盖、集成测试、部署、运行反馈



每一个阶段都都有对应的SOP、对应可能用到的产出模板、加速的Skill等等内容作为参考。
