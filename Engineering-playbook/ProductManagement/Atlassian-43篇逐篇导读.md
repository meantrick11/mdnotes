# Atlassian 产品管理专题：43 篇逐篇导读

> 对应 [Atlassian Product Management 专题导航](https://www.atlassian.com/agile/product-management)。本文把导航中的 43 篇文章逐篇归位，写出各自回答的问题和实际用途；综合观点与贯穿案例见[专题首页](README.md)。以下是中文转述，不是逐段翻译。

**怎样使用这份导读？** 先从当前工作中的问题找主题，再选原文细读。不要因为一篇文章有“7 个阶段”或“9 种工具”，就把它直接变成团队流程；先问它解决的是哪类问题，以及你的团队是否真遇到了这个问题。

## 1 角色与工作方式：谁为方向负责？

| 原文 | 核心问题与可用之处 |
| --- | --- |
| [产品经理](https://www.atlassian.com/agile/product-management/product-manager) | 解释 PM 的职责和日常判断，并与 PO 区分。适合建立岗位边界，而不是把 PM 定义成“写需求的人”。 |
| [新任产品经理第一周](https://www.atlassian.com/agile/product-management/tips-for-new-product-manager) | 新到岗位时尽早听客户、认识团队、保持初来时的观察力；适合设计入职第一周，而非急着承诺一张路线图。 |
| [Product Owner](https://www.atlassian.com/agile/product-management/product-owner) | 讨论 PO 如何管理待办事项、沟通相关方、连接业务目标与执行；适合厘清 PM、PO 与研发的交接。 |

这一组的共同提醒是：职位名称不会自动划清责任。先约定决策权与交接点，再选择组织结构。详见[产品管理与角色协作](00-总览与角色/产品管理与角色协作.md)。

## 2 战略与定位：往哪里去，为什么客户会选择你？

| 原文 | 核心问题与可用之处 |
| --- | --- |
| [产品战略](https://www.atlassian.com/agile/product-management/product-strategy) | 把愿景、目标、客户需求和优先举措连起来；用于判断一项功能是否值得做。 |
| [产品开发战略](https://www.atlassian.com/agile/product-management/product-development-strategy) | 从想法、验证到开发和上市，为新产品或新功能安排连续的决策过程。 |
| [产品差异化](https://www.atlassian.com/agile/product-management/product-differentiation) | 比较功能、品质、价格、服务和品牌等差异化路径；用于回答客户为什么选你。 |
| [产品组合管理](https://www.atlassian.com/agile/product-management/portfolio-management) | 当多个产品与团队争用资源时，用统一视图、指标和沟通机制连接整体战略。 |
| [产品生命周期管理](https://www.atlassian.com/agile/product-management/plm) | 从构想到退场连接产品信息和团队；适合讨论跨阶段信息如何保留。 |

这几篇分别处理单产品方向、新产品形成、竞争选择、多产品取舍与全生命周期信息。它们的层次不同，不能用一张路线图替代。详见[产品战略与生命周期](01-战略与定位/产品战略与生命周期.md)。

## 3 发现与需求：先确认问题，再爱上方案

| 原文 | 核心问题与可用之处 |
| --- | --- |
| [产品发现](https://www.atlassian.com/agile/product-management/discovery) | 在开发前理解客户并验证假设，强调持续发现和团队共同学习。 |
| [功能请求](https://www.atlassian.com/agile/product-management/feature-request) | 记录谁在什么情境下遇到问题、希望获得什么收益；使“加个功能”成为可研究的线索。 |
| [最小可行产品](https://www.atlassian.com/agile/product-management/minimum-viable-product) | 用尽量小的可用方案检验关键假设，并利用反馈决定下一步。 |
| [产品简报](https://www.atlassian.com/agile/product-management/product-brief) | 在探索早期简明写出对象、问题、价值和未知项，让相关方有共同的讨论起点。 |

从“客户想要模板”到“用户到底卡在哪里”，需要证据与实验，而不是把请求照单全收。详见[从反馈到问题验证](02-发现与需求/从反馈到问题验证.md)。

## 4 规划与优先级：把方向变成可调整的行动

| 原文 | 核心问题与可用之处 |
| --- | --- |
| [产品路线图](https://www.atlassian.com/agile/product-management/product-roadmaps) | 路线图如何表达愿景、方向与进展；还讨论谁参与、如何创建、展示和更新。 |
| [敏捷路线图](https://www.atlassian.com/agile/product-management/roadmaps) | 保持目标清楚，同时让实现路径随反馈变化；适合不确定性较高的产品工作。 |
| [路线图展示](https://www.atlassian.com/agile/product-management/tips-for-presenting-product-roadmaps) | 以背景、证据和取舍建立共识，避免空话和过度承诺。 |
| [产品规划](https://www.atlassian.com/agile/product-management/product-planning) | 从市场研究、愿景、规格和原型到上市，把关键环节串成计划。 |
| [优先级框架](https://www.atlassian.com/agile/product-management/prioritization-framework) | 比较 RICE、Kano、MoSCoW、价值／工作量、机会评分和延迟成本，按问题选择方法。 |
| [产品功能](https://www.atlassian.com/agile/product-management/product-features) | 区分功能与客户收益，并把功能放回用户需求、战略和路线图中判断。 |
| [用户故事地图](https://www.atlassian.com/agile/product-management/story-mapping) | 按用户目标与活动展开完整旅程，识别缺口并划分优先发布的切片。 |

这一组的顺序是：先有目标与客户旅程，再比较机会，最后用路线图对齐团队。详见[路线图与优先级](03-规划与优先级/路线图与优先级.md)。

## 5 设计与开发：使“为什么做”在交付中不丢失

| 原文 | 核心问题与可用之处 |
| --- | --- |
| [产品需求文档](https://www.atlassian.com/agile/product-management/requirements) | PRD 如何说明目的、功能和行为；敏捷环境下更重视共同理解与持续更新。 |
| [产品规格](https://www.atlassian.com/agile/product-management/product-specification) | 将范围、设计、测试和发布考虑具体化，减少跨团队误解与范围漂移。 |
| [产品设计](https://www.atlassian.com/agile/product-management/product-design) | 以用户问题和可用性为中心设计产品，而不只追求外观。 |
| [产品开发](https://www.atlassian.com/agile/product-management/product-development) | 从构思到测试、商业化解释产品开发的多阶段过程及团队协作。 |
| [新产品开发流程](https://www.atlassian.com/agile/product-management/new-product-development-process) | 用七阶段说明新产品如何从问题与想法走到上市后学习；阶段之间应允许迭代。 |
| [产品工程](https://www.atlassian.com/agile/product-management/product-engineering) | 工程师从“接票交付”走向参与发现、设计和结果验证。 |
| [产品评审](https://www.atlassian.com/agile/product-management/product-critique) | 通过有目标的跨职能反馈，检查可用性、功能和价值，并及时发现缺口。 |

文档解决“说清楚”，评审解决“共同发现问题”，研发参与解决“方案是否可行又有价值”。详见[从定义到交付](04-设计与开发/从定义到交付.md)。

## 6 发布与增长：交付以后，价值能否被发现？

| 原文 | 核心问题与可用之处 |
| --- | --- |
| [产品发布](https://www.atlassian.com/agile/product-management/product-release) | 让新能力可用所需的测试、部署、支持和后续处理；与面向市场的上市区分。 |
| [产品上市](https://www.atlassian.com/agile/product-management/product-launch) | 从目标、受众和定位到上市执行、反馈与调整。 |
| [上市清单](https://www.atlassian.com/agile/product-management/product-launch-checklist) | 用检查项协调上市前准备、上市时执行和上市后评估。 |
| [上市时间线](https://www.atlassian.com/agile/product-management/product-launch-timeline) | 让营销、研发、销售和支持的工作与依赖在同一节奏上。 |
| [上市活动](https://www.atlassian.com/agile/product-management/product-launch-event) | 讨论故事、演示与互动活动如何吸引目标受众；适用于确有集中传播需求的上市。 |
| [增长产品管理](https://www.atlassian.com/agile/product-management/growth-product-management) | 从目标指标与机会地图出发，设计实验、分析结果并更新增长策略。 |
| [产品驱动增长](https://www.atlassian.com/agile/product-management/product-led-growth) | 让用户通过产品体验直接感受价值，由体验推动获取、转化与扩展。 |

“功能已上线”“市场已知道”“用户已持续获得价值”是三个不同的里程碑。详见[发布上市与增长](05-发布与增长/发布上市与增长.md)。

## 7 度量与运营：把结果带回下一轮决策

| 原文 | 核心问题与可用之处 |
| --- | --- |
| [产品分析](https://www.atlassian.com/agile/product-management/product-analytics) | 从实际使用行为理解产品，同时警惕只看数据、失去对人的理解。 |
| [产品管理 KPI](https://www.atlassian.com/agile/product-management/product-management-kpis) | 讨论收入、留存、NPS、上市时间、缺陷和采用等指标如何与战略对齐。 |
| [产品指标](https://www.atlassian.com/agile/product-management/product-metrics) | 从获取成本、终身价值、流失、经常性收入和激活等角度观察产品表现。 |
| [NPS](https://www.atlassian.com/agile/product-management/nps-score) | 用推荐意愿观察客户态度，结合反馈而非只报告一个分数。 |
| [产品运营](https://www.atlassian.com/agile/product-management/product-operations) | 用数据、流程、工具及跨职能对齐支持规模化产品团队。 |

指标告诉我们哪里可能有问题，访谈和观察帮助解释原因，产品运营让这条学习链在团队变大后依然转得动。详见[指标与持续运营](06-度量与运营/指标与持续运营.md)。

## 8 工具与协作：流程需要支撑，但软件不能代替判断

| 原文 | 核心问题与可用之处 |
| --- | --- |
| [产品管理工具](https://www.atlassian.com/agile/product-management/product-management-tools) | 从想法收集到路线图、交付、分析与反馈，比较工具应支持哪些协作能力。 |
| [产品开发软件](https://www.atlassian.com/agile/product-management/product-development-software) | 看任务、待办、版本与敏捷工作流如何连接从想法到交付的过程。 |
| [路线图软件](https://www.atlassian.com/agile/product-management/roadmap-software) | 比较路线图工具的可视化、协作、集成与报告能力。 |
| [远程产品管理](https://www.atlassian.com/agile/product-management/remote-product-management) | 远程场景下建立清晰边界、共享文档和足够的主动沟通。 |
| [AI 与产品管理](https://www.atlassian.com/agile/product-management/pm-and-ai) | 用 AI 辅助研究、分析和自动化，同时理解其局限并保留人的判断。 |

原文来自 Atlassian，软件推荐与 Jira 生态相关。可以借鉴它提出的协作问题，具体工具仍应按团队现状评估。详见[工具与协作](07-工具与协作/工具与协作.md)。
