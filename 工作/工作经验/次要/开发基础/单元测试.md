## 单元测试关键要素总结

### 一、定义与价值
- **定义**：单元测试是验证软件最小可测试单元（函数、方法、类）正确性的测试方法，通常由开发人员在功能实现中或完成后编写。
- **价值**：
  - 提高代码质量与可靠性；
  - 尽早发现故障，降低后期修复成本；
  - 提高开发效率；
  - 便于重构和维护，形成回归安全网；
  - 促进团队协作；
  - 可作为代码使用样例手册。

### 二、核心原则：AIR
- **A：Automatic 自动化**：可自动执行，通常接入 CI，代码变更自动触发。
- **I：Independent 独立性**：测试之间独立，不依赖执行顺序或结果，粒度足够小。
- **R：Repeatable 可重复执行**：同样条件下结果一致，不依赖网络、数据库、文件系统等外部因素，外部依赖需 Mock。
- 额外要求：**明确断言、执行速度快、边界测试充分、覆盖率较高**。

### 三、编写流程与规范
1. **拆分测试用例**
   - 覆盖所有分支：if、else、switch 等；
   - 覆盖边界条件：如 -1、0、1。
2. **统一命名规范**
   - 测试类：`XxxTest`，如 `CalculatorTest`；
   - 测试方法：描述测试内容，如 `testAddition`。
3. **存放路径**
   - Maven 项目：源码 `src/main/java`，测试代码 `src/test/java`；
   - 测试类通常与被测类同包名，但在不同目录。
4. **选择框架**
   - Java 常用：**JUnit + Mockito**；
   - JUnit 提供注解和断言；
   - Mockito 用于模拟依赖对象，隔离外部服务。

### 四、Mockito 核心用法
- **mock 与 spy**
  - `mock`：默认不调用真实方法，返回默认值；
  - `spy`：默认调用真实方法，可通过插桩改变行为。
- **初始化方式**
  - `@ExtendWith(MockitoExtension.class)` + `@Mock` / `@Spy`；
  - `Mockito.mock(XX.class)` / `Mockito.spy(XX.class)`；
  - `MockitoAnnotations.openMocks(this)` + `@Mock` / `@Spy`。
- **参数匹配**
  - 通过方法签名指定哪些调用需要被处理；
  - 使用 `ArgumentMatchers.any(Class)`、`anyLong`、`anyString` 等；
  - 注意：匹配器和普通参数不能混用，`anyXxx` 通常不包括 `null`。
- **方法插桩**
  - 返回指定值：`when(mock.method()).thenReturn(value)` 或 `doReturn(value).when(mock).method()`；
  - void 方法：`doThrow`、`doNothing`、`doAnswer`；
  - 异常：`doThrow(Exception.class).when(obj).someMethod()` 或 `when(...).thenThrow(...)`；
  - 多次插桩：`thenReturn(1, 2, 3)`；
  - 自定义逻辑：`thenAnswer` / `doAnswer`；
  - 调用真实方法：`thenCallRealMethod()`。
- **verify 验证**
  - 验证调用次数和参数：`verify(mock).add("one")`；
  - 次数控制：`times(1)`、`never()`、`atLeast(1)`、`atMost(1)`；
  - 顺序验证：`InOrder`。
- **@InjectMocks**
  - 自动将当前类中的 mock/spy 按类型或名字注入；
  - 被标注属性必须是实现类，常配合 `@Spy` 使用。

### 五、通义灵码辅助生成单元测试
- **手工选中代码**：在问答框输入 `/generate unit test` 或“生成单元测试”，可追加参数如 `JUnit5 Mockito`。
- **快捷按钮**：方法签名上方图标，点击后选择“生成单元测试”。
- **采纳方式**：
  - 插入代码；
  - 复制；
  - 新建文件，按 Java 单测规范放入 test 目录。
- **追问优化**：
  - 输入补充要求或点击预置 Tag，如 `Retry`、`Use Mockito`、`Use Spring Test`、`Explain code`；
  - 使用 `/add test coverage` 或中文追问提高覆盖率；
  - 可先采纳部分用例，再在测试文件中用代码续写补充。
- 文中提到：通义灵码生成单测可提效 **30% 以上**，但生成用例通常不遍历全部，需要审查调整。

### 六、常见异常与解决
- `UnfinishedStubbingException`：`when` 后未正确指定返回值。
- `InvalidUseOfMatchersException`：匹配器与普通参数混用。
- `No stubbing found...`：`verify` 或 `when` 参数与实际调用不匹配。
- `TooManyActualInvocations`：实际调用次数超过预期。
- `NeverWantedButInvoked`：`never()` 但实际被调用。
- `PotentialStubbingProblem`：插桩后实际代码未调用该方法。
- `WrongTypeOfReturnValue`：返回类型与方法签名不匹配。
- `Cannot mock/spy class`：final 类、静态方法、私有方法，需 PowerMockito 等工具。
- `VerificationInOrderFailure`：顺序验证与实际调用顺序不符。

### 七、进阶场景
- **微服务 / Feign 调用**
  - 使用 `@SpringBootTest` + `@AutoConfigureMockMvc`；
  - `MockMvc` 不启动 HTTP 服务即可模拟 REST 请求；
  - 通过 `WebApplicationContext` 获取 Bean，反射替换 FeignClient 为 mock；
  - `objectMapper` 模拟请求/响应序列化和反序列化；
  - 用 `Mockito.when(...).thenReturn(...)` 插入 Stub。
- **Mock RedisTemplate**
  - 直接 `@Mock RedisTemplate` 容易因属性为 null 导致 NPE；
  - 通过 `@Configuration` + `@Bean` 创建 mock 的 `RedisTemplate`；
  - 同时 mock `ValueOperations`、`SetOperations`、`HashOperations`、`ListOperations`、`ZSetOperations`、`RedisConnectionFactory`、`RedisConnection`；
  - 用 `when(redisTemplate.opsForXxx()).thenReturn(...)` 填充依赖。
- **when thenReturn**
  - 链式定义模拟对象返回值；
  - 支持多次调用返回不同值：`thenReturn(3, 4, 5)`。

### 八、最佳实践清单
- 遵循 **AIR**：自动化、独立、可重复；
- 测试粒度小、断言明确、执行快；
- 分支和边界覆盖充分；
- 外部依赖全部 Mock，不依赖真实网络、数据库、Redis、文件系统；
- 接入 CI，代码变更自动触发；
- 使用 JUnit 做断言，Mockito 做隔离、插桩和验证；
- 使用 MockMvc 加速 REST 单元测试；
- 借助通义灵码生成初版用例，但必须人工审查、追问和补充覆盖率。

**一句话总结**：单元测试的关键是遵循 AIR 原则，用 JUnit 编写明确断言，用 Mockito 隔离外部依赖并完成插桩与验证，同时保持规范命名、独立可重复、覆盖分支边界，并接入 CI 形成质量防护网。
