# 常见产品架构形态

这组笔记回答：为什么有的项目是“一个网页加一个后端”，有的却有用户端、运营端、企业侧连接器、门户、平台端，以及多个仓库和分支？

先读 [00 架构的四个维度](00-架构的四个维度.md)，再按当前项目选读。这里的形态不是互斥分类：一个产品可以同时是多入口产品、企业 SaaS 和微服务后端。

| 文档 | 主要回答 |
| --- | --- |
| [00 架构的四个维度](00-架构的四个维度.md) | 产品、入口、部署、代码分别在说什么？ |
| [01 单一应用](01-单一应用.md) | 一个网页和一个后端为什么够用？ |
| [02 多入口产品](02-多入口产品.md) | 为什么同一产品会有多个前端？ |
| [03 多租户 SaaS](03-多租户SaaS.md) | 多个企业共用厂商系统时怎样隔离？ |
| [04 企业本地部署](04-企业本地部署.md) | 部署在客户内部为何还需要认证、运维？ |
| [05 中心平台与企业侧连接器](05-中心平台与企业侧连接器.md) | 中心如何协调企业侧系统？ |
| [06 混合与联邦式部署](06-混合与联邦式部署.md) | 中心和企业侧各运行一部分时会遇到什么？ |
| [07 代码组织与产品架构](07-代码组织与产品架构.md) | 产品、服务、仓库、模块、分支如何区分？ |

每读一种形态，回答五个问题：**谁使用、从哪里进入、系统部署在哪里、数据主要在哪里、谁负责运营**。然后再看仓库和服务划分。文中的短视频、电商、飞数和数宝只用作概念示例；除明确注明的部分外，不代表其真实完整的内部架构。
