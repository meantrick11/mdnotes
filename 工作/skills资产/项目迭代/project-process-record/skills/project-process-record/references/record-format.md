# 过程记录格式参考

按事件裁剪字段，不必逐项填空。将“未发生”“待决定”“证据不足”写清，比补齐模板更重要。

## 问题或决策页

```markdown
# <稳定编号>：<具体问题>

状态：待调查 / 待决定 / 已决定 / 验证中 / 已解决 / 已取代
发现：<日期或可确认的时间范围；事后回溯需注明>
上级问题：<链接；没有则省略>
相关问题：<链接；没有则省略>

## 触发与影响
<观察到什么，影响哪个目标、约束或后续工作>

## 当时的证据
<原始链接、版本、run 或提交；写明证据局限>

## 选项与取舍
<主要方案、各自代价；未比较过的方案不补写成当时选项>

## 决定及理由
<决定者或依据、决定日期；尚未决定则明确标注>

## 执行与验证
<做了什么、结果如何；未执行则标注计划/建议>

## 后续更新
- <日期>：<新证据、状态变化或替代决定，附链接>

## 遗留问题
<下一步要验证什么，链接子问题>
```

## 时间线与索引

时间线每条只写“日期或范围、关键转折、问题页链接”；主题入口概述起点、主要分歧、当前状态，并列出问题页。原始报告保留原位，通过链接引用。涉及跨项目复用的经验，可另提炼为 SOP 或 Skill，不直接把项目结论复制进通用 Skill。

## 证据表述

- **当时记录**：原有文件、提交或运行产物能证明当时已知道或已决定。
- **事后还原**：根据留存材料重建过程，说明来源与可确认范围。
- **无法确认**：缺少材料，保留问题，等待补充。
- **建议**：有人提出但未执行；与已批准的决定分开。
- **已验证**：有对应的运行或验收证据，并注明数据、版本和限制。
