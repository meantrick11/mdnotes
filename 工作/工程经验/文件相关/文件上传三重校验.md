# 文件上传三重安全校验笔记
> 对应代码：`checkExtension`、`checkMimeType`、`checkMagicBytes`
> 校验顺序一般：**后缀名校验 → MimeType校验 → MagicBytes魔数校验**，层层拦截，防护恶意文件上传

## 一、第一层：checkExtension 文件后缀名校验
### 作用
校验上传文件的后缀名是否在后台配置的白名单列表，**第一道关卡，快速拦截非法后缀**。
### 入参
`extension`：提取出来的文件后缀（如jpg、pdf）
### 代码逻辑
1. 读取配置类`fileServiceConfig`中的上传校验配置，获取**允许上传的后缀白名单 allowed**；
2. 如果白名单为空/空集合，直接跳过本次校验；
3. 使用`stream().anyMatch`**忽略大小写**匹配后缀（防止`.JPG`、`.Png`大小写绕过）；
4. 后缀不在白名单：打印告警日志，抛出业务异常，拒绝上传。

### 原理
只校验**文件名**的后缀字符串，和文件实际内容无关。

### ✅优点 & ❌缺点
- ✅ 简单高效、配置驱动，不需要修改代码，调整配置即可增减允许后缀
- ❌ **极易绕过**：攻击者只需要修改文件名后缀就能绕过。例如把`virus.exe`重命名为`test.jpg`，直接通过本层校验。

---

## 二、第二层：checkMimeType MIME类型校验
### 作用
校验HTTP请求头中的`Content-Type`，验证客户端上报的文件媒体类型，**第二层辅助校验**。
### 入参
`extension` 文件后缀、`contentType` 请求头携带的Content-Type（来自MultipartFile）
### 代码逻辑
1. 如果`contentType`为空，直接跳过校验；
2. 根据小写后缀，从`EXTENSION_MIME_MAP`获取该后缀对应的合法MIME集合；没有配置则跳过；
3. 预处理contentType：截取`;`前面内容（因为Content-Type经常附带参数，例如`image/jpeg; charset=utf-8`），去除前后空格；
4. 判断处理后的MIME是否存在于该后缀允许的MIME集合，不存在则打日志、抛异常拦截。

> `EXTENSION_MIME_MAP`：静态Map，key=小写后缀，value=Set集合，保存该后缀合法MIME，示例：`jpg -> {image/jpeg}`

### 原理
MIME是客户端（浏览器）在HTTP请求头里声明的文件类型，后端维护后缀与MIME的映射关系做校验。

### ✅优点 & ❌缺点
- ✅ 在后缀校验基础上增加一层限制，提高攻击成本
- ❌ **客户端可控，可以抓包伪造**。攻击者修改请求头的Content-Type就能绕过，**不能信任客户端提交的值，只能作为辅助校验**

## 三、第三层：checkMagicBytes 魔数(Magic Bytes)校验
### 作用
读取文件二进制头部字节，识别文件**真实格式**，三层校验里**最核心、安全等级最高**的防护。
> 魔数：文件二进制开头固定标记，是文件本身内置特征，和文件名、请求头无关。

### 入参
`extension` 文件后缀、`file` MultipartFile上传文件对象
### 代码逻辑
1. 小写后缀去查询`EXTENSION_MAGIC_FAMILY`，拿到**预期文件家族 expectedFamily**；该后缀无配置则直接跳过校验；
    > `EXTENSION_MAGIC_FAMILY`静态Map：key后缀，value为文件家族标识，如IMAGE、DOC；jpg/png/gif统一归类IMAGE家族
2. 通过try-with-resources打开文件输入流，读取文件**前12个字节**作为文件头；
3. 读取字节不足2个（文件过小），直接跳过校验；
4. `detectMagicFamily(header, read)`：自定义方法，比对文件头字节魔数，返回识别到的文件家族`detected`；
5. 识别结果为空 或 识别家族≠预期家族：告警日志 + 抛异常拦截上传；
6. 异常处理：业务异常直接向上抛出；读取流发生其他异常 → 打印警告日志，**跳过魔数校验，放行文件**。

### ✅优点 & ❌缺点
- ✅ 校验文件二进制真实内容，单纯修改文件名、修改请求头无法绕过；专门防御【改后缀伪装文件】攻击
- ❌
  1. **家族匹配粒度粗**：jpg、png都属于IMAGE家族，png文件改后缀jpg，校验会直接放行。如果业务要求只能上传jpg，需要改成精确魔数匹配，不能用家族归类。
  2. 代码存在安全隐患：文件流读取异常时，直接跳过魔数校验，文件放行。高危业务建议改成：读取异常直接拒绝上传。
  3. 无法防御**图片马**：文件头部保留图片魔数，文件尾部追加恶意脚本。图片马需要额外图片解析、内容检测。
  4. 仅读取前12字节，少数特殊文件魔数不在文件头部，无法识别。

# 四、三层校验对比汇总表
| 校验方法 | 校验数据源 | 是否可客户端伪造 | 安全等级 | 定位 |
| ---- | ---- | ---- | ---- | ---- |
| checkExtension 后缀校验 | 上传文件名 | ✅极易伪造，改文件名即可 | 低 | 第一层快速过滤，基础白名单 |
| checkMimeType MIME校验 | HTTP请求头Content-Type | ✅抓包修改请求头伪造 | 中 | 第二层辅助校验，增加攻击成本 |
| checkMagicBytes 魔数校验 | 文件二进制头部字节 | ❌不能简单伪造 | 高 | 核心校验，识别文件真实类型 |

# 五、整体执行流程
1. 校验后缀名：不在白名单直接拦截 ✖
2. 后缀合法 → 校验MimeType：MIME不匹配拦截 ✖
3. MIME通过 → 魔数校验：文件真实类型不符合预期拦截 ✖
4. 三层全部校验通过，才允许保存文件 ✔

# 六、现有代码风险点（生产重点关注）
1. **魔数校验异常分支放行风险**：读取文件头IO异常时，代码只打日志，跳过魔数校验。建议修改：捕获异常直接抛出异常拒绝上传，不要放行。
2. 魔数使用家族归类：多图片格式共用IMAGE家族，限制单一文件类型场景不适用，需要调整detectMagicFamily做精确魔数判断。
3. MIME校验仅作为辅助，**不可单独依赖**，因为客户端可篡改请求头。
4. 三层校验只能防御基础恶意文件上传，无法防御图片马；高危场景额外需要：图片渲染校验、病毒扫描、上传目录禁止脚本执行权限。
5. 白名单`allowedExtensions`需要严格管控，禁止开放`exe、bat、jsp、php`等脚本/可执行后缀。

# 七、总结
文件上传推荐**组合校验策略**，三者缺一不可：
- 后缀白名单：低成本第一道防线，拦截大部分明显非法后缀；
- MimeType校验：辅助加固，提高攻击者绕过成本；
- MagicBytes魔数校验：核心防护，校验文件二进制真实类型，解决修改文件名伪装文件的攻击。

> 三层组合大幅提升恶意文件上传的攻击门槛，但不是绝对安全，高风险业务需要叠加更多防护手段。
