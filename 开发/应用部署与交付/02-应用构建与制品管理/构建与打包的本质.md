# 构建与打包的本质

构建把源码和依赖转化为可验证、可分发的产物；打包给产物确定结构和运行入口。Python 项目可能交付 wheel、源码包、锁定依赖的应用目录或容器镜像，不能把“Python 无须编译”理解为“没有构建过程”。

```text
Git 提交 → 解析依赖 → 静态检查/测试 → 构建 → 标记版本 → 入库 → 部署同一制品
```

理想构建输入包括源码版本、解释器和依赖版本、构建脚本、基础镜像及平台架构。输出至少记录制品名称、版本、构建时间、对应提交和校验值；通过测试的那个制品应被提升到后续环境，避免每个环境重新从源码构建出不同结果。

**依赖声明**回答需要什么；**锁定文件**记录具体解析结果；**环境配置**提供运行时差异；**制品**则是本次发布的字节内容。数据库密码和环境地址不应烘焙进可分发制品。配置注入后，才形成某个环境里的运行实例。

最小练习：对同一提交在隔离环境中安装锁定依赖、运行测试、生成包或镜像，记录版本与校验值，再在另一环境部署该制品并验收。失败时先区分是构建输入、制品、配置还是运行平台问题。
