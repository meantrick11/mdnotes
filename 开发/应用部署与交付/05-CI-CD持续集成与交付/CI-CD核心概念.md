# CI/CD 核心概念与交付边界

**CI（持续集成）**是频繁合并变更，并自动运行构建与验证，尽早发现集成问题。**持续交付**使通过验证的版本始终处于可发布状态；**持续部署**再把满足门禁的版本自动发布到目标环境。团队可只做到前两者。

```text
Git 提交/合并 → 触发流水线 → 检查与测试 → 构建制品 → 入库
                                                ↓
                         测试环境部署 → 验收 → 发布决策 → 生产发布 → 观测
```

Pipeline 描述整体流程，Job 是平台上的一次任务或任务定义，Stage 是逻辑阶段，Step 是具体动作。Jenkins、GitLab CI 和 GitHub Actions 负责执行与编排；质量标准来自项目测试、代码评审、制品和发布策略，而不是工具名称。

有效流水线应保证：失败即停止；测试结果可见；同一提交对应可追溯制品；环境凭据由安全机制注入；部署前后有明确验证；能够找到上一个可用版本。自动化能减少手工差错，但不能替代需求验收、数据兼容性检查和生产风险判断。

最小练习：给 FastAPI 项目加提交触发的单元测试和构建任务；保存构建编号、Git 提交和制品版本；将同一制品部署到测试环境并进行接口冒烟验证。再模拟测试失败，确认流程不会继续部署。
