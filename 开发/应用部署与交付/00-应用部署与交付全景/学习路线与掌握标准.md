# 学习路线与掌握标准

学习目标是独立交付 AI/后端应用。层次含义：**L1** 解释定位；**L2** 独立完成常见场景；**L3** 设计方案并处理复杂故障；**L4** 深入实现和规模化治理。阶段表示学习先后，不表示技术价值高低。

| 阶段 | 内容 | 建议掌握 | 可验证产出 |
| --- | --- | --- | --- |
| P0 当前应掌握 | Linux、SSH、构建依赖、Python 手动部署、systemd、Docker/Compose、进程端口日志排查 | L2 | 单机部署 FastAPI，重启后自恢复，能定位启动失败 |
| P1 工程交付 | CI/CD、Jenkins 基础流水线、Nginx、多服务、制品配置、更新回滚、推理服务 | L2；部署设计到 L3 | 从 Git 提交到测试环境自动构建部署，完成一次回滚演练 |
| P2 按需深入 | Kubernetes、Helm、Prometheus、Grafana、OpenTelemetry、Ansible、Terraform | 先 L1，再按项目需求到 L2/L3 | 说明引入条件，并在实际场景做最小实验 |

## 推荐顺序

1. 读全景与构建链路，画出自己的应用从提交到运行的路径。
2. 完成 Linux/SSH/Python/systemd 单机服务部署，记录启动、验证与排障。
3. 用 Docker 与 Compose 重做同一应用，比较配置、数据和网络处理。
4. 为项目加构建测试流水线、制品版本、Nginx 入口和回滚步骤。
5. 项目出现多节点、容量或治理要求时再学习 P2 对应技术。

每个阶段以实际演练验收；“读过文档”不等于达到 L2。技术专题 README 中的规划状态与能力层次分开记录。
