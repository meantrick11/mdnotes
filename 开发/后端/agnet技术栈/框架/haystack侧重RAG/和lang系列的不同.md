# Haystack vs LangChain/LangGraph 核心差异
## 1. 底层核心范式不同
- **Haystack**：以 **Component + Pipeline（DAG有向无环图）** 作为基础抽象。
  所有能力（文档切分、嵌入、检索、重排、LLM、Agent）全部封装成独立组件；组件之间通过端口连接，数据沿着连线单向流动。Pipeline默认是一次性执行DAG，组件之间没有全局共享内存。
- **LangGraph（Lang系列核心编排层）**：以 **状态图 StateGraph** 为基础抽象。
  基础单元是 Node（节点），节点之间依靠状态对象传递信息；不是端口连线，而是节点读写同一个共享状态。可以轻松构造带循环、分支、回退的图，不局限于DAG。
> LangChain本体更多是各类模型/工具的统一包装层，LangGraph负责流程编排，二者是组合关系；Haystack是完整一体化框架，编排、文档处理、检索都在同一个项目内。

## 2. 原生能力侧重点
- **Haystack：文档优先框架**
  从诞生目标就是解决非结构化文档处理：PDF、docx、txt等文档加载、清洗、分块、元数据管理、Document数据模型、多种检索器、重排器都是一等公民。
  Agent只是众多组件里其中一个，是在文档检索能力之上扩展出来的可选模块。
- **LangGraph：通用Agent/工作流编排框架**
  没有原生强文档模型，文档、检索只是众多工具中的一类。
  它不偏向文档场景，可对接数据库调用、API调用、业务审批、多Agent协作等任意任务；RAG只是它的一个业务场景，不是框架本体的核心。

## 3. Agent实现方式
- **Haystack Agent**：封装好的现成Component。
  内置工具调用循环逻辑，你只需要传入LLM和工具，配置退出条件，不需要手动编写循环、分支判断代码。开箱即用，但是自定义循环控制的自由度有限。
- **LangGraph Agent**：**没有内置成品Agent**。
  Agent由你自己组装：LLM节点、工具节点，手写条件边来判断是否继续调用工具。完全自定义循环逻辑、分支跳转，可以自由实现ReAct、Plan-and-Execute、Self-Reflection等任意Agent范式。

## 4. 组件与模型生态
- **Haystack**：组件数量偏少，但是**组件内聚度高**，尤其检索链路组件质量高；模型集成以主流LLM/Embedding为主。生态聚焦RAG，第三方插件少，但是组件之间接口标准统一，调试时每个组件输入输出都可以单独查看。
- **LangChain/LangGraph**：生态极其庞大，海量模型、工具、向量库、第三方集成。但很多集成由社区维护，质量参差不齐；大量封装是薄包装，底层参数不透明。

## 5. 可观测、调试与部署
- **Haystack**：Pipeline自带组件级日志、输入输出捕获。适合工程化部署，组件可单独测试、序列化，更适合稳定的生产RAG服务。
- **LangGraph**：调试重心在状态流转，自带可视化图、断点、会话持久化。适合迭代复杂Agent逻辑，会话记忆、人机交互、中途暂停是强项；生产部署需要额外处理状态持久化。

## 6. 适用边界
**Haystack 擅长：**
知识库问答、文档检索类RAG、Agentic-RAG；流程相对稳定，以文档处理为主，不需要复杂多分支/多轮业务循环。

**LangGraph 擅长：**
通用智能体、多Agent系统、需要人工介入审批、长会话记忆、多步骤复杂业务流程；检索只是其中一环。

## 极简对比表
|维度|Haystack|LangGraph(Lang系列)|
| ---- | ---- | ---- |
|基础抽象|Component + DAG Pipeline|Node + StateGraph|
|数据流|组件端口点对点传递数据|全局共享状态读写|
|Agent形态|现成封装组件|需要手动组装节点+条件边|
|核心定位|文档/RAG一体化框架|通用工作流/智能体编排引擎|
|文档模型|Document为一等核心类型|无原生文档模型，文档属于普通数据|
|循环能力|Pipeline仅支持简单循环；Agent内置固定循环|原生支持任意循环、分支、回退|
|生态|聚焦RAG，集成少而精|海量第三方集成，覆盖面广|
