# 管道循环

了解循环在 Haystack 管道中的工作原理、终止方式，以及如何利用循环实现反馈与自我修正。

Haystack 管道支持循环：组件图中的循环，即后续组件的输出反馈到更早的组件。这支持了自我修正、验证或迭代优化等反馈流程，以及更高级的智能体行为。

运行时，只要组件的所有必需输入再次准备就绪，管道就会重新运行该组件。你可以通过精心设计图和路由逻辑，或使用内置的安全限制来控制循环的停止时机。

## 同一组件的多次运行

如果某个组件参与循环，那么在单次 Pipeline.run() 调用中，该组件可能会运行多次。管道会为每个组件维护一个内部访问计数器：

- 组件每运行一次，其访问计数就会增加1。
- 你可以在断点等调试工具中使用此访问次数来检查循环的特定迭代次数。

在最终的管道结果中：
- 对于每个运行的组件，管道仅**返回最后生成的输出**。
- 要在最终结果字典中捕获中间组件（例如验证器或路由器）的输出，请使用 include_outputs_from 参数。

**最好不要自相连，而通过将输出发送给ConditionalRouter路由组件，由路由组件进行判断是否循环/或者硬性设置循环次数**

## 循环终止&安全限制

循环最终必须停止，这样管道运行才能完成。循环有两种主要结束方式：

1. 自然完成：没有更多可运行的组件
当工作队列为空且没有组件可以再次运行时（例如，路由器停止将输入反馈回循环），管道完成。
2. 达到最大运行次数
每个管道都有每个组件的运行限制，该限制由 max_runs_per_component 构造函数的 Pipeline 参数控制，默认值为 100。如果任何组件超出此限制，Haystack 会引发 PipelineMaxComponentRuns 错误。

**你可以将此限制设置为更低的值：**
```python
from haystack import Pipeline

pipe = Pipeline(max_runs_per_component=5)
```
每次执行前都会检查该限制，因此限制为3的组件会成功完成3次运行，直到第4次尝试时才会触发错误。

## 循环中贪婪与惰性可变参数套接字的对比

部分组件支持可变参数输入，可在单个套接字上接收多个值。在循环中，可变参数行为控制着输入在多次迭代中的使用方式。

- **贪婪可变参数套接字**：每次仅消费一个值，并在组件运行后将其移除。这包括用户提供的输入，可防止它们无限次重新触发组件。大多数可变参数套接字默认都是贪婪模式。
- **惰性可变参数套接字**：累积所有迭代中从前序节点接收到的值。适用于需要随时间收集多个部分结果的场景（例如，在继续执行前收集多次循环迭代的输出）。

**对于大多数循环场景，只需像往常一样连接组件并使用 max_runs_per_component 来防止错误就足够了。**

## 故障排除循环

如果你的管道看起来卡住或运行时间比预期长，以下是常见原因及调试方法。

### 无限循环的常见原因

1. 条件从未满足：由于大语言模型（LLM）的行为或数据问题，你的退出条件（例如"Rome" in reply）可能永远无法成立。请务必设置合理的max_runs_per_component作为安全保障。**这点也是路由组件需要注意的，很有可能路由的不完全**

2. 依赖可选参数：当一个组件有多个输出接口但仅返回其中部分时，未返回的输出不会触发其下游连接。这可能会在循环中造成混乱。

比如：
```python
@component
class Validator:
    @component.output_types(valid=str, invalid=Optional[str])
    def run(self, text: str):
        if is_valid(text):
            return {"valid": text}  # "invalid" is never returned
        else:
            return {"invalid": text}
```

如果你将 invalid 连接回上游组件以进行重试，但同时存在其他保持循环活跃的连接，可能会出现意外行为。


相反，请使用带有明确且互斥条件的ConditionalRouter：

```python
router = ConditionalRouter(
    routes=[
        {
            "condition": "{{ is_valid }}",
            "output": "{{ text }}",
            "output_name": "valid",
            "output_type": str,
        },
        {
            "condition": "{{ not is_valid }}",
            "output": "{{ text }}",
            "output_name": "invalid",
            "output_type": str,
        },
    ]
)
```

3. 如果用户提供的输入连接到循环内部的套接字，可能会导致循环意外重启。

4. 为同一组件提供输入的多条路径：如果循环内的一个组件从多个来源接收输入，那么只要任意一条路径提供输入，它就会运行。

## 调试技巧

1. 从低限制开始：开发循环时，将 max_runs_per_component=3 设置为 3 或类似值。这能帮助你尽早发现问题并获得明确的错误提示，而无需等待超时。
2. 使用 include_outputs_from：添加中间组件（如你的路由器）以查看每一步的运行情况：
`result = pipe.run(data, include_outputs_from={"router", "validator"})`
3. 启用追踪：使用追踪功能可以查看每个组件的执行情况，包括输入和输出。这能让你轻松跟踪循环的每一次迭代。快速调试时，可使用 LoggingTracer（设置说明）。深入分析时，可与 Langfuse 等工具或其他 追踪后端集成。
4. 可视化流水线：使用 pipe.draw() 或 pipe.show() 查看图形结构并确认你的连接无误。
5. 使用断点：在特定组件和访问计数上设置Breakpoint，以检查该迭代时的状态。
6. 检查被阻塞的管道：如果看到PipelineComponentsBlockedError，则表示没有组件可以运行。这通常意味着缺少连接或存在循环依赖。请确保已提供所有必需的输入。

通过结合精心的图表设计、组件级运行限制以及这些调试工具，你可以在 Haystack 管道中构建稳定的反馈循环。
