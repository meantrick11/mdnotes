# 管道断点

学习如何使用断点暂停和恢复 Haystack 管道的执行，借助这些断点调试工作流、检查状态，并从保存的快照中继续执行工作流。

## 介绍

Haystack 管道支持断点功能，用于调试复杂的执行流程。Breakpoint 允许你在特定组件处暂停执行、查看管道状态，并从保存的快照恢复执行。该功能适用于所有常规组件以及 Agent 组件。

你可以在管道中的任意组件上设置断点，并指定特定的访问次数。触发后，系统会停止管道的执行，并捕获当前管道状态的快照。启用快照文件保存功能后，该状态可保存至 JSON 文件，具体见下文快照文件保存。你可以查看和修改该快照，并利用它从执行停止的准确位置恢复运行。

## 为常规组件设置Breakpoint

通过指定组件名称和触发断点的访问次数来创建Breakpoint。这对于包含循环的管道非常有用。默认的visit_count值为 0。

```python
from haystack.dataclasses.breakpoints import Breakpoint
from haystack.core.errors import BreakpointException

# Create a breakpoint that triggers on the first visit to the "llm" component
break_point = Breakpoint(
    component_name="llm",
    visit_count=0,  # 0 = first visit, 1 = second visit, etc.
    snapshot_file_path="/path/to/snapshots",  # Optional: save snapshot to file
)

# Run pipeline with breakpoint
try:
    result = pipeline.run(data=input_data, break_point=break_point)
except BreakpointException as e:
    print(f"Breakpoint triggered at component: {e.component}")
    print(f"Component inputs: {e.inputs}")
    print(f"Pipeline results so far: {e.results}")
```
将抛出一个 BreakpointException，其中包含执行中断时刻之前的组件输入和管道输出，例如紧接在执行与断点相关联的组件（即上例中的 llm）之前。

如果在snapshot_file_path中指定了Breakpoint并启用了快照文件保存功能，系统将保存一个与BreakpointException中信息相同的JSON快照。默认情况下禁用将快照文件保存到磁盘；

要在断点期间访问管道状态，我们既可以捕获断点引发的异常，也可以指定 JSON 文件的保存位置，请注意必须启用文件保存功能。

## 使用自定义快照回调

你可以向Pipeline.run()传递一个snapshot_callback，以自行处理快照，而无需保存到文件中。当触发断点或因错误创建快照时，系统会使用PipelineSnapshot对象调用该回调函数。这对于将快照保存到数据库、发送到远程服务或进行自定义日志记录非常有用。

```python
from haystack.core.errors import BreakpointException
from haystack.dataclasses.breakpoints import Breakpoint, PipelineSnapshot


def my_snapshot_callback(snapshot: PipelineSnapshot) -> None:
    # Custom handling: e.g. save to DB, send to API, or log
    print(f"Snapshot at component: {snapshot.break_point}")


break_point = Breakpoint(component_name="llm", visit_count=0)
try:
    result = pipeline.run(
        data=input_data,
        break_point=break_point,
        snapshot_callback=my_snapshot_callback,
    )
except BreakpointException as e:
    print(f"Breakpoint triggered: {e.component}")
```

当提供 snapshot_callback 时，将跳过文件保存操作，由该回调函数负责处理快照。

## 快照文件保存

快照文件保存到磁盘功能**默认处于禁用状态**。若要在触发断点或管道故障时将快照保存为 JSON 文件，请将环境变量HAYSTACK_PIPELINE_SNAPSHOT_SAVE_ENABLED设置为"true"或"1"（不区分大小写）。启用后，快照会在触发断点时写入snapshot_file_path指定的路径，或在运行失败时写入使用快照进行错误恢复中定义的默认目录。

无论是否提供此设置，只要提供了自定义的 snapshot_callback 函数，就始终会调用它。

```python
import os

# Enable saving snapshot files to disk
os.environ["HAYSTACK_PIPELINE_SNAPSHOT_SAVE_ENABLED"] = "true"

break_point = Breakpoint(
    component_name="llm",
    visit_count=0,
    snapshot_file_path="/path/to/snapshots",
)
# When the breakpoint triggers, a JSON file will be written to /path/to/snapshots/
```
## 从断点中回复管道执行

要从断点恢复管道的执行，请在管道运行时使用pipeline_snapshot传入生成的JSON文件路径。

使用load_pipeline_snapshot()先加载JSON，再将其传递给管道。

```python
from haystack.core.pipeline.breakpoint import load_pipeline_snapshot

# Load the snapshot
snapshot = load_pipeline_snapshot("llm_2025_05_03_11_23_23.json")

# Resume execution from the snapshot
result = pipeline.run(data={}, pipeline_snapshot=snapshot)
print(result["llm"]["replies"])
```
## 使用快照进行错误恢复

如果运行失败，管道会自动创建最后一个有效状态的快照。该快照包含失败前的输入、访问次数和中间输出。你可以检查快照、修复问题，然后从该检查点恢复执行，而无需重新启动整个运行。

### 故障时访问快照

将 pipeline.run() 包裹在 try/except 块中，并从引发的 PipelineRuntimeError 中获取快照：

```python
from haystack.core.errors import PipelineRuntimeError

try:
    pipeline.run(data=input_data)
except PipelineRuntimeError as e:
    snapshot = e.pipeline_snapshot
    if snapshot is not None:
        intermediate_outputs = snapshot.pipeline_state.pipeline_outputs
        # Inspect intermediate_outputs to diagnose the failure
```

启用快照文件保存后（参见快照文件保存），Haystack 还会将同一份快照以 JSON 文件的形式保存到磁盘。目录会按以下顺序自动选择：

~/.haystack/pipeline_snapshot
/tmp/haystack/pipeline_snapshot
./.haystack/pipeline_snapshot

文件名将遵循以下格式：{component_name}_{visit_nr}_{YYYY_MM_DD_HH_MM_SS}.json


### 从快照恢复

你可以直接从内存快照恢复，也可以从磁盘加载它。

```py
from haystack.core.pipeline.breakpoint import load_pipeline_snapshot

snapshot = load_pipeline_snapshot(
    "/path/to/.haystack/pipeline_snapshot/reader_0_2025_09_20_12_33_10.json",
)
result = pipeline.run(data={}, pipeline_snapshot=snapshot)
```
