# Smart Pipeline Connections 页面内容解读

这一页介绍 Haystack Pipeline 的**智能流水线连接**能力：在**不改动组件本身逻辑**的前提下，简化组件之间的连线代码，减少样板代码，降低对 `Joiner`、`OutputAdapter` 这类“粘合组件”的依赖，让流水线代码更容易阅读维护。

主要包含两大核心功能，同时说明了原有粘合组件的适用边界：

## 1. Implicit List Joining｜隐式列表合并
可以直接将**多个组件输出连接到同一个组件输入**，不再需要显式写 Joiner 组件。
### 生效条件
1. 目标组件输入类型为 `list` / `list | None` / 列表联合类型；
2. 所有接入的输出都是兼容的列表类型。

### 行为
多个输出产出的列表，会被框架**自动拼接合并成一个完整列表**再传给目标输入。

**示例场景**：文件处理流水线
`FileTypeRouter` 将不同 MIME 类型文件分流给 `TextFileToDocument`、`HTMLToDocument` 两个转换器；两个转换器的 documents 输出直接同时接到 `DocumentWriter` 的输入，无需 `DocumentJoiner`。适合并行多分支结果汇总，附带完整可运行 Python 代码与流程图。

## 2. Flexible Type Connections｜灵活隐式类型适配
组件连线时支持内置自动类型转换，减少 `OutputAdapter` 使用。
> 类型合法性在校验 `connect()` 阶段检查，**类型转换实际发生在流水线运行时**；系统优先严格类型匹配，保证旧项目向后兼容。

支持的转换规则：

| 源类型 | 目标类型 | 行为 |
|---|---|---|
| `str` | `ChatMessage` | 将字符串包装成 user 角色的 ChatMessage 对象 |
| `ChatMessage` | `str` | 提取消息的 text 文本；text 为 None 时抛出 `PipelineRuntimeError` |
| `T`（单个对象） | `list[T]` | 将单个对象包装为只有一个元素的列表 |
| `list[str]` / `list[ChatMessage]` | `str` / `ChatMessage` | 取列表第一项；列表为空抛出运行时异常 |

**示例场景**：RAG 查询流水线
`OpenAIChatGenerator` 输出是 `list[ChatMessage]`，可以直接连接到检索器 `InMemoryBM25Retriever` 的字符串 query 入参，框架自动提取第一条消息文本作为检索关键词，附带完整示例代码。

## 3. 仍然需要 Joiner / OutputAdapter 的场景
智能连接并不能完全替代粘合组件，遇到下面场景建议继续使用显式组件：
1. 需要**超出简单列表拼接**的自定义聚合逻辑；
2. 需要上面表格没有覆盖的类型转换；
3. 需要显式控制数据格式、输出顺序。

> 提示：拿不准业务逻辑时，显式的 Joiner / OutputAdapter 代码可读性更高、可控性更强。

简单总结：智能连接解决两类高频痛点：**多分支输出合并列表**、**常见数据类型自动互转**，省去大量胶水代码，但复杂逻辑依然推荐使用传统粘合组件。
