# 组件(Components)

组件是管道(Pipeline)的构建模块。他们在查询路由至管道不同分支的同时，执行文本预处理、检索或摘要生成等等任务。本文汇集了Haystack的所有可用组件类型。

**组件之间通过管道相互连接，他们就像构建块一样，可以轻松地相互替换。**组件可以将其他组件选定地输出作为输入，可以通过pipeline.run()时为组件提供输入。

## 独立使用或者通过Pipeline相连

可以通过pipeline进行对组件进行集成相连以完成特定任务需要。同时，也可以使用其中地一些组件而不用Pipeline相连。比如你可以单独运行DocumentWriter，将文档写入文档存储库。

每个组件都有一个run()方法。当你在管道中连接组件并通过调用Pipeline.run()运行管道时，系统会按顺序调用每个组件的run()方法。

*组件类似节点，pipeline类似边，run类似invoke，也就是激活图，不过这样稍微有助于对比，如果，但是整体机制还是有些不同，比如lang系列是通过全局共享State，图只是更改State的途径，而Haystack则是通过组件直接通过Pipeline进行传递输入&输出来进行对整体结果的转变*

## 输入和输出

要在管道中连接组件，你需要了解它们所接受的输入和输出的名称。一个组件的输出必须与后续组件所接受的输入兼容。例如，要在管道中连接检索器（Retriever）和排序器（Ranker），你必须知道检索器输出documents，而排序器接受文档作为输入。

每个组件文档页面顶部的表格中都列出了必需的输入和输出，方便你快速查看。

你也可以在组件的run()方法代码中查看它们。以下是MetaFieldRanker的输入输出示例：
```python
# "documents" is the output name you need when connecting components in a pipeline
@component.output_types(documents=list[Document])
# "documents" is the mandatory input, additionally you can also specify the optional top_k parameter
def run(self, documents: list[Document], top_k: int | None = None):
    """
    Ranks a list of Documents based on the selected meta field.

    :param documents: List of Documents.
    :param top_k: The maximum number of Documents you want the Ranker to return.
    :return: List of Documents sorted by the value of their meta field.
    """
```

## 预热组件（Warming Up Components）

**使用大量资源的组件（如大语言模型或嵌入模型）都有一个 warm_up() 方法，该方法会将必要的资源（如模型）加载到内存中。**而简单处理组件(文本分割器、Document复制、过滤组件等)不需要预加载资源。

此方法会在组件首次运行时自动调用，因此你可以直接使用组件，无需显式调用 warm_up()：

```python
from haystack import Document
from haystack_integrations.components.embedders.sentence_transformers import (
    SentenceTransformersDocumentEmbedder,
)

doc = Document(content="I love pizza!")
doc_embedder = SentenceTransformersDocumentEmbedder()

result = doc_embedder.run([doc])  # warm_up() is called automatically on first run
print(result["documents"][0].embedding)

```

如果你想控制资源加载的时机，仍然可以显式调用 warm_up()。
