![分层](./pictures/langchain的分层.png)

首先，langchain能够满足90%的agent开发，主要原因在于：
    1. langchain 对底层的langchain-core的基类有转发(装饰器@tool、@chain|消息基类BaseMessage、HumanMessage/AIMessage/SystemMessage/ToolMessage|模型抽象基类BaseChatModel、BaseLLM、BaseEmbeddings|工具体系BaseTool、StructuredTool|整套（LCEL）Runnable、RunnableLambda、RunnableParallel、RunnablePassthrough|Prompt | 输出解析ChatPromptTemplate、BaseOutputParser、Json/Pydantic 解析器|RAG 底层抽象|Document、BaseRetriever、BaseVectorStore|通用回调、序列化、基础异常),所以可以直接在langchain中直接引入对应的类或者装饰器，但本质还是对langchain-core的转发。
    2. 除了上述对langchain-core的转发之外，langchain还有对上层业务的封装，比如init_chat_model，，该函数依赖langchain-core定义的模型抽象基类，同时自动适配langchain-openai、langchain-ollama等第三方模型集成包，然后才能封装，初始化模型
    3. 在上述core基类以及部分零件的封装之后，那么需要最终合成为agent，实现具能够React的agent，就需要使用到langgraph这类图编排器，通过维护全局状态或者函数调用，构建其工作流，比如create_agent(model=?,tools=[]...),然后才是一个完整的agent

综上所述，langchain-core是langchain体系的核心，具有最基础的类定义、装饰器等，然后利用langgraph的图编排(GraphAPI，全局共享State,图节点编排)或者函数式调用(FuncAPI,函数调用、全局无state，通过参数传递数据)功能，将langchian-core中的类或者langchian的中级封装组件(init_chat_model()等函数)对应到一个大的状态图和工作流里面，比如使用create_agent(model=?,tools=[],...)然后才是完整的agent实现



# 一、先分清两大包本质（一眼区分）
## 1. langchain-core（底层标准，无业务逻辑）
只做**抽象基类、通用装饰器、基础数据结构、LCEL运行时**
- 无任何厂商模型实现（没有ChatOpenAI、通义千问）
- 无高层业务工具（没有`init_chat_model`、`create_agent`）
- 无第三方工具实现（搜索、数据库工具都不在这）
### core里固定包含（必记）
1. **装饰器**
`@tool`、`@chain`
2. **消息基类**
`BaseMessage`、`HumanMessage`/`AIMessage`/`SystemMessage`/`ToolMessage`
3. **模型抽象基类**
`BaseChatModel`、`BaseLLM`、`BaseEmbeddings`
4. **工具体系**
`BaseTool`、`StructuredTool`、`ToolCall`
5. **Runnable整套（LCEL）**
`Runnable`、RunnableLambda、RunnableParallel、RunnablePassthrough
6. **Prompt/输出解析**
`ChatPromptTemplate`、`BaseOutputParser`、Json/Pydantic解析器
7. **RAG底层抽象**
`Document`、`BaseRetriever`、`BaseVectorStore`
8. 通用回调、序列化、基础异常

## 2. langchain（上层业务胶水包）
两类内容：**自有实现函数** + **core内容的重导出**
### ① langchain自己原生实现（不是转发）
- `init_chat_model`：模型统一工厂函数
- `create_react_agent` / `create_agent`：Agent高层封装（底层调用langgraph）
- 各类Chain、检索封装、多轮记忆封装、业务策略工具
### ② 重导出（re-export，只是转发core）
`from langchain.tools import tool`、各类Message、BaseTool、ChatPromptTemplate
源码内部只是一行`from langchain_core.xxx import xxx`，没有自己代码

# 二、快速判断：是原生langchain，还是core转发？
## 判断1：看功能定位（最简单）
1. **纯接口/基类/装饰器/基础数据结构** → 源头一定是core
   @tool、所有Message、BaseChatModel、Runnable、Document
2. **工厂函数、Agent创建、模型自动分发、业务流程封装** → langchain原生
   init_chat_model、create_react_agent
3. **具体厂商模型（ChatOpenAI）** → langchain-openai等集成包

## 判断2：代码里验证（10秒分辨）
打开Python交互环境，打印`__module__`看真实来源
```python
# 测试1：@tool
from langchain.tools import tool
print(tool.__module__)
# 输出 langchain_core.tools → 源头core，langchain只是转发

# 测试2：init_chat_model
from langchain.chat_models import init_chat_model
print(init_chat_model.__module__)
# 输出 langchain.chat_models.base → 原生langchain实现
```

## 判断3：导入路径经验规律
- 能直接从`langchain_core.xxx`导入的，全是core原生
- 只能从`langchain`导入、core里找不到同名函数，是langchain自有代码
- 两边都能导入但`__module__`指向core：重导出兼容写法

# 三、一句话总结区分
1. `@tool`、消息类、Runnable、BaseTool、BaseChatModel：**定义在core，langchain只是转发**
2. `init_chat_model`、`create_agent`、各类Chain：**langchain自己写的高层工具，core不存在**
3. 开发规范：稳定项目直接`from langchain_core import xxx`，减少依赖耦合；demo为方便可从langchain导入转发内容
