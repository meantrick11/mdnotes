## 摘要
OWL 2 Web本体语言（非正式简称OWL 2）是面向语义Web的本体语言，具备形式化定义的语义含义。OWL 2本体包含类、属性、个体与数据值，以语义Web文档形式存储。OWL 2本体可与RDF编写的信息协同使用，OWL 2本体本身主要以RDF文档格式交换。《OWL 2文档总览》介绍OWL 2整体概况，建议在阅读其他OWL 2文档前先行阅读。

这份入门文档通俗易懂地介绍OWL 2：包括面向其他领域背景读者的导读；通过一个贯穿全文的示例演示如何用OWL 2表达简单信息，再逐步表达复杂信息；讲解OWL 2如何管理本体；最后区分OWL 2的各个子语言。

## 1 引言
W3C的OWL 2 Web本体语言（简称OWL）属于语义Web语言，用于描述事物、事物集合、事物之间关系的丰富复杂知识。OWL是基于计算逻辑的语言，用OWL表达的知识可供计算机程序做推理：校验知识一致性，或是把隐式知识显式推导出来。OWL文档称为**本体**，可以发布在万维网上，能够引用其他OWL本体，也可被其他OWL本体引用。OWL属于W3C语义Web技术栈，配套技术包含RDF与SPARQL。

这份入门文档的核心目标：帮助读者理解OWL本身，理解它的优势与局限。文档主体借助一套贯穿全文的示例，介绍OWL绝大多数语言特性。示例本体全文放在附录。示例本体只是用来演示OWL关键语法特性，本身并不代表一份高质量本体的范例。

### 1.2 OWL语法
OWL用于语义Web，因此OWL中的名称都采用国际化资源标识符（IRI，RFC 3987）。由于IRI字符串很长，OWL中大量使用缩写机制。不同序列化语法的缩写实现方式各有差异，但阅读本文示例，无需深究这些底层细节。命名空间及相关声明机制详见8.2节。

OWL拥有多种语法，服务于不同用途：
1. **函数式语法**：用于规范定义，同时作为OWL 2工具（API、推理机）实现的基础。
2. **RDF/XML语法**：本质就是RDF/XML，只是对OWL构造做专门映射。**所有OWL 2工具必须支持该语法，是强制要求**。
3. **曼彻斯特语法（Manchester syntax）**：专门设计，便于非逻辑专业人员阅读。
4. **OWL XML语法**：基于XML Schema定义的一套XML语法。

现有工具可以完成不同OWL语法之间的互相转换。很多语法里OWL语言构造同样用IRI表示，使用简写形式需要相应声明。更多细节见8.2节。

本文示例以及附录完整示例本体，可以切换为上述四种任意语法查看。针对基于RDF的语法，文档同时提供RDF/XML和Turtle两种序列化形式。页面下方按钮可以控制页面展示/隐藏各类语法。

## 2 什么是OWL 2？
OWL 2是用来编写**本体**的语言。“本体”一词在计算机科学内外都有复杂演变；本文语境下，本体指一类计算产物，类似程序、XML模式、网页，通常保存为文档。本体是针对现实世界某一部分（一般称为**感兴趣领域**或者主题）的一组精确描述性语句。精确描述带来多重价值：最重要的一点，避免人类沟通产生歧义；同时保证软件行为统一可预测，保障软件之间互操作。

想要精确描述目标领域，需要定义一套核心术语，称为**词汇表**，并固定术语含义。除自然语言简短定义之外，术语含义也可以通过描述该术语与其他术语之间的关系来刻画。**术语集（terminology）**包含词汇表以及术语之间的关联信息，是一份典型OWL 2文档的核心组成部分。除术语知识之外，本体还可以包含**断言知识**：描述领域内具体对象，而不是描述通用概念。

OWL 2**不是编程语言**：OWL2属于**声明式语言**，用逻辑方式描述现实事态。配套工具（推理机）基于这些描述推导出更多信息。推理机内部算法如何实现推导不属于OWL文档定义内容，取决于具体工具实现。但推导的正确结果由形式语义预先确定；形式语义分为两套：**直接语义**、**基于RDF的语义**。只有符合这套语义标准的实现，才被视作符合OWL2规范。

正是声明式的本质，编写OWL文档和写程序在概念上并不等同。当然，二者都产出复杂形式化文档，软件工程部分理念可以迁移到本体工程：例如方法论、协作开发、模块化、本体模式等。

OWL2**不是语法校验类模式语言**。和XML不同，OWL2并不提供复杂机制约束文档的语法结构。特别地，OWL无法强制要求某条信息（例如一个人的社保号）必须在文档语法层面出现。这点需要特别留意，OWL部分特性容易被使用者误解为做这类语法约束。

OWL2**也不是数据库框架**。诚然OWL文档存储信息，数据库同样存储信息；断言知识可以类比数据库内容，术语知识可以类比数据库模式。但是二者底层假设（即语义）存在关键差异：数据库中一条事实如果没有出现，通常被视作这条事实为假，这就是**封闭世界假设**；而OWL2文档遵循**开放世界假设**：某条事实没有出现，只代表文档缺少这条信息，该事实有可能为真。数据库模式一般还带有命令式约束语义。当然，很多面向本体的系统，底层可以使用数据库作为支撑载体。

## 3 知识建模：基本概念
OWL2是知识表示语言，用来形式化表达、交换、推理目标领域的知识。理解OWL2知识表达，先要掌握一组基础概念：
- **公理(Axioms)**：OWL本体所表达的基础陈述。
- **实体(Entities)**：用来指代现实世界对象的元素。
- **表达式(Expressions)**：把实体组合，由基础构件构造复杂描述。

虽然OWL2用于捕获知识，但它所能表示的“知识”并不能覆盖人类全部知识。可以把OWL2理解为强大的通用建模语言，覆盖人类知识的一部分。建模产出物称为**本体**；这个叫法也用来避免歧义，因为“模型”一词在知识表示领域有完全不同含义。

把知识显式形式化，可以看作由一条条基础陈述（命题）构成，例如“正在下雨”“所有人终有一死”。每一份OWL2本体本质就是一堆这样的知识片段。本体中写下的陈述叫做**公理**；本体断言所有公理全部成立。给定某一种现实事态，OWL陈述可以为真，也可以为假；这一点区别于实体、表达式。

人类思考会从已有知识推出结论。OWL的重要能力就是，针对它能够表达的知识，复现这种推理。什么叫一条陈述由其他陈述推导而来？含义是：只要集合A内所有陈述全部成立，则陈述a也必然成立。用OWL术语描述：公理集合A**蕴含(entails)**陈述a。

公理集合可以**一致(consistent)**：存在某一种现实事态，让集合内全部公理同时成立；也可以**不一致(inconsistent)**：不存在这样的事态。OWL的形式语义本质就是规定：对于哪些“现实事态”，某一组OWL陈述取值为真。

OWL工具——**推理机**，可以自动计算推导结果。本体公理之间的相互作用非常微妙，人类很难一眼看透。这既是OWL2的优势，同时也是短板。
> ✅优势：工具能够发现人类注意不到的隐含信息；知识工程师可以更加直接地建模，系统也可以对建模给出反馈、指出建模问题。
> ⚠️短板：人类很难立刻预判各类构造组合之后实际会产生什么效果。工具可以缓解这个问题，但高质量本体工程仍然需要一定学习和实践经验。

仔细看OWL内部的陈述，它们很少是完全独立的，一般都具备内部结构，指向现实对象：把对象归到某个分类（例如“玛丽是女性”），描述对象之间的关系（例如“约翰和玛丽是夫妻”）。陈述里的原子成分，不管是对象（约翰、玛丽）、类别（女性）还是关系（婚姻），统称为**实体**。

在OWL2中：
- 对象叫做**个体(individuals)**
- 类别叫做**类(classes)**
- 关系叫做**属性(properties)**

OWL2的属性再细分为三类：
1. **对象属性(Object properties)**：建立个体与个体之间的联系，例如一个人与其配偶；
2. **数据属性(Datatype properties)**：把个体关联到数据字面量，例如给一个人标注年龄；
3. **注解属性(Annotation properties)**：用来描述本体自身（公理、实体）的元信息，例如公理作者、创建日期，而不是描述业务领域本身。

OWL一大核心能力：使用**构造子(constructors)**，把实体名称组合形成**表达式**。举个简单例子，原子类“女性”、“教授”可以合取，得到“女教授”这个类表达式。类表达式可以用在陈述中，也可以嵌套进别的表达式。从这个角度，表达式可以视作依靠结构定义出来的“新实体”。

不同实体的构造子丰富程度差异很大：类的表达式语言非常强大；属性的表达式语言则简陋很多。这种差异既有历史原因，也有技术层面考量。

## 4 类、属性、个体——以及基于它们的基础建模
讲完通用概念，接下来进入OWL2建模细节。下面从几乎所有建模语言都具备的基础特性讲起，逐步过渡到高级构造。本文以一个家庭信息作为建模示例。
> 注意：这个示例并不代表OWL适用的典型领域，也不是高质量本体的范本；家庭这个主题本身文化相关、定义复杂多变。本示例仅用于演示各类OWL语言构造。

### 4.1 类与实例
先引入我们要描述的人物。

> 函数式语法
```
 ClassAssertion( :Person :Mary ) 
```
> RDF/XML语法
```
 <Person rdf:about="Mary" />
```
> Turtle语法
```
 :Mary rdf:type :Person .
```
> 曼彻斯特语法
```
 Individual: Mary
 Types: Person
```
> OWL/XML语法
```
 <ClassAssertion>
 <Class IRI="Person" />
 <NamedIndividual IRI="Mary" />
 </ClassAssertion>
```

这条陈述描述个体Mary，声明Mary属于**Person（人）**这个类。更严谨表述：Mary是Person类的**实例(instance)**。

**类**用来把具备共同特征的个体归为一组。类本质代表一组个体集合。建模时，类常常对应人类认知中的概念，例如“人”“女人”。

我们可以用同类语句说明Mary同时是Woman（女人）的实例。

> 函数式语法
```
 ClassAssertion( :Woman :Mary ) 
```
> RDF/XML语法
```
 <Woman rdf:about="Mary" />
```
> Turtle语法
```
 :Mary rdf:type :Woman .
```
> 曼彻斯特语法
```
 Individual: Mary
 Types: Woman
```
> OWL/XML语法
```
 <ClassAssertion>
 <Class IRI="Woman" />
 <NamedIndividual IRI="Mary" />
 </ClassAssertion>
```

由此可以看出：**类成员身份不是互斥的**。个体可以同时属于多个不同类；可以按照性别、年龄、鞋码等多种维度对个体分组。

### 4.2 类层次结构
前面出现Person（人）和Woman（女人）两个类。人类常识知道：Person比Woman更加泛化——只要某个体是女人，则该个体一定是人。但是这个关系不能仅仅靠单词字面让机器理解，属于人类背景知识，必须显式告诉推理机。

在OWL2使用**子类公理(subclass axiom)**实现：

> 函数式语法
```
 SubClassOf( :Woman :Person )
```
> RDF/XML语法
```
 <owl:Class rdf:about="Woman">
 <rdfs:subClassOf rdf:resource="Person" />
 </owl:Class>
```
> Turtle语法
```
 :Woman rdfs:subClassOf :Person .
```
> 曼彻斯特语法
```
 Class: Woman
 SubClassOf: Person
```
> OWL/XML语法
```
 <SubClassOf>
 <Class IRI="Woman" />
 <Class IRI="Person" />
 </SubClassOf>
```

本体写入这条公理之后，推理机只要得知某个个体是Woman实例，就能够推导出该个体同时也是Person实例。

> 经验法则：当“所有A都是B”这句话成立，就可以设置A是B的子类。

本体建模经常大量使用子类公理，建立完整**类层次结构(class hierarchies)**，描述领域全部类之间泛化‑特化关系。例如声明所有母亲都是女人：

> 函数式语法
```
 SubClassOf( :Mother :Woman )
```
> RDF/XML语法
```
 <owl:Class rdf:about="Mother">
 <rdfs:subClassOf rdf:resource="Woman" />
 </owl:Class>
```
> Turtle语法
```
 :Mother rdfs:subClassOf :Woman .
```
> 曼彻斯特语法
```
 Class: Mother
 SubClassOf: Woman
```
> OWL/XML语法
```
 <SubClassOf>
 <Class IRI="Mother" />
 <Class IRI="Woman" />
 </SubClassOf>
```

推理机由此可以推导出：所有母亲也必然是人。也就是说，子类关系具备**传递性(transitive)**；同时子类关系具备**自反性(reflexive)**，每一个类都是自己的子类。

不同词汇有可能描述完全相同的个体集合；OWL提供**等价类(EquivalentClasses)**，表示两个类语义完全等同。例如Person与Human指代同一套集合，Person全部实例就是Human全部实例，反之亦然。

> 函数式语法
```
 EquivalentClasses( :Person :Human )
```
> RDF/XML语法
```
 <owl:Class rdf:about="Person">
 <owl:equivalentClass rdf:resource="Human" />
 </owl:Class>
```
> Turtle语法
```
 :Person owl:equivalentClass :Human .
```
> 曼彻斯特语法
```
 Class: Person
 EquivalentTo: Human
```
> OWL/XML语法
```
 <EquivalentClasses>
 <Class IRI="Person" />
 <Class IRI="Human" />
 </EquivalentClasses>
```

声明Person等价于Human，逻辑效果等价于同时写两条子类公理：Person是Human子类，并且Human是Person子类。

### 4.3 类不相交
4.1节说明一个个体可以属于多个类。但有些场景，属于一个类就代表绝对不能属于另一个类。例如示例中Man（男人）和Woman（女人），不存在个体同时属于二者（本示例暂时忽略生物学边界案例）。类之间这种互斥关系称为**类不相交(class disjointness)**。

该信息属于人类背景知识，必须显式写出，推理机才能使用。

> 函数式语法
```
 DisjointClasses( :Woman :Man )
```
> RDF/XML语法
```
 <owl:AllDisjointClasses>
 <owl:members rdf:parseType="Collection">
 <owl:Class rdf:about="Woman" />
 <owl:Class rdf:about="Man" />
 </owl:members>
 </owl:AllDisjointClasses>
```
> Turtle语法
```
 [] rdf:type owl:AllDisjointClasses ;
 owl:members ( :Woman :Man ) . 
```
> 曼彻斯特语法
```
 DisjointClasses: Woman, Man
```
> OWL/XML语法
```
 <DisjointClasses>
 <Class IRI="Woman" />
 <Class IRI="Man" />
 </DisjointClasses>
```

实践中，开发者经常遗忘写不相交公理。人们直觉上默认类之间天然互斥，但如果缺少这条公理，大量有价值的推导就无法得到。
> 举例：上面这条不相交公理，推理机才能推导出Mary不是Man。同时基于已有公理，推理机还能进一步推导出Mother和Man也是不相交类。

### 4.4 对象属性
前面章节描述个体、类归属，以及类之间的关系。但本体更多时候需要描述**个体和个体之间的关系**，家庭建模中这点尤为重要。举个例子：Mary是John的妻子。

> 函数式语法
```
 ObjectPropertyAssertion( :hasWife :John :Mary )
```
> RDF/XML语法
```
 <rdf:Description rdf:about="John">
 <hasWife rdf:resource="Mary" />
 </rdf:Description>
```
> Turtle语法
```
 :John :hasWife :Mary .
```
> 曼彻斯特语法
```
 Individual: John
 Facts: hasWife Mary
```
> OWL/XML语法
```
 <ObjectPropertyAssertion>
 <ObjectProperty IRI="hasWife" />
 <NamedIndividual IRI="John" />
 <NamedIndividual IRI="Mary" />
 </ObjectPropertyAssertion>
```

用来描述个体之间联系的实体（本例中hasWife），叫做**属性(properties)**。

⚠️个体书写顺序至关重要：“Mary是John的妻子”成立，反过来“John是Mary的妻子”不成立。这是建模常见错误。建议属性命名做到阅读无歧义：名词类属性可以用hasXXX / XXXOf；动词类属性使用主动式loves或者被动式lovedBy，避免歧义。

OWL还可以声明：两个个体**不具备**某条属性关系。例如：Mary不是Bill的妻子。

> 函数式语法
```
 NegativeObjectPropertyAssertion( :hasWife :Bill :Mary )
```
> RDF/XML语法
```
 <owl:NegativePropertyAssertion>
 <owl:sourceIndividual rdf:resource="Bill" />
 <owl:assertionProperty rdf:resource="hasWife" />
 <owl:targetIndividual rdf:resource="Mary" />
 </owl:NegativePropertyAssertion>
```
> Turtle语法
```
 [] rdf:type owl:NegativePropertyAssertion ;
 owl:sourceIndividual :Bill ;
 owl:assertionProperty :hasWife ;
 owl:targetIndividual :Mary .
```
> 曼彻斯特语法
```
 Individual: Bill
 Facts: not hasWife Mary
```
> OWL/XML语法
```
 <NegativeObjectPropertyAssertion>
 <ObjectProperty IRI="hasWife" />
 <NamedIndividual IRI="Bill" />
 <NamedIndividual IRI="Mary" />
 </NegativeObjectPropertyAssertion>
```

**负属性断言**用来显式说明某件事实不成立。这点在OWL开放世界假设下格外重要：没有写出来不代表为假；负断言可以把“明确为假”的知识记录下来。

### 4.5 属性层次结构
4.2节讲：A属于B类可以推出A属于父类。属性也有完全类似场景：如果B是A的妻子，那么B同时也是A的配偶（反过来不成立）。OWL使用子对象属性公理描述：

> 函数式语法
```
 SubObjectPropertyOf( :hasWife :hasSpouse )
```
> RDF/XML语法
```
 <owl:ObjectProperty rdf:about="hasWife">
 <rdfs:subPropertyOf rdf:resource="hasSpouse" />
 </owl:ObjectProperty>
```
> Turtle语法
```
 :hasWife rdfs:subPropertyOf :hasSpouse .
```
> 曼彻斯特语法
```
 ObjectProperty: hasWife
 SubPropertyOf: hasSpouse
```
> OWL/XML语法
```
 <SubObjectPropertyOf>
 <ObjectProperty IRI="hasWife" />
 <ObjectProperty IRI="hasSpouse" />
 </SubObjectPropertyOf>
```

同时也有属性等价的简写语法，和类等价类似。

### 4.6 定义域与值域约束
当两个个体通过某条属性建立联系，我们往往可以得到关于这两个个体的额外推导，最常见就是推导类归属。例如B是A的妻子，就可以推导出：A是男人，B是女人。也就是说，属性关系本身附带对参与个体的隐式信息。OWL使用**定义域(Domain)**、**值域(Range)**公理表达这种对应。

> 函数式语法
```
 ObjectPropertyDomain( :hasWife :Man ) 
 ObjectPropertyRange( :hasWife :Woman ) 
```
> RDF/XML语法
```
 <owl:ObjectProperty rdf:about="hasWife">
 <rdfs:domain rdf:resource="Man" />
 <rdfs:range rdf:resource="Woman" />
 </owl:ObjectProperty>
```
> Turtle语法
```
 :hasWife rdfs:domain :Man ;
 rdfs:range :Woman .
```
> 曼彻斯特语法
```
 ObjectProperty: hasWife
 Domain: Man
 Range: Woman
```
> OWL/XML语法
```
 <ObjectPropertyDomain>
 <ObjectProperty IRI="hasWife" />
 <Class IRI="Man" />
 </ObjectPropertyDomain>
 <ObjectPropertyRange>
 <ObjectProperty IRI="hasWife" />
 <Class IRI="Woman" />
 </ObjectPropertyRange>
```

写下这两条公理后，如果出现“Sasha 通过hasWife关联Hillary”这条事实，推理机会自动推导出Sasha属于Man，Hillary属于Woman。

> ⚠️建模常见误区：定义域、值域**不是校验约束**，不是用来“拦截错误数据”；而是用来**推导新的类断言**。
> 举例：hasAge定义域是Person；如果写“Felix是Cat，Felix hasAge 9”。推理机会推导出Felix是Person。很多建模者不希望这个结果，这是频繁踩坑点。

### 4.7 个体相等与不等
基于前面公理：John属于Man，Mary属于Woman，Man和Woman不相交，可以推导出John和Mary不是同一个个体。但是如果新增另一个男性个体Bill，现有公理**无法保证John和Bill不是同一个个体**。
> OWL**不做唯一名称假设(unique names assumption)**：不同IRI名字，并不自动代表是不同个体。该特性非常适配语义Web场景：不同组织在不同时间，有可能给同一个现实事物分配不同标识符。

如果想要声明John和Bill不是同一个个体，必须显式写出DifferentIndividuals。

> 函数式语法
```
 DifferentIndividuals( :John :Bill )
```
> RDF/XML语法
```
 <rdf:Description rdf:about="John">
 <owl:differentFrom rdf:resource="Bill" />
 </rdf:Description>
```
> Turtle语法
```
 :John owl:differentFrom :Bill .
```
> 曼彻斯特语法
```
 Individual: John 
 DifferentFrom: Bill 
```
> OWL/XML语法
```
 <DifferentIndividuals>
 <NamedIndividual IRI="John" />
 <NamedIndividual IRI="Bill" />
 </DifferentIndividuals>
```

同样，可以声明两个名字指向同一个现实个体，例如James和Jim指代同一个人：

> 函数式语法
```
 SameIndividual( :James :Jim )
```
> RDF/XML语法
```
 <rdf:Description rdf:about="James">
 <owl:sameAs rdf:resource="Jim" />
 </rdf:Description>
```
> Turtle语法
```
 :James owl:sameAs :Jim.
```
> 曼彻斯特语法
```
 Individual: James
 SameAs: Jim
```
> OWL/XML语法
```
 <SameIndividual>
 <NamedIndividual IRI="James" />
 <NamedIndividual IRI="Jim" />
 </SameIndividual>
```

推理机得到SameIndividual，会把所有关于James的事实全部迁移到Jim，反之亦然。

### 4.8 数据类型
前面描述个体要么直接归类，要么和别的个体建立对象属性。现实建模还经常需要给个体附加数据字面量：出生日期、年龄、邮箱等。OWL提供**数据属性(datatype properties)**：将个体关联到数据字面量，可复用大量XML Schema数据类型。

示例：John年龄是51。

> 函数式语法
```
 DataPropertyAssertion( :hasAge :John "51"^^xsd:integer )
```
> RDF/XML语法
```
 <Person rdf:about="John">
 <hasAge rdf:datatype="http://www.w3.org/2001/XMLSchema#integer">51</hasAge>
 </Person>
```
> Turtle语法
```
 :John :hasAge 51 .
```
> 曼彻斯特语法
```
 Individual: John
 Facts: hasAge "51"^^xsd:integer
```
> OWL/XML语法
```
 <DataPropertyAssertion>
 <DataProperty IRI="hasAge" />
 <NamedIndividual IRI="John" />
 <Literal datatypeIRI="http://www.w3.org/2001/XMLSchema#integer">51</Literal>
 </DataPropertyAssertion>
```

也可以写负数据属性断言：Jack的年龄**不是**53。

> 函数式语法
```
 NegativeDataPropertyAssertion( :hasAge :Jack "53"^^xsd:integer )
```
> RDF/XML语法
```
 <owl:NegativePropertyAssertion>
 <owl:sourceIndividual rdf:resource="Jack" />
 <owl:assertionProperty rdf:resource="hasAge" />
 <owl:targetValue rdf:datatype="http://www.w3.org/2001/XMLSchema#integer">
 53
 </owl:targetValue>
 </owl:NegativePropertyAssertion>
```
> Turtle语法
```
 [] rdf:type owl:NegativePropertyAssertion ;
 owl:sourceIndividual :Jack ;
 owl:assertionProperty :hasAge ;
 owl:targetValue 53 .
```
> 曼彻斯特语法
```
 Individual: Jack
 Facts: not hasAge "53"^^xsd:integer
```
> OWL/XML语法
```
 <NegativeDataPropertyAssertion>
 <DataProperty IRI="hasAge" />
 <NamedIndividual IRI="Jack" />
 <Literal datatypeIRI="http://www.w3.org/2001/XMLSchema#integer">53</Literal>
 </NegativeDataPropertyAssertion>
```

数据属性同样支持定义域、值域。区别在于值域写**数据类型**，而不是类。示例：hasAge定义域是人，值域是非负整数。

> 函数式语法
```
 DataPropertyDomain( :hasAge :Person ) 
 DataPropertyRange( :hasAge xsd:nonNegativeInteger ) 
```
> RDF/XML语法
```
 <owl:DatatypeProperty rdf:about="hasAge">
 <rdfs:domain rdf:resource="Person" />
 <rdfs:range rdf:resource="http://www.w3.org/2001/XMLSchema#nonNegativeInteger" />
 </owl:DatatypeProperty>
```
> Turtle语法
```
 :hasAge rdfs:domain :Person ;
 rdfs:range xsd:nonNegativeInteger .
```
> 曼彻斯特语法
```
 DataProperty: hasAge
 Domain: Person
 Range: xsd:nonNegativeInteger
```
> OWL/XML语法
```
 <DataPropertyDomain>
 <DataProperty IRI="hasAge" />
 <Class IRI="Person" />
 </DataPropertyDomain>
 <DataPropertyRange>
 <DataProperty IRI="hasAge" />
 <Datatype IRI="http://www.w3.org/2001/XMLSchema#nonNegativeInteger" />
 </DataPropertyRange>
```

> 再次提醒前面的建模陷阱：hasAge定义域是Person；如果写“Felix是Cat，Felix hasAge 9”，推理机会推出Felix属于Person，很多场景并非本意。定义域/值域是推理规则，不是校验约束。
