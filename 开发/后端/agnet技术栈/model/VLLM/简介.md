# vLLM
**vLLM 是伯克利Sky Computing Lab开源的大模型推理&服务引擎，核心目标：提升LLM在线服务吞吐量、提高显存利用率、降低推理成本**。
> 名字拆解：**v**irtual **L**arge **L**anguage **M**odel，来源于它的核心创新：PagedAttention（分页注意力）。

## ✅ 核心技术（面试高频）
1. **PagedAttention（分页注意力）⭐核心**
传统KV Cache需要**连续显存块**，不同对话序列长短不一，极易产生显存碎片，大量显存被浪费。
vLLM借鉴操作系统**虚拟内存/页表**思想：
- 把KV Cache切为固定大小的**block（页）**
- 一个对话的KV块不需要物理上连续；用页表记录逻辑块→GPU物理块映射
- 支持块复用、按需分配、释放，显存碎片大幅减少，显存利用率显著提升。

2. **Continuous Batching（连续批处理 / 动态批）**
普通静态batch：攒够一批请求，统一跑完；短请求要等长请求，GPU空闲。
连续批：**请求随时加入，生成完成一条就立刻补新请求进batch**，而不是等整批全部结束，GPU利用率拉高，吞吐大幅上涨。
> 搭配 Chunked Prefill（分块预填）进一步优化长上下文场景。

3. 配套优化
- 高度优化CUDA kernel；支持量化：AWQ / GPTQ / FP8
- 分布式推理：张量并行、流水线并行；支持多LoRA、前缀缓存prefix caching、推测解码speculative decoding

## ✅ 能力与生态
- 原生兼容HuggingFace模型，一行命令启动**兼容OpenAI协议的API服务**，直接对接LangChain、RAG等应用，几乎不用改上层代码
- 支持流式输出stream，适合聊天接口
- 硬件：NVIDIA GPU、AMD GPU、Intel、TPU等
- 两种用法：离线批量推理；在线API服务（生产最常用）

## ✅ 和同类框架对比（简要）
- vLLM：**通用性强、生态好、上手快**，工业界最普及；长上下文、对话场景首选。
- TensorRT-LLM：NVIDIA专属，极致性能，但生态弱、配置复杂。
- SGLang：新兴，在结构化输出、复杂Agent/多轮调用上有优势。

## ✅ 最简启动示例
```bash
pip install vllm
# 启动OpenAI兼容服务
vllm serve Qwen/Qwen2-7B-Instruct --tensor-parallel-size 1
```
然后就可以用OpenAI SDK访问 `http://localhost:8000/v1`

## ✅ 一句话总结
> vLLM = 以PagedAttention为核心，配合连续批处理，**解决KV Cache显存碎片问题，把GPU打满，用更少显卡承载更多并发对话请求的开源大模型部署引擎**。
