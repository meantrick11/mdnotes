# 模型调用成千上万次的原因及其防护

## 原因

1. 工具颗粒度过细
    比如将read_file改成read_line，一个文件阅读就需要调用上万次read_line

2. 缺少终止条件
    没有设置最大工具调用轮数，模型反复调用同一个工具，陷入循环

3. prompt约束不足
    模型不回合并任务，遇到小人物久调用工具，不做批量处理

4. 模型幻觉
    模型编造不存在的工具调用，无限调用。

## 防护/处理策略

1. 限流+熔断
    - 全局最大轮数限制
    - 单轮最大tool_calls
    - 超时熔断

2. 工具粒度重构
    - 避免过细颗粒的原子工具


3. 任务规划层
    - 先评估任务：预估需要多少次工具调用；
    - 如果预估数量很大，优先合并成批量调用；
    - 判断是否需要分页，而不是逐条调用；
    - 必要时主动拒绝不合理的海量任务。

4. 后端异步 + 队列（当确实需要大量调用时）
如果业务真的需要执行大量函数（比如批量处理几百上千个文件）：
    - Agent不阻塞等待全部执行完成；
    - 提交任务到异步任务队列（Celery/RabbitMQ）；
    - Agent 只提交任务，任务后台慢慢跑；
    - 模型拿到任务 ID，告诉用户任务后台执行，后续再查询结果。
