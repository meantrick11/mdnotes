# 层级总览

| 层级 | 通俗理解 / 解决的问题 | 能回退什么 | 典型技术 / 框架 | 主要边界 |
|---|---|---|---|---|
| **L1 Agent 状态级** | **把 AI 的“脑子”倒回去** | messages、plan、state、tool 调用状态、执行分支 | **LangGraph Checkpointer**、Agent state persistence | 真实文件、程序、系统环境完全不受影响 |
| **L2 工作区 / 代码级** | **把项目代码倒回去** | Agent 创建、修改、删除的代码/文档文件 | **Git、Shadow Git、Cursor Checkpoints**、patch/diff | 已启动进程、安装依赖、系统配置不会恢复 |
| **L3 文件系统级** | **把 Agent 所在“硬盘”倒回去** | 项目文件、依赖文件、配置、目录、`pip install` 等落盘结果 | **OverlayFS、Docker writable layer、COW filesystem、Sandbox filesystem snapshot** | 通常不恢复 RAM、运行中的进程执行状态 |
| **L4 执行环境级** | **把整台虚拟电脑倒回去** | filesystem + memory + process/runtime state，部分方案支持 fork | **VM Snapshot、Daytona VM、Firecracker、CRIU、部分 Modal Sandbox Snapshot** | Agent 环境之外的远程服务仍然不会恢复 |
| **L5 外部业务状态级** | **把 Agent 对其他系统造成的影响尽量倒回去** | 数据库事务、订单状态、云资源、部分 API 操作 | **DB Transaction、WAL、Saga、Event Sourcing、Compensating Transaction** | 邮件、付款、现实世界动作很多无法真正撤销 |
| **L6 统一 Runtime 级** | **一次“回到某条消息”，所有可控状态一起恢复** | Agent state + workspace + filesystem + process + sandbox + 可补偿外部状态 | **Checkpoint Manager + Sandbox/VM + LangGraph + Transaction/Compensation** | 目前更多是系统架构组合，没有一个框架天然解决全部问题 |


## 当前现状

由于想要对整个系统进行回退，但是查看市面上大多数的agent的操作都是：
1. 会话级别回退->只是重新生成
2. 会话级别+文件写入级别->通过git进行文件控制

剩下的几乎没有回退功能，比如当前会话当前消息回退之后，当前消息产生的系统进行还在运行(也就是没有办法真正从操作系统层面进行回退)，更有胜者只能回退最近的一条消息，减少状态的管理。

**局限于工作区的文件操作+agent状态级回退+命令行操作、沙箱状态回退等等，而不能够接触整个执行环境(电脑)的runtime，就算扩展至电脑，那么如果操作的支付完成等等外部世界，也不能够及时回退，已经是既定的事实(可以间接沟通，比如尝试退款等等，而不是直接回退，agent机制也是，同样尝试执行命令进行操作回退)**

| 类型 | 主流支持情况 |
|---|---|
| Agent state / conversation | ✅ 常见 |
| 文件修改 | ✅ 常见 |
| Shell 命令造成的系统变化 | ❌ 通常不自动回退 |
| 已启动进程 | ❌ 通常不自动 kill/恢复 |
| pip/apt 安装 | ❌ 通常不自动恢复 |
| MCP / API 外部操作 | ❌ |
| 远程数据库 | ❌ |
| 完整 OS 状态 | ❌ |

## 展望

当前多数 Agent 的状态管理仍停留在会话状态与工作区文件状态层面。真正的系统级 rollback，需要把 Agent 的执行环境也纳入 Runtime，通过 VM / sandbox snapshot、memory checkpoint、filesystem versioning 等方式，将消息、Agent state 与环境状态绑定到统一 checkpoint。
进一步发展后，Agent Runtime 可以从“调用电脑工具”升级为“管理整个数字执行环境”：负责状态、进程、权限、资源、分支、回退与外部副作用。这可以被视为 Agentic OS 的一个核心方向——用户面对的不再一定是应用和文件，而是意图与最终状态，传统应用逐渐成为 Agent 背后的能力提供者。
但 OS snapshot 只能控制本地数字环境，邮件、云服务、远程数据库、支付等外部副作用仍需要 transaction、compensation、approval 等机制处理，因此真正的 Agentic OS 本质上是“多状态域的 Runtime + 事务/副作用管理系统”，而不是简单的整机快照。
