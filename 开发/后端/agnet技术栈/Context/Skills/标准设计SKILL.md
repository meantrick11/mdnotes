| 主线 | 核心问题 |
|---|---|
| Skill 工程 | 怎么设计 Skill、怎么写 Skill、怎么测试 Skill |
| 知识工程 | Agent 怎么调用知识库、知识库怎样设计才方便 Agent 调用 |

四个学习模块应该这样展开。

### 1. 怎么设计 Skill

这部分不是先学 Markdown 语法，而是学习如何把一项工作抽象成可复用流程。

需要掌握：

- 什么情况下应该设计 Skill
- 一个大任务是否需要拆成多个 Skill
- Skill 的触发条件和排除条件
- Skill 需要什么输入
- Agent 应执行哪些步骤
- 哪些步骤需要调用工具或知识库
- 信息不足时怎样处理
- 什么样的输出才算完成
- 怎样判断 Skill 设计得好不好

设计 Skill 时，先填写这张“任务卡”：

```text
Skill 名称：
解决的用户任务：
适用场景：
不适用场景：
输入材料：
执行步骤：
需要调用的知识：
需要调用的工具：
禁止自行推断的内容：
输出结果：
完成标准：
```

Skill 的本质是：**告诉 Agent 遇到某类任务时应该怎样工作。**

### 2. 怎么写 Skill

写 Skill 才进入文件层面。标准结构一般是：

```text
data-asset-skill/
├── SKILL.md
├── references/
├── scripts/
├── assets/
└── agents/
    └── openai.yaml
```

各部分职责是：

- `SKILL.md`：触发条件、工作流程、判断规则和完成标准。
- `references/`：完成任务可能用到的规则、标准、数据结构说明。
- `scripts/`：需要稳定、重复执行的计算或文件处理程序。
- `assets/`：报告、表格等输出模板。
- `agents/openai.yaml`：界面信息、调用策略和依赖配置。

其中最重要的是 `name` 和 `description`。Agent 首先只看到名称和描述，再判断要不要加载完整 Skill，所以描述必须同时写清楚“做什么”和“什么时候使用”。[OpenAI Skills 文档](https://developers.openai.com/api/docs/guides/tools-skills)

一个最小版本可以是：

```markdown
---
name: data-asset-inventory
description: 盘点组织的数据资源，识别材料缺口，并生成结构化数据资产候选清单。适用于用户提供业务系统、数据库、数据表或数据目录材料的场景。
---

根据用户提供的材料盘点数据资源。

1. 确认组织、部门和业务范围。
2. 检查材料是否包含系统、数据库、数据表、责任部门和更新频率。
3. 缺少关键信息时提出问题，不自行编造。
4. 查询数据资产知识库中的术语和盘点规则。
5. 输出资产候选清单、材料缺口和待确认事项。

每项判断都要标明依据。无法确认的信息标记为“待确认”。
```

### 3. 怎么让 Agent 调用知识库

这部分要学习完整的 RAG 或检索链路：

```text
用户问题
   ↓
Agent 判断是否需要查知识库
   ↓
生成检索词或检索条件
   ↓
调用 File Search、MCP、API 或数据库工具
   ↓
返回相关知识片段
   ↓
筛选和综合
   ↓
结合来源生成答案
```

你需要重点掌握四个问题：

1. **什么时候查**  
   Skill 中要规定哪些判断必须检索知识库，不能仅靠模型记忆。

2. **查什么**  
   Agent 应根据任务生成检索词、同义词、业务对象和过滤条件。

3. **怎么查**  
   根据数据类型选择调用方式：
   - 文档知识：关键词检索、语义检索、混合检索。
   - 结构化数据：SQL、API。
   - 企业业务系统：MCP 或专用工具。
   - 实时信息：业务接口或联网查询。

4. **查完怎么用**  
   要求 Agent：
   - 引用来源；
   - 区分原文事实和自己的推断；
   - 多个来源冲突时说明冲突；
   - 没检索到依据时不编造。

OpenAI 的 File Search 可以让 Agent 对已上传文件进行语义和关键词检索；文档进入向量库后会被切分、向量化并建立索引，再供 Agent 查询。[File Search 文档](https://developers.openai.com/api/docs/guides/tools-file-search) [Retrieval 文档](https://developers.openai.com/api/docs/guides/retrieval)


### 4. 怎么设计知识库，让 Agent 更好调用

这才是你说的“了解当前知识库怎样、他们搭建的数据库怎样”的落点。

学习重点包括：

- 文档如何分类
- 知识应该切多细
- 每条知识需要哪些元数据
- 如何处理同义词和业务术语
- 如何记录来源、版本和适用范围
- 不同行业和客户的知识如何隔离
- 过期内容如何更新
- 冲突知识如何处理
- 检索结果如何评估

例如，不能只是把几十份 PDF 全扔进去。数据资产知识条目至少应包含：

```yaml
title: 数据资源定义
knowledge_type: 术语定义
industry: 通用
source: 某标准名称
source_level: 国家标准
version: 2025
effective_date: 2025-06-01
applicable_scope: 企业数据资源盘点
keywords:
  - 数据资源
  - 数据资产
  - 数据目录
status: 有效
content: ...
```

这样 Agent 才能根据行业、版本、适用范围和权威等级过滤，而不是仅凭文本相似度选择内容。

必须先分清四个对象：

| 对象 | 作用 |
|---|---|
| Agent | 理解任务、作出判断并组织执行 |
| Skill | 告诉 Agent 这类任务应该怎么做 |
| 知识库 | 为判断提供术语、标准、规则和案例 |
| 工具 | 让 Agent 能真正检索知识库或访问数据库 |

一句话概括就是：

> Skill 管“怎么做”，知识库管“依据什么做”，工具管“怎样取得信息”，Agent 把它们组合起来完成任务。

你的学习顺序可以安排为：

1. 分析三个标准 Skill，理解结构、触发方式和工作流。
2. 手写一个不接知识库的最小 Skill。
3. 建一个只有十几条知识的小型知识库。
4. 让 Agent 能检索这个知识库并引用依据。
5. 把知识库调用写进 Skill。
6. 准备正确问题、错误问题、信息不足问题和不应触发的问题进行测试。
7. 最后再把主题替换为“数据资产服务”。

FDE 案例也应该按照这四个维度拆：

- 它设计了什么 Skill？
- Skill 怎样描述工作流程？
- Agent 通过什么工具访问知识？
- 知识库为什么能支持 Agent 完成任务？
