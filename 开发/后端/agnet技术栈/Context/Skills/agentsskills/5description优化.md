# Agent Skills 优化技能描述笔记
来源：https://agentskills.io/skill‑creation/optimizing‑descriptions

## 触发机制原理
`description` 是智能体判断是否加载技能的核心依据。
- 依托渐进式披露机制：系统启动时仅读取所有技能的`name`和`description`，任务匹配成功后，才完整加载 `SKILL.md`。
- 注意：简单任务即便描述匹配也可能不触发。智能体原生就能处理的请求不会调用技能；技能更适合陌生API、领域工作流、特殊格式这类需要专业知识的任务。
- 描述写得过窄：需要时不会触发；写得过宽：出现不该触发的误报。

## 编写优质描述的原则
1. **祈使句式**：告诉智能体「什么场景下要使用此技能」，而不是单纯陈述技能功能。
2. **聚焦用户意图**：描述用户想要达成的目标，不要写技能内部实现细节。
3. **覆盖隐式场景**：写明即使用户没有明确说出领域关键词，也可启用该技能。
4. **控制长度**，最大不超过规范限制的1024字符。

## 设计触发测试用例
准备约20条测试提问，10条应触发、10条不应触发，每条标注`should_trigger`。
1. **应触发用例**
    - 句式混合正式、口语、缩写、少量笔误；
    - 一部分明确提及领域名词，一部分只描述业务诉求；
    - 兼顾简短指令、带完整上下文的长指令，覆盖简单与多步骤任务；
    - 重点准备关联关系不直观的提问，这才是检验描述好坏的关键。
2. **不应触发用例**
    - 优先使用**近似误报用例**：关键词部分重合，但实际任务不同；不要用完全无关的问题，无法起到测试效果。
3. 贴近真实输入：加入文件路径、业务背景、字段名称、口语表达。

## 开展触发测试
- 判断标准：智能体加载完整`SKILL.md`才算成功触发，可查看执行日志、工具调用记录。
- 模型具有随机性，每条用例建议运行3次，计算触发率，默认阈值设为0.5。
- 可以编写脚本实现批量自动化测试。

## 避免过拟合：训练集/验证集拆分
- **训练集（约60%）**：用来定位问题、修改描述文案。
- **验证集（约40%）**：仅用来检验泛化效果，**不能用验证集结果指导修改描述**。
- 两套数据集都要均衡分配正负用例，固定划分，迭代过程不重新打乱。

## 标准化优化循环
1. 分别在训练集、验证集上评估当前描述。
2. 定位训练集失败案例：该触发未触发、不该触发却误触发。**只参考训练集的问题**。
3. 修改描述：
    - 漏触发：适度扩大适用范围，补充场景；
    - 误触发：明确边界，写明不适用的场景；
    - 不要硬编码测试用例的特定关键词，防止过拟合；多次微调无效，直接更换整套描述；保证字符不超1024。
4. 重复评估‑修改，一般迭代5轮就足够。
5. 选取**验证集通过率最高**的版本，不一定是最后一次迭代产物，后期迭代容易出现过拟合。

## 落地验证
1. 更新`SKILL.md`的description字段，校验字符长度。
2. 使用一批完全未参与优化的全新测试用例做最终校验。

> 示例对比
> 较差：`Process CSV files.`
> 优化后：写明可做统计、衍生列、绘图、脏数据清洗；覆盖CSV、TSV、Excel，说明即使用户没有明确提到关键词，也可启用。
