# Agent Skills 规范笔记
来源：https://agentskills.io/specification

## 目录结构
技能包为文件夹，**必须包含 `SKILL.md`**：
- `SKILL.md`：必填，存放元数据和任务指令
- `scripts/`：可选，放置可执行代码
- `references/`：可选，放置参考文档
- `assets/`：可选，放置模板、静态资源
- 可自定义增加其他任意文件、子目录

## SKILL.md 文件格式
文件分为两部分：YAML前置元数据 + Markdown正文。

### 前置元数据
|字段|是否必填|约束说明|
|---|---|---|
|`name`|是|最多64字符；仅小写字母、数字、连字符；不能首尾是连字符、不能连续连字符；必须和外层文件夹同名|
|`description`|是|最多1024字符，不能为空；描述技能功能与适用场景，包含关键词方便AI匹配任务|
|`license`|否|许可证名称，或指向包内许可证文件|
|`compatibility`|否|最多500字符；写明环境依赖：适配产品、系统包、网络权限等，多数技能无需填写|
|`metadata`|否|字符串键值对，存放自定义扩展信息|
|`allowed‑tools`|否|空格分隔字符串，预授权可调用工具；实验性功能，各智能体实现支持程度不一|

> 最简配置仅需填写 `name`、`description`，其余字段按需追加。

### 正文内容
元数据后的Markdown正文，编写技能执行指令，格式无强制限制。
建议包含：分步操作指引、输入输出示例、常见边界情况。
> 技能激活会完整加载该文件；内容过长时，建议把详情拆分到外部引用文件。

```
---
name:
description:
---

这个 Skill 要帮助 Agent 完成什么。

# When to use

典型使用场景。

# Inputs

需要哪些输入。

# Workflow

1.
2.
3.
4.

# Decision rules

如果 A → 怎么做
如果 B → 怎么做

# References

什么时候读哪个 reference。

# Scripts

什么时候调用哪个 script。

# Output

最终产物结构。

# Validation

怎么检查结果。

# Gotchas

Agent 常犯错误。
```

## 可选子目录约定
为推荐的目录组织规范，全部为非强制：
### scripts/
存放脚本代码。脚本尽量独立，写明依赖，完善错误提示，处理边界；支持语言取决于智能体，常见Python、Bash、JavaScript。

### references/
存放补充参考文档，智能体按需读取。可放技术说明、表单模板、领域文档；单个文件尽量精简，减少上下文占用。

### assets/
存放静态资源：文档/配置模板、图表、数据表、结构定义文件。

## 渐进式披露加载机制
智能体分阶段加载技能，任务需要时才读取更多细节：
1. **元数据**：系统启动，读取全部技能的名称、描述，数据量很小
2. **指令**：技能被激活，完整读取SKILL.md正文，建议控制在5000token以内
3. **资源**：scripts/references/assets下的文件，仅在实际需要才加载

> 建议主文件SKILL.md控制在500行以内，把详细资料迁移到外部文件。

## 文件引用规则
在SKILL.md中引用包内其他文件，使用**相对于技能包根目录**的相对路径。
引用尽量保持单层深度，避免多层嵌套引用链。

## 技能校验
使用工具校验技能包：
```
skills-ref validate ./my-skill
```
用于校验SKILL.md元数据合法性、检查命名规范。
