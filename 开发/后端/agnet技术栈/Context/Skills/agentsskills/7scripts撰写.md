# Agent Skills 技能脚本使用笔记
来源：https://agentskills.io/skill‑creation/using‑scripts

## 一次性命令
无需放到`scripts/`目录，直接写在SKILL.md指令调用外部工具，可用工具：uvx、pipx、npx、bunx、deno run、go run。
1. 锁定工具版本，保证跨环境行为一致；
2. 环境依赖写在文档或`compatibility`元字段；
3. 命令逻辑复杂时，不要使用一次性命令，改为封装到`scripts`脚本。

## 在SKILL.md引用打包脚本
1. 路径规则：统一使用**相对于技能包根目录的相对路径，禁止绝对路径**；`references`目录下文档引用脚本同样遵循该规则。
2. 在SKILL.md中列出脚本清单，告知智能体脚本存在；
3. 指令中给出完整运行示例。

## 自包含脚本
脚本内部直接声明依赖，不需要额外配置文件。
- Python：遵循PEP723，脚本内TOML块声明依赖，使用`uv run`运行；支持锁定依赖版本、Python版本，可生成lock文件。
- Deno：通过`npm:`/`jsr:`导入包，直接指定版本。
- Bun：import语句直接写包版本，无需`package.json`。
- Ruby：使用`bundler‑inline`，脚本内声明gem依赖。

## 面向AI智能体的脚本设计核心规范
1. **禁止交互式输入**：智能体运行在非交互Shell，无法响应弹窗、键盘确认；全部入参只能来自命令行参数、环境变量、标准输入，否则脚本会永久挂起。
2. 提供`--help`帮助输出：写明功能、参数、调用示例，输出尽量精简，这是智能体获取脚本接口的主要方式。
3. 编写明确的错误提示：说明故障、预期值、修复建议，避免笼统的“输入无效”。
4. 使用结构化输出：优先JSON、CSV；业务数据输出到stdout，警告、诊断日志输出stderr，做到业务数据与日志分离，便于程序解析。

## 额外设计考量
- **幂等性**：智能体会重试命令，优先实现“不存在才创建”，避免重复执行直接报错。
- 输入校验：拒绝模糊输入，尽量使用枚举限定合法取值。
- 高危操作支持`--dry‑run`试运行，预览变更效果。
- 差异化退出码：不同故障返回不同退出码，并在帮助文档说明含义。
- 破坏性操作增加显式确认参数，例如`--confirm`、`--force`。
- 管控输出大小：工具会截断超长输出；大内容默认返回摘要，支持分页；或者强制通过`--output`输出至文件。
