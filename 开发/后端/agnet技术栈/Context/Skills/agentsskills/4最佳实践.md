# Agent Skills 技能编写最佳实践笔记
来源：https://agentskills.io/skill‑creation/best‑practices

## 从真实业务经验出发
不要直接让大模型凭空生成技能，容易产出空洞笼统的流程。技能需要扎根真实领域知识，有两种实现途径：
1. **从实际任务提炼**：和AI协作完成真实业务，记录成功步骤、需要修正的问题、输入输出格式、项目特有约束，再封装成可复用技能。
2. **基于现有项目资料合成**：使用内部手册、运维手册、API文档、评审记录、故障案例等一手材料，不要只依赖网上通用的通用最佳实践。

## 通过实际运行迭代优化
技能初稿通常不够完善。使用真实任务运行技能，完整分析全部执行结果，不只关注报错。阅读执行日志，排查误触发、信息遗漏、冗余指令。一轮「执行‑修改」就可以明显提升质量；复杂业务场景需要多轮迭代。可参考质量评估文档开展系统化测试。

## 合理消耗上下文资源
技能激活后，完整的`SKILL.md`会载入上下文窗口，会占用对话可用token。
1. **只补充AI不知道的内容**：删掉常识科普，只写项目约定、领域流程、特殊边界、指定工具与API。判断标准：缺少这条指令AI是否会出错，不出错就删除。
2. **高内聚设计技能单元**：类似函数设计，封装一套完整、可组合的工作。粒度过细会同时加载多个技能，引发指令冲突；粒度过宽会导致难以精准触发。
3. **保持适度详细**：精简步骤搭配示例，效果优于堆砌全部边界场景的超长文档。
4. **大型技能用好渐进式披露**：`SKILL.md`建议控制在500行、5000token以内。大量参考资料放到`references`目录，写明**什么条件下才读取外部文件**，不要笼统写“查看参考文档”。

## 校准指令管控力度
根据任务的脆弱程度，调整指令的严格程度：
1. **指令粒度匹配任务脆弱度**：允许多种实现的任务，给予AI自由度，重点说明业务目的；操作容易出错、要求结果严格一致，则给出强制明确步骤。大部分技能二者混合使用。
2. **给出默认方案，避免罗列一堆等价选项**：指定首选工具或实现方案，仅简短补充备选方案。
3. **优先写通用处理流程，不要写死单条实例**：教会AI解决一类问题的通用方法，而不是只适配某一条特定查询。

## 高效指令常用编写模式（按需选用）
1. **踩坑注意事项**：记录业务环境下反常识、高频踩坑点，拒绝空泛的通用建议。AI实际踩过的错误直接补充到此，建议放在`SKILL.md`主体。
2. **输出模板**：需要固定输出格式，直接提供模板；篇幅较长的模板存放在`assets`目录做引用。
3. **多步骤检查清单**：使用清单防止AI跳过步骤，适合步骤存在依赖的工作流。
4. **校验循环**：完成工作后执行校验，发现问题就修复，校验通过后才允许继续；校验可以运行脚本，也可以对照参考文档。
5. **计划‑校验‑执行**：高危、批量操作，先生成执行计划，校验计划无误之后，才执行真实操作。
6. **打包可复用脚本**：观察执行日志，如果AI反复重复实现同一套逻辑，把逻辑封装为脚本放入`scripts`目录。

## 后续优化方向
完成基础技能后，可参考两份材料进一步打磨：
1. 评估技能输出质量：搭建测试用例，系统化打分迭代
2. 优化技能描述：调试`description`字段，保障正确触发，减少误触发
