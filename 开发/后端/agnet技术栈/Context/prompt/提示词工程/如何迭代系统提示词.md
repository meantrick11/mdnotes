# 提示词工程概述

Context Engineering 侧重于给模型什么信息 / 内容，Prompt Engineering 侧重于怎么给，如何组织等。
上下文包含对话历史、系统提示词、工具调用返回结果、长短期记忆、RAG 检索出来的片段等等；判断哪些信息必须携带、哪些需要摘要压缩、哪些直接全量送入模型，管理整套信息的取舍与生命周期，这就是上下文工程的范畴。
提示词工程，是对筛选完成的上下文素材做编排、约束与文案优化，最终组装成输入给 LLM 的完整文本，目标是让 Agent/AI 系统的输出更贴合业务目标。凡是需要定制提示文案的环节都属于提示词工程：系统提示词、工具定义提示词、MCP 提示词、当前轮用户提示词，不同类型提示词各自拥有独立的生命周期。
总结来说：上下文工程管理的是信息的生命周期（给什么？），提示词工程管理的是如何优化提示词，以更优的方式引导模型完成用户的任务（怎么约束，怎么给？）

## 2.0 什么时候进行提示词工程

本指南聚焦于可通过提示工程控制的成功标准。并非所有成功标准或失败评估都能通过提示工程得到最佳解决。例如，有时选择不同的模型就能更轻松地降低延迟和成本。

**编者认为，只要需要和提示词相关的地方，都可以考虑是否需要提示词工程以优化提示词，以让LLM更好地完成任务，比如系统提示词，工具定义，MCP提示词，当前轮提示词(绝大多数情况下不用每轮都考虑优化当前轮提示词，一个是成本，另外一个也太过复杂)**

## 3.0 如何进行提示词工程

### 3.1 通用原则

#### 清晰直接

尽可能保持你的提示词足够清晰，避免模棱两可的语言描述，比如让AI写项目，但是不能直接将项目书发给它(除非项目书十分全面)，而是自己拆成小模块、小链路，每个链路涉及什么数据流/状态转换，可以不需要精确到具体函数的实现，但是需要对于让AI做的任务描述的很清楚，否则模型很容易天花乱坠地“瞎回答”


#### 提示词四要素

1. 上下文(Context)

对于你具体的任务，任务的背景信息/动机是什么？让模型获得更全面的上下文，比如项目是否需要满足高并发等等具体信息，进而让模型更好地理解你的任务，进行高质量的回复。

在很多其他教程中，可能会有给模型指定角色，比如"你是一个从业10年的后端开发工程师...",但是读者任务，指定角色也是属于给定上下文的一种，只不过是角色信息，所以没有单开一个要素

2. 任务(Task)

提示还是为了让模型完成某项特定的任务，无论是长对话/短对话(当前轮)，对于其任务的描述必不可少

3. 限制条件(Constrain)

对于给定任务，需要模型做的边界条件在哪里？是否可以任意改动项目代码？还是只追踪某一部分？哪些能做？哪些不能做？这些都要写清楚，才不会出现模型生成的内容天马行空

4. 格式化输出/具体示例(Examples)

对于特定任务，可能已经有固定的生成模板，那么就需要在给定提示词中增加任务完成示例，比如论文分析，需要让模型返回

```text
论文名:...
论文作者:...
解决问题:...
主要方法:...
等等
```

给定具体输出示例之后，模型才能更好地输出你想要的格式和内容。添加示例的时候，尤其是在构建系统提示词的时候，需要保持**相关性，贴合实际使用场景**，**多样性，覆盖边缘情况，多种使用边界**，**结构化输入输出，大多数只规定结构化输出，而模型大多能够理解你的意图，即使不结构化输入**。


#### 其他可用技巧

1. 使用XML标签进行构建提示词

整个方法Anthropic推荐使用，但是现在的模型都能够很好地理解用户的输入即使不适用XML标签构建提示词，所以不是提示词工程的主要因素，与此同时OpenAI也同样推荐将指令放到提示词开头，并通过一些标志来分割指令和上下文，比如：

```text
Summarize the text below as a bullet point list of the most important points.

Text: """
{text input here}
"""
```

2. 长上下文提示
    - 将长格式数据放在输入起始位置或者末尾，由于transformer的注意力双端特性，即模型对长输入的两头的注意力更加，表现更好
    - 使用XML标签包裹文档内容和元数据
    - 要求引用回答，让模型根据文档内容进行回答，聚焦具体的文档内容

3. 输出格式化

在四要素中也有提到，应该注重对于模型的输出限制，告诉模型该做什么？不该做什么？输出怎样的格式才是你具体所想的任务完成情况,比如具体的篇幅，预期，角度，风格等等，一般可以通过示例进行补充说明

应该侧重告诉模型**该做什么?怎么做？而不是不该做什么?**

```text
The following is a conversation between an Agent and a Customer. The agent will attempt to diagnose the problem and suggest a solution, whilst refraining from asking any questions related to PII. Instead of asking for PII, such as username or password, refer the user to the help article www.samplewebsite.com/help/faq

Customer: I can’t log in to my account.
Agent:
```

4. 零样本(Zero-shot)->少量样本学习(Few-shot)->微调(Fine-tune)

如果提示词工程的零样本学习(不提供示例)，到少量样本学习(少量学习)都无效，那么才考虑对模型进行微调，后者成本也更高。
