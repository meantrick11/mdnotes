## 1. Boolean 布尔型
- 取值：`true` / `false` / `NULL`
- 适用：开关状态，是否启用、是否删除。
```sql
is_active boolean default false;
```

## 2. 字符串：CHAR / VARCHAR / TEXT
1. `CHAR(n)`：定长，不足n补空格，极少用。
2. `VARCHAR(n)`：变长，最多n个字符，普通短文本（用户名、邮箱）。
3. `TEXT`：**无长度上限**，大段文本、描述。
> Postgres中 `VARCHAR` 和 `TEXT` 性能几乎一样，没有MySQL的差异。

## 3. 数字类型
- `Integer`：int，4字节，范围 ±21亿，普通整数。
- `BIGINT`：8字节，大整数，主键id优先用。
- `SERIAL / BIGSERIAL`：**伪类型**，自动创建自增序列。`BIGSERIAL`最常用。
> ⚠️新版推荐：`IDENTITY` 替代 serial。
- `NUMERIC(精度,小数位)`：**高精度十进制，用于金额、财务，无浮点误差**。
- `REAL`（4字节）、`DOUBLE PRECISION`（8字节）：浮点数，**不要存钱，会精度丢失**，适合科学计算。

> ✅金钱一定用 `NUMERIC`，不要用double。

## 4. 时间日期
- `DATE`：仅日期 `2026‑08‑23`
- `TIME`：仅时间 `14:30:00`
- `TIMESTAMP`：日期+时间；还有 `TIMESTAMPTZ` **带时区时间戳（强烈推荐业务使用）**
- `INTERVAL`：时间间隔，例如 `2 hours`，用来计算时间差。

```sql
create_at timestamptz default now();
```

## 5. UUID
128位全局唯一ID，前面讲过，做主键。
```sql
id UUID PRIMARY KEY DEFAULT gen_random_uuid()
```

## 6. JSON / JSONB
- `JSON`：原样存储文本，查询慢。
- `JSONB`：**二进制JSON，支持索引，业务首选**。适合存动态扩展字段。
```sql
extra JSONB;
```

## 7. HSTORE
键‑值存储，类似map，只存字符串键值，现在大多用JSONB替代。

## 8. Array 数组
Postgres特色，可以直接存数组：
```sql
tags text[]; --可以存 {'go','python'}
```

## 9. Enum 枚举
预定义固定可选值，比如订单状态：`pending`、`paid`、`cancelled`，限制只能填规定值。

## 10. 用户自定义类型 User‑defined Data Types
自己写复合类型，业务一般很少用。

## 📝业务开发选型速查表（面试直接背）
|业务场景|推荐类型|避坑|
|---|---|---|
|自增主键ID|`BIGSERIAL` / `BIGINT GENERATED AS IDENTITY`|不要用int，容易溢出|
|分布式主键|`UUID`|优先v7，v4索引性能差|
|用户名、邮箱|`VARCHAR(255)`||
|长文本、文章内容|`TEXT`|不要刻意限制长度|
|金额、财务|`NUMERIC(12,2)`|❌禁止double/float|
|普通整数数量|`INTEGER`||
|时间（创建、更新）|`TIMESTAMPTZ`|尽量不用不带时区timestamp|
|开关状态|`BOOLEAN`||
|动态不确定字段|`JSONB`|优先jsonb，不要json|
|多选标签|`text[]`数组 / 关联表|简单场景直接数组|
|固定状态集合|`ENUM`|状态会频繁新增就别用enum，改表麻烦|

### 冷门类型（图里出现，但几乎不用）
- XML：现在基本被JSONB淘汰。

### 高频坑点
1. **不要用浮点数存钱**，会出现 `0.1+0.2≠0.3`。
2. 时间戳优先 `timestamptz`，避免时区错乱。
3. `SERIAL`只是语法糖，不是真正数据类型，底层是序列+bigint。
