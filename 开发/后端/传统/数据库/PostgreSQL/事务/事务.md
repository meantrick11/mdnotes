# PostgreSQL Transaction

PG 中所有的 SQL 操作，默认都运行在事务中，没有 “非事务” 的操作。

## 1.0 事务的分类
PG 没有复杂的 “事务类型” 划分，核心分为 显式事务 和 隐式事务，同时支持嵌套事务（伪嵌套）、保存点事务 等高级用法：
### 1.1 隐式事务

PG 默认开启 AUTOCOMMIT=on，单条 SQL 语句会自动被包裹为一个独立事务，执行成功自动提交，失败自动回滚。
- 无需手动写 BEGIN/COMMIT
- 适用场景：简单的单条增删改查


```sql
-- 这就是一个隐式事务：执行成功自动提交，失败自动回滚
UPDATE users SET name='张三' WHERE id=1;
```

### 1.2 显式事务(手动事务)

通过关键字手动开启、提交、回滚事务，**用于多条 SQL 绑定为一个整体。**核心关键字：
- BEGIN / START TRANSACTION：开启事务
- COMMIT：提交事务（所有操作永久生效）
- ROLLBACK：回滚事务（所有操作全部撤销）,可以配合SAVEPOINT关键字设置回滚点

```sql
-- 开启显式事务
BEGIN;
-- 第一步：扣钱
UPDATE account SET balance = balance - 100 WHERE id=1;
-- 第二步：加钱
UPDATE account SET balance = balance + 100 WHERE id=2;
-- 全部成功则提交
COMMIT;
-- 任意一步失败则回滚
-- ROLLBACK;
```

### 1.3 带保存点的事务（部分回滚）

```sql
BEGIN;
INSERT INTO table1 VALUES(1);
SAVEPOINT sp1; -- 设置保存点
INSERT INTO table1 VALUES(2);
ROLLBACK TO sp1; -- 回滚到保存点，只撤销第二条插入
COMMIT; -- 最终只插入了第一条数据
```

### 1.4 嵌套事务

PG不支持嵌套事务，可以同通过保存点模拟嵌套效果，外层事务控制最终提交/回滚。

## 事务的特性:ACID特性

1. 原子性：事务是最小执行单元要么全部成功，要么全部失败，不会执行一半
**杜绝了扣了钱但没到账的中间态**

2. 一致性：事务执行前后，数据库的约束规则、数据完整性保持不变
**保证数据永远合法，比如余额不能为负**

3. 隔离性：多个并发事务互不干扰，

**解决并发问题(脏读、不可重复读、幻读)**

4. 持久性：事务commit之后，数据永久写入磁盘，断电、当即也不会丢失
**保证数据安全**

## 三、PG 事务的核心作用（重点）

1. 保证数据的正确性（最核心作用）
解决业务逻辑的完整性：
银行转账、订单支付、库存扣减
必须全部成功，不允许部分执行
2. 错误恢复与数据回滚
执行中出现异常（语法错误、数据冲突、程序崩溃），可以直接 ROLLBACK 撤销所有操作，恢复到事务开始前的状态。
3. 并发控制，解决多用户冲突
PG 事务通过隔离级别，解决高并发下的问题：
脏读：读到其他事务未提交的数据
不可重复读：同一事务内两次查询结果不一致
幻读：查询时出现了之前不存在的数据
4. 保证数据持久化，防止数据丢失
提交后的事务，即使数据库崩溃，数据也不会丢失，PG 会通过 WAL（预写日志）自动恢复。
5. 支持部分回滚（保存点）
复杂业务中，不需要因为小错误回滚整个事务，提升执行效率。

## 特殊事务

一些事务本身可能需要开启或提交内部事务比如VACUUM，所有他就必须要求自己是“顶层”事务持有者，就能自由地提交、开始新事务，如果你先手动 BEGIN，那么当前的事务边界已经被你占用了，VACUUM 没有权限在你的事务内部再自己提交一次——PostgreSQL 不支持这种"事务中间偷偷提交"的行为，于是直接在语法/执行层面拒绝：

ERROR:  VACUUM cannot run inside a transaction block

**PostgreSQL 检测到 VACUUM 这类命令必须自己是顶层事务（因为它需要自主控制提交时机、分段提交），而当前会话已经处于一个用户手动开启的事务块中（顶层名额已被占用），且 PostgreSQL 又不支持真正独立提交的子事务/嵌套事务，所以直接拒绝执行，报错提示 "cannot run inside a transaction block"。**


有些操作本身就要求自己是顶层事务（PostgreSQL识别到之后就算是单个操作也不会在外边再添加begin&commit），如果再手动,那么顶层事务就变成了手动设定的那个，VACUUM这类命令就不再是顶层了，PostgreSQL不支持事务嵌套，所以会报错。
