# 路径参数

**路径参数+数据校验**

## 路径参数

可以使用Python的格式化字符串相同的语法来声明路径"参数"&"变量"。比如:

```python
from fastapi import FastAPI

app = FastAPI()

@app.get("/items/{item_id}")
async def read_item(item_id):
    return {"item_id":item_id}
```
参数路径item_id将值作为item_id传递函数，这里没有参数类型限制，可以是任何类型。
可以运行`127.0.0.1:8000/item/3`测试

## 带类型的路径参数

可以使用标准的Python类型注释在函数中声明路径参数的类型。


```python
from fastapi import FastAPI

app = FastAPI()

@app.get("/items/{item_id}")
async def read_item(item_id:int):
    return {"item_id":item_id}
```

此例中，item_id只能是int类型，如果你使用`127.0.0.1:8000/item/foo`访问，那么因为类型不匹配，他会返回一个错误信息如下：
```json
{
  "detail": [
    {
      "type": "int_parsing",
      "loc": [
        "path",
        "item_id"
      ],
      "msg": "Input should be a valid integer, unable to parse string as an integer",
      "input": "foo"
    }
  ]
}
```

## 文档

同理，你可以访问`127.0.0.1:8000/docs`或者`127.0.0.1:8000/redoc`进入自动化的交互式API文档

## Pydantic

所有的数据均由Pydantic在后台执行，比如上述的限制item为int类型，如果数据不符合，那么Pydantic会报错。

## 顺序匹配

**FastAPI是从上到下顺序匹配路由，直到匹配到第一条就终止。**所以在创造路由的时候需要注意路由的顺序问题。

```python
from fastapi import FastAPI

app = FastAPI()


@app.get("/users/me")
async def read_user_me():
    return {"user_id": "the current user"}


@app.get("/users/{user_id}")
async def read_user(user_id: str):
    return {"user_id": user_id}
```

如果第二个路由和第一个路由交换位置，那么由于**顺序匹配原则，`/users/me`永远不会被匹配到了。

同理，**开发时不能重复定义同一个路径的操作。**

## 预定义值

### 创建枚举值

创建专属枚举值，专属性更强，如果只是限制一个str，还是太宽泛，有时候某些业务只允许一种或几种访问。
```python
from fastapi import FastAPI


class ModelName(str, Enum):
    alexnet = "alexnet"
    resnet = "resnet"
    lenet = "lenet"


app = FastAPI()


@app.get("/models/{model_name}")
async def get_model(model_name: ModelName):
    if model_name is ModelName.alexnet:
        return {"model_name": model_name, "message": "Deep Learning FTW!"}

    if model_name.value == "lenet":
        return {"model_name": model_name, "message": "LeCNN all the images"}

    return {"model_name": model_name, "message": "Have some residuals"}
```

### 获取枚举值

使用`model_name.value`或者`your_enum_member.value`获取实际值
，如上述代码的定义函数所示。

## 包含路径的参数

假设你有一个路径为 `/files/{file_path}` 的 路径操作。

但你需要 file_path 本身包含一个 路径，例如 `home/johndoe/myfile.txt`。

那么该文件的 URL 将类似于：`/files/home/johndoe/myfile.txt`.

## OpenAPI 支持¶
OpenAPI 不支持声明 路径参数 包含内部 路径 的方式，因为这可能导致难以测试和定义的场景。

尽管如此，你仍然可以在 FastAPI 中实现，使用 Starlette 的内部工具之一。

文档仍然可以正常工作，尽管不会添加任何说明该参数应包含路径的文档。

路径转换器¶
使用 Starlette 的直接选项，你可以通过类似于以下的 URL 声明包含 路径 的 路径参数：


/files/{file_path:path}
在此例中，参数名称为 file_path，最后的部分 :path 告诉它该参数应匹配任何 路径。

因此，你可以这样使用它：


```python

from fastapi import FastAPI

app = FastAPI()


@app.get("/files/{file_path:path}")
async def read_file(file_path: str):
    return {"file_path": file_path}

```

## 回顾

- 路径是可以带参数的
- 路径参数是可以限制类型的
- 路径参数可以使用枚举类型(enum)进行限制
- 路径参数限制是通过fastapi底层的Pydantic进行数据校验的
- API注释以及自动文档

## FastAPI只需要声明一次数据类型定义


Flask、Django DRF 都要**重复声明多遍**
###  一、先看 FastAPI：只声明1次（Pydantic模型）
写一遍 `Item` 类，同时搞定：IDE提示、数据解析、校验、接口文档，无重复
```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

# 【仅声明1次】数据结构、类型、校验规则
class Item(BaseModel):
    name: str
    price: float

@app.post("/item")
def create(item: Item):
    # IDE自动补全 item.name / item.price
    return item
```
只写这一套，四个能力全部自动生成。

---

### 二、Flask（搭配 Marshmallow + Flask-RESTX 做完整接口）：至少声明3次
#### 1. 第一次：数据库模型（SQLAlchemy）
```python
class ItemDB(db.Model):
    name = db.String(100)
    price = db.Float()
```
#### 2. 第二次：序列化校验 Schema（处理解析+验证）
```python
from marshmallow import Schema, fields
class ItemSchema(Schema):
    name = fields.String(required=True)
    price = fields.Float(required=True)
```
#### 3. 第三次：API文档模型（Swagger文档用）
```python
api = Api(app)
item_model = api.model("Item", {
    "name": fields.String,
    "price": fields.Float
})
```
#### 4. 路由里还要手动取值、手动转类型
```python
@app.route("/item", methods=["POST"])
def create():
    json_data = request.get_json()
    # 手动调用schema校验、解析
    data = ItemSchema().load(json_data)
    # 没有IDE自动提示，写 data["name"] 不会自动补全
    return data
```
#### 重复痛点：
`name`、`price` 字段在**数据库、校验Schema、文档Model**三处重复定义；改字段长度/必填规则，三处必须同步修改，极易不一致。

---

### 三、Django DRF（Django REST Framework）：至少2次声明，复杂场景3次
#### 1. 第一次：Django ORM 数据库模型
```python
class Item(models.Model):
    name = models.CharField(max_length=100)
    price = models.FloatField()
```
#### 2. 第二次：Serializer 序列化器（解析+校验）
```python
from rest_framework import serializers
class ItemSerializer(serializers.ModelSerializer):
    class Meta:
        model = Item
        fields = ["name", "price"]
```
哪怕用 `ModelSerializer` 自动映射，**字段约束、自定义校验规则依然要在Serializer里再写一遍**（比如最小价格、名称长度限制，数据库模型里写一遍，序列化器还要再写一遍）。

#### 3. 第三次：接口文档注解（drf-yasg/swagger）
如果要自动生成API文档，还要单独写 `swagger_auto_schema` 再描述一遍参数结构，第三套重复代码。

#### 代码痛点：
IDE无法根据Serializer给视图函数做自动补全，视图里只能用 `serializer.validated_data["name"]`，没有类型提示；数据校验、数据库约束、文档描述三套分离。

---

### 四、原生裸Flask（不用任何扩展）：重复次数最多，全靠手写
没有序列化工具，**每一条规则都要在路由函数里重复写**：
```python
@app.route("/item", methods=["POST"])
def create():
    data = request.json
    # 手动校验（重复写类型、必填）
    if not data.get("name") or not isinstance(data["name"], str):
        return {"err": "name必须是字符串"}, 400
    if not data.get("price") or not isinstance(data["price"], float):
        return {"err": "price必须是数字"}, 400
    # 手动解析、手动转类型
    name = data["name"]
    price = float(data["price"])
    # 文档还要单独写Markdown/Postman，第四份重复
    return {"name": name, "price": price}
```
每新增一个字段，就要多一堆if判断，完全没有统一声明。

---

### 五、总结「多次声明」和FastAPI「一次声明」核心区别
| 能力                | Flask/DRF 需要声明几次       | FastAPI 只声明1次Pydantic模型 |
|---------------------|-----------------------------|-------------------------------|
| IDE自动补全、类型检查 | 无，或单独写注释            | 自动生效                      |
| JSON数据解析（转Python对象） | 单独Schema/手动转换 | 自动转换                      |
| 字段数据验证、必填、长度 | 单独一套校验代码 | 类型注解自动校验              |
| Swagger/OpenAPI接口文档 | 单独一套文档模型 | `/docs` 自动生成              |

简单说：其他框架把「类型、解析、校验、文档」拆成多套独立代码，每一套都要重复写字段；FastAPI 一套类型声明统一供给全部功能，不用重复。
