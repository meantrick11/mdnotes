# 第三章 内存管理

## 3.1 没有存储器抽象

**核心问题：**如果程序直接使用物理地址，操作系统怎样同时运行多个程序，并防止它们相互破坏？本节先看没有地址空间抽象时的限制，再看保护键和静态重定位为何只能解决一部分问题。

没有存储器抽象时，程序发出的地址就是**物理地址**。例如读取地址 `1000`，访问的就是物理内存的第 `1000` 个位置。程序既看不到独立于物理内存的私有地址空间，也不能自然地假设自己从地址 `0` 开始运行。

早期系统可以把操作系统放在低地址 RAM、较高地址 ROM，或把一部分系统放在 RAM、设备驱动放在 ROM。ROM 可以防止其中的代码被用户程序改写，但**不能自动隔离两个用户程序**；操作系统若在可写 RAM 中，也可能被错误的用户程序覆盖。这些布局说明了存放位置和写保护的差别，尚未提供每个进程各自的地址空间。

在最简单的单道方式下，内存一次只装入一个用户程序。程序结束后，下一个程序可以覆盖原来的位置。多个线程共享同一程序的内存映像，因此可以在该映像内交替执行；它们不能替代彼此独立的多个程序所需的地址隔离。

### 3.1.1 没有存储器抽象时运行多个程序

**方法一：整进程交换。**操作系统把当前程序的全部内存内容保存到非易失性存储器，再装入另一个程序运行。任一时刻内存仍只有一个用户程序，因此不会发生两个驻留程序相互覆盖的问题；代价是每次切换需要搬运整个内存映像。3.2.2 会在地址空间背景下进一步讨论交换。

**方法二：在物理内存中同时放置多个程序，并增加保护机制。**早期 IBM 360 把内存划为块，给块设置保护键；运行进程的状态字也带有键。访问时硬件比较两者，不匹配就产生陷入。只有操作系统能修改保护键，因而进程不能任意读写别的进程或系统占用的块。

保护键解决的是**访问保护**，仍未解决**重定位**。设程序 A 占据物理地址 `0` 起的 16 KiB，程序 B 装在 `16384` 起。B 编写时的 `JMP 28` 本想跳到自身偏移 `28` 的指令；如果机器把 `28` 直接当物理地址，控制流却跳进 A。即使保护键随后阻止访问，B 仍无法正常运行。

**静态重定位**在装入时改写需要重定位的地址：把 B 的 `JMP 28` 改成 `JMP 16412`（`16384 + 28`）。它要求可执行文件标出哪些位置含有待修正地址，增加装入工作；程序以后若搬到另一位置，还要重新处理。保护键加静态重定位能让多个程序共存，但管理复杂，也没有给程序提供稳定、独立的地址视图。

| 机制 | 解决的问题 | 仍然存在的限制 |
| --- | --- | --- |
| 单道运行 | 避免多个驻留程序覆盖 | 无法让独立程序同时驻留 |
| 整进程交换 | 让多个程序轮流运行 | 切换需保存、恢复完整映像 |
| 保护键 | 阻止越权访问其他内存块 | 程序地址仍指向物理位置 |
| 静态重定位 | 装入到非预定位置 | 装入成本高，搬迁时需再处理 |

**自测：**为什么两个程序有不同的保护键，第二个程序的 `JMP 28` 仍可能执行错误？保护和重定位分别要改变什么？
