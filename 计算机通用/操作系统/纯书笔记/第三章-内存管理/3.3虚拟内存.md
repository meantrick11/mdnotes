# 第三章 内存管理

## 3.3 虚拟内存

**核心问题：**进程的地址空间可能大于物理内存，也可能只用到其中少数区域。虚拟内存让进程继续使用自己的地址空间，而运行时只把所需部分放进 RAM。本节围绕分页、页表、地址转换加速及大地址空间的页表组织展开。

**虚拟内存不等于交换整个进程。**3.2 的整进程交换以进程映像为搬运单位；这里把地址空间分成较小的单位，在访问缺失部分时再调入。程序发出的虚拟地址经 MMU 转成物理地址；若所需页不在内存，硬件产生缺页异常，由操作系统处理。

### 3.3.1 分页

分页把虚拟地址空间划为固定大小的**虚拟页**，把物理内存划为同样大小的**页框**。页与页框不要求编号相同，也不要求进程各页在物理内存中连续。一个页可以映射到某页框；没有驻留的页暂时没有有效页框映射。

设页大小 `P = 2^k` 字节，虚拟地址 `v` 可拆为：

- 虚拟页号 `p = ⌊v / P⌋`；
- 页内偏移 `d = v mod P`，满足 `0 ≤ d < P`。

若页表指出页 `p` 位于物理页框 `f`，则**物理地址 `= f × P + d`**。转换只替换页号，页内偏移保持不变。例如 `P = 4096`、虚拟地址 `8196`，有 `p = 2`、`d = 4`；若页 `2` 映射到页框 `6`，物理地址就是 `6 × 4096 + 4 = 24580`。

**缺页路径：**访问未驻留的合法页 → MMU 产生缺页异常 → 操作系统找到该页的后备内容，并准备空闲页框；必要时先处理被移出页的修改内容 → 把目标页装入页框、更新映射 → 重新执行导致缺页的指令。选择哪一页退出属于 3.4 的页置换算法，本节只需理解这一步为何存在。

### 3.3.2 页表

**页表**记录“虚拟页号 → 物理页框号”的映射，并携带有效性与访问控制信息。MMU 用虚拟页号查页表项，再与原地址中的页内偏移拼成物理地址。不同进程有不同映射，因此相同虚拟地址可以落到不同物理页框。

典型页表项包含以下信息；实际位布局依硬件而异：

| 字段 | 作用 |
| --- | --- |
| 页框号 | 指向当前驻留的物理页框 |
| 在内存位 / 有效位 | 表示能否用该项直接完成地址转换；未驻留的合法页访问会触发缺页 |
| 读、写、执行权限及特权位 | 限制访问类型及用户态、内核态的访问范围 |
| 引用位（R） | 记录近期是否访问过，可供后续管理使用 |
| 修改位（M、脏位） | 记录驻留后是否写过；移出脏页通常须回写后备存储 |
| 禁止缓存位 | 指定该页是否可由 CPU 缓存；设备寄存器等内存映射 I/O 区域可能需要禁用缓存，避免读到过期值或让设备操作停留在缓存中 |

**缺页与非法访问不同。**一个属于进程地址空间、只是暂不驻留的页，可以通过调入继续运行；地址根本无映射，或访问违反权限，则不能把它当成普通缺页自动修复。具体异常分类和处理依硬件、操作系统而异。

单级页表的空间问题很快显现：32 位虚拟地址、4 KiB 页对应 `2^(32−12) = 2^20` 个虚拟页。若每项占 4 字节，一个完整单级页表需约 4 MiB，且是**每个进程**的开销；更大的地址空间会使直接建满页表更不现实。

### 3.3.3 加速分页过程

分页系统同时面对两个目标：**每次访存的地址转换要快**，并且**页表本身不能随虚拟地址空间无限膨胀**。把整个页表放进高速硬件寄存器，查找快却昂贵，进程切换时还要装载大量表项；把页表完全放在主存，切换时只需更换页表起始地址，但每次访存可能额外读取页表。TLB 主要缓解前一个目标；大页表的组织在 3.3.4 继续讨论。

#### 转换检测缓冲区（TLB，快表）

**TLB（Translation Lookaside Buffer）**位于 MMU 中，缓存少量近期使用的“虚拟页号 → 物理页框号”映射，以及有效位、访问权限、修改位等信息。它利用程序倾向于反复访问少数页的特点，避免每次都去主存查页表。教材也称它为**关联存储器**：硬件把待查虚拟页号与多个 TLB 项并行比较，所以命中时能迅速找到映射。

1. **TLB 命中：**MMU 找到有效表项，先检查访问权限，再取页框号与页内偏移组成物理地址。若权限不允许，例如写只读页，产生保护异常。
2. **TLB 未命中，但页表映射有效：**查找页表，把映射装入 TLB，随后重试访存；这时页面已在 RAM，**无需从磁盘或 SSD 调页**。
3. **页表没有可用映射：**交给操作系统判断页面是否已在 RAM、是否需要从后备存储调入，以及该地址是否合法；不能单凭 TLB 未命中判断发生了磁盘 I/O。

TLB 是页表映射的缓存。装入新映射时若 TLB 已满，需要替换某个旧项；这只是**TLB 项替换**，不意味着把相应的物理页面换出 RAM。教材的硬件管理示例中，旧 TLB 项的修改位在被清除时写回页表，使页表仍能反映页面是否被写过。操作系统修改映射或权限后，也必须使对应的旧 TLB 项失效或更新，否则处理器可能继续使用过期权限或页框号。

#### 软件 TLB 管理

**硬件管理 TLB**时，TLB 未命中后由 MMU 遍历页表并装入表项；通常只有映射无法由硬件完成时才陷入操作系统。**软件管理 TLB**时，硬件在 TLB 未命中后直接产生 TLB 异常，由操作系统查找映射、必要时替换一个 TLB 项、写入新表项，再重新执行被中断的指令。后者简化 MMU，但要求未命中处理路径足够短，因为 TLB 容量通常远小于 RAM 可容纳的页数，未命中可能比真正的缺页频繁得多。

**页表遍历（page table walk）**是沿页表层级查找某虚拟页映射的过程。它可由硬件完成，也可由软件完成；遍历页表本身不等于从磁盘读取页面。多级页表使遍历可能涉及多次主存访问，因此 TLB 命中率尤其重要。

| 情况 | 页面实际位置 | 处理动作 | 是否需要后备存储 I/O |
| --- | --- | --- | --- |
| **软失效（soft miss）** | 已在 RAM，页表有可用映射，但 TLB 没有 | 找到映射并更新 TLB | 不需要 |
| **次要缺页错误（minor page fault）** | 已在 RAM，但当前进程页表尚无可用映射 | 操作系统补建当前进程的页表映射，再更新 TLB | 不需要 |
| **硬失效（hard miss）／主要缺页错误（major page fault）** | 所需页面尚未在 RAM | 从磁盘或 SSD 调入页面，建立映射并更新 TLB | 需要 |
| **非法地址或越权访问** | 不属于可合法访问的映射 | 报告访问错误；不能靠装入页面修复 | 不需要按正常调页处理 |

**两层区别：**软失效只是 TLB 缺项，已有页表映射；次要缺页错误已经进入缺页异常处理，但页面其实在 RAM，例如被另一进程预先调入，只需为当前进程建立映射。硬失效需要取回不在 RAM 的页面，对应主要缺页错误。教材用这些分类说明处理成本的差异；不要把“TLB 未命中”“缺页异常”和“必须访问磁盘”画等号。

**自测：**一个页面在 RAM、当前进程页表项有效，但 TLB 中没有它，会发生什么？若页表项也没有当前进程的映射，而页面已被另一进程调入 RAM，又属于哪类情况？

### 3.3.4 针对大内存的页表

**多级页表**把页号拆成若干索引，只为实际用到的地址范围建立下级页表。教材的两级示例把 32 位地址划为 `10 位一级索引 + 10 位二级索引 + 12 位页内偏移`，页大小为 4 KiB。一级表的每项覆盖 `2^(10+12) = 4 MiB` 虚拟地址；未使用的 4 MiB 区域无需对应二级表。这节省稀疏地址空间的页表内存，代价是 TLB 未命中时可能需要更多次内存访问。

例如虚拟地址 `0x00403004`：一级索引为 `1`，二级索引为 `3`，页内偏移为 `4`。先用一级项找到二级页表，再用二级项找到页框；若某一级项不存在，就不能继续按普通已驻留映射访问。

**倒排页表**换一个计数方向：按**物理页框**建项，记录该页框当前属于哪个进程及其哪个虚拟页。表项数取决于物理页框数，而非整个虚拟地址空间的页数，因此空间开销较小；但给定“进程、虚拟页”时，不能再直接以虚拟页号索引，查找更复杂。教材讨论用 TLB 缓存常用映射，并用哈希等结构缩短 TLB 未命中后的查找。

例如物理内存为 16 GiB、页大小为 4 KiB，物理页框数是 `16 GiB / 4 KiB = 2^22`，倒排页表约需 `2^22` 项，与进程可使用多少虚拟页无直接关系。查找时仍需要从“进程标识 + 虚拟页号”定位对应页框；哈希表把可能匹配的项缩到较短的链上，TLB 则让常见映射不必每次都走这条查找路径。

| 结构 | 主要解决的问题 | 代价 |
| --- | --- | --- |
| TLB | 缩短常见地址转换路径 | 容量有限，映射变化须保持一致 |
| 多级页表 | 避免为未用虚拟区间建满页表 | 未命中时页表遍历层数增加 |
| 倒排页表 | 让表项数随物理页框数增长 | 从虚拟页反查页框更困难 |
