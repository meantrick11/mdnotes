# 第三章 内存管理

## 3.2 一种存储器抽象：地址空间

**核心问题：**如何让多个程序同时驻留内存，却都能使用自己的地址 `0`，并且不能访问彼此的内存？答案是把程序使用的地址与实际物理位置分开，再由硬件在访问时转换和检查。

### 3.2.1 地址空间的概念

**地址空间**是进程可用来寻址的一组地址。通常每个进程拥有独立地址空间；两个进程都引用地址 `28`，其物理位置可以完全不同。地址空间是给程序的视图，**不是一块天然连续、同样大小的物理内存**；此处先讨论把它映射到一段连续物理内存的简单方案。

**基址寄存器与界限寄存器**提供动态重定位和保护。假设进程被装入从物理地址 `B` 开始、长度为 `L` 的区域，程序发出逻辑地址 `a`：

1. 硬件检查 `0 ≤ a < L`；越界则产生陷入，交由操作系统处理。
2. 检查通过后，计算物理地址 `B + a`，再发起内存访问。

例如 `B = 16384`、`L = 16384`，程序跳转到 `a = 28`，实际取指地址是 `16412`。程序本身无需改写；切换进程时，操作系统装入该进程对应的基址和界限。寄存器必须受特权保护，否则进程可自行扩大界限或改变基址而突破隔离。每次访存都要做界限检查与地址加法，这是该方案的硬件开销。它也要求整个进程占据一段连续的物理内存。

**易混点：**基址是物理起点，界限在这里表示允许的地址范围长度；合法逻辑地址的上界是**严格小于** `L`，不是小于等于 `L`。保护键检查“谁能访问这块物理内存”，基址与界限则同时解决“程序地址落在哪里”和“是否越界”。

### 3.2.2 交换

当所有进程所需的物理内存之和超过 RAM 容量，可以采用**整进程交换**：把暂时不运行的进程完整移到磁盘或 SSD，需要运行时再调回。它与下一节虚拟内存的关键差别是：这里进程运行时通常需要**整个映像驻留**，虚拟内存允许只驻留正在使用的部分。

进程换出会留下空闲区；之后换入的位置可能与上次不同，因此需要重定位。交换使多个进程的装入、移出不断改变内存布局，也可能产生许多分散的空洞。把已驻留进程搬到一起可把空洞合并为更大的连续区域，这叫**内存紧缩**，但移动大量数据成本高，通常不作为常规操作。

进程运行中还可能增长：堆向高地址扩展，栈可能向低地址扩展。相邻位置有空闲区时可直接扩展；否则可能需要搬迁、换出其他进程，或等待空间释放。预留增长空间能减少搬迁次数，却会占用暂时不用的 RAM；换出时只需保存实际使用的部分。

### 3.2.3 空闲内存管理

动态分配要求系统知道哪些区域已占用、哪些区域空闲。本节给出两类表示方法，以及在空闲区链表上寻找可用区域的算法。

**位图。**把内存划成固定大小的分配单元，每个单元对应一位，例如 `0` 表示空闲、`1` 表示占用。若内存大小为 `M` 字节、单元大小为 `u` 字节，则位图约需 `⌈M/u⌉` 位。单元越小，位图越大，但尾部未用空间越少；单元越大则相反。申请 `k` 个连续单元时，还必须找到 `k` 个连续空闲位，搜索可能较慢。

**链表。**按地址记录已分配段和空闲洞，每项包含类型、起始地址、长度及指向下一项的指针。进程释放空间后，要检查左右邻居；相邻空闲洞应合并，避免可用空间被切碎。按地址排序便于找邻居，双向链表便于从待释放段回看前一项。

| 分配算法 | 选择空闲洞的规则 | 主要取舍 |
| --- | --- | --- |
| 首次适配（first fit） | 从表头找第一个足够大的洞 | 搜索通常较短；可留下较大洞 |
| 下次适配（next fit） | 从上次停下的位置继续找 | 避免总从表头开始；教材引述的模拟中效果略逊于首次适配 |
| 最佳适配（best fit） | 找够用且最小的洞 | 通常需检查整表；容易留下难以利用的小洞 |
| 最差适配（worst fit） | 取最大的洞 | 希望余下洞仍有用，但教材中的模拟结果不佳 |
| 快速适配（quick fit） | 按常见尺寸维护多个空闲洞表 | 申请快；释放时寻找邻居并合并更困难 |

**例子：**空闲洞依地址顺序分别为 `3`、`6`、`2` 个单元，现在申请 `2` 个单元。首次适配选择第一个洞，最佳适配选择第三个洞。后者恰好用尽该洞，但不能由单次结果推出它总体更省内存；长期分配、释放后的碎片形态才决定效果。

**自测：**为何进程换入到新物理位置后必须重定位？位图中“找连续 `k` 位”和“统计空闲位总数至少为 `k`”为什么不是一回事？
