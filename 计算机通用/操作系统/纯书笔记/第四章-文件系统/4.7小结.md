# 第四章 文件系统

## 4.7 小结

**本章主线：**文件系统把“按块读写设备”变成可命名、持久、可共享且可保护的文件和目录。外部接口回答“应用怎样找和用文件”；内部实现回答“名称怎样落到块、怎样管理空间并在故障后继续正确工作”。原书本节无编号子节。

| 视角 | 要解决的问题 | 本章主要机制与取舍 |
| --- | --- | --- |
| 文件与目录接口 | 如何命名、访问、分组和共享 | 文件名、属性、`open/read/write/seek`、目录树、相对/绝对路径、硬链接和符号链接；简洁接口隐藏存储布局 |
| 文件块定位 | 文件第 n 块在哪里 | 连续分配定位快却难增长；块链灵活但随机访问慢；FAT 用内存换查找；i-node 用每文件索引支持扩展 |
| 空间与多用户管理 | 哪些块可用，谁可占用多少 | 空闲链表/位图、块大小、配额；容量、管理成本和局部性相互制约 |
| 可靠性 | 崩溃或误操作后如何恢复 | 日志确保更新过程可恢复，一致性检查找元数据矛盾，备份恢复历史内容；三者任务不同 |
| 性能与设备适配 | 如何减少慢 I/O 并适应闪存 | 缓存、预读、邻近分配、日志结构写入、FTL/TRIM；机械磁盘的寻道优化不可直接套到 SSD |
| 实例 | 设计选择怎样组合 | MS-DOS/FAT 用目录项和 FAT 链；UNIX V7 用目录项与 i-node 分离名称和对象 |

**三个最容易混淆的关系：**

1. **名称与文件对象**：目录项提供名称和索引；硬链接可让不同名称指向同一对象，符号链接保存另一个路径。
2. **日志与备份**：日志帮助完成或恢复崩溃中的更新；备份保留可恢复的历史内容。日志不能代替备份。
3. **逻辑块与物理位置**：文件系统把文件偏移映射到逻辑存储块；SSD 的 FTL 可再把逻辑地址映射到不断变化的闪存物理页。

**复盘问题：**如果应用请求 `open("/usr/ast/mbox")` 后读取第 n 块，路径解析先通过目录项找到文件元数据，再由 FAT 或 i-node 等方案找到该块；数据可能先从缓存返回。若要修改，写回策略与日志影响崩溃后的状态，备份决定能否找回早先版本。沿这条链即可把本章各小节连起来。
