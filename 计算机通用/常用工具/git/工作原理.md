# 工作原理

git通过以每个文件在最初提交的基线为标准建立不同文件的blob，也就是提交到追踪过程，提交之后，如果一个文件进行修改再提交，那么.git仓库会记录相对于基线版本的增量，所以本质还是**增量记录**，这个过程中可以指定记录不同的工作目录，以及.git仓库所在的位置(如果工作目录+仓库目录不在同一个位置，那么这就是**影子仓库**)。

由于是增量记录，所以二进制/视频等等形式要想记录完整，就必须得复制一份，那么整个仓库的增长速度会非常快，所以这类形式的文件不适合使用git仓库进行版本控制



Git 是基于内容寻址对象数据库的分布式版本控制系统。

文件内容以 Blob 对象存储，目录结构由 Tree 对象组织。Git 通过 Index 管理下一次提交的文件状态，Commit 引用根 Tree 和父 Commit，从而建立完整的项目快照及其历史关系。

Git 分支是指向 Commit 的可移动引用，HEAD 通常指向当前分支。新建分支不复制代码和历史，只创建一个新的引用。

分支合并可能是快进式引用移动，也可能通过三方合并创建具有多个父提交的新 Commit。远程仓库拥有独立的对象数据库和引用，本地通过 Fetch、Push 等操作交换对象并同步引用状态。

Git 对象不可变，引用可变。这是 Git 能够实现版本追踪、分支管理、合并和历史回退的基础。
