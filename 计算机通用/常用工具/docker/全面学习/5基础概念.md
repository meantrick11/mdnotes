# 基础概念

## 什么是容器？

### 说明

想象一下，你正在开发一款超棒的网络应用，它包含三个核心组件——React前端、Python接口以及PostgreSQL数据库。如果你想开展这个项目，就必须安装Node、Python和PostgreSQL。

你如何确保自己拥有与团队中其他开发人员、CI/CD 系统或生产环境中所使用的相同版本？

你如何确保应用所需的 Python（或 Node、数据库）版本不会受到本机已安装版本的影响？又该如何管理潜在的冲突？

**什么是容器？简单来说，容器是为你的应用各个组件提供的隔离进程。每个组件——前端的React应用、Python API引擎以及数据库——都在各自独立的环境中运行，与你设备上的其他所有内容完全隔离开来。**

这就是它们的优势所在。容器具备以下特点：

1. 自包含。每个容器都具备运行所需的全部内容，无需依赖宿主机上任何预先安装的依赖项。
2. 隔离性。由于容器在隔离环境中运行，它们对主机和其他容器的影响极小，从而提升了应用程序的安全性。
3. 独立。每个容器均被独立管理。删除一个容器不会影响其他任何容器。
4. 便携性。容器可在任何地方运行！在开发机器上运行的容器，在数据中心或云端的任何位置都能正常工作！

### 容器和虚拟机的对比

不用深究的话，虚拟机就是一个完整的操作系统，拥有自己的内核、硬件驱动、程序和应用。仅为隔离单个应用而启动虚拟机，会产生大量额外开销。

容器本质上就是一个包含运行所需所有文件的隔离进程。如果你运行多个容器，它们会共享同一个内核，从而让你能用更少的基础设施运行更多应用。

### 容器的启动

在Docker Desktop上首先通过顶部的搜索框搜索想要拉取的镜像名，然后点击pull，然后点击启动，实例容器就被运行了，随后就可以对其进行一些操作，最后不用的时候点击停止容器即可。

**无论是Docker Desktop、命令行抑或是软件开发的Docker SDK对容器进行操作(创建、启动、停止、移动、删除)和管理，这些都可以是Docker的Client，Client对Host中的Docker Daemon提供的API接口进行操作，运行在主机上的Docker Daemon监听Docker API请求并管理Docker对象，如image、container、network、volume等，一个守护进程还可以和其他守护进程进行通信以管理Docker服务。**

## 什么是镜像？

## 解释

既然容器是一个独立的进程，它的文件和配置从哪里获取？又该如何共享这些环境？

**这就是容器镜像发挥作用的地方。容器镜像是一种标准化的包，其中包含运行容器所需的所有文件、二进制文件、库和配置。**

**镜像是构建一个应用环境的所有文件（库、代码、配置等），而容器是一个镜像通过Docker Daemon API管理的一个在主机上运行的一个进程实例**

对于一个PostgreSQL镜像，该镜像会打包数据库二进制文件、配置文件以及其他依赖项。对于一个Python网络应用程序，它会包含Python运行时、你的应用代码以及其所有依赖项。

镜像有两个重要原则：
1. 镜像是不可变的，镜像一旦创建，就无法修改，只能创建新的镜像或者在其上添加更改。
2. 容器镜像由多个层构成，每一层都代表一组用于添加、删除或修改文件的文件系统变更。

这两个原则让你可以扩展或向现有镜像中添加内容。例如，如果你正在构建一个 Python 应用程序，你可以从Python 镜像开始，然后添加额外的层来安装应用程序的依赖项并添加你的代码。这样你就可以专注于应用程序本身，而不是 Python 本身。


### 查找镜像

Docker Hub 是用于存储和分发镜像的默认全球市场。它拥有超过 10 万由开发者创建的镜像，你可以在本地运行这些镜像。你可以在 Docker Hub 中搜索镜像，并直接从 Docker Desktop 运行它们。

### 镜像分层

Docker 镜像采用 UnionFS 联合文件系统实现分层结构。镜像由多层只读层堆叠组成，Dockerfile 每条指令生成一层，每层保存与上层差异。镜像层可复用缓存。启动容器时，在镜像之上增加一层可读写容器层；文件修改遵循写时复制 CoW，只复制修改文件到读写层，底层镜像保持不变。删除容器仅销毁读写层，镜像不受影响。

**简易理解就是，每一条Dockerfile的命令就是一层(下层可能依赖上层)，Dockerfile是从头开始定义“如何组装”出一个全新的 image（镜像）**


## 什么是注册中心？

### 说明

既然你已经了解了容器镜像是什么以及它的工作原理，你可能会好奇——这些镜像存储在哪里？

你可以将容器镜像存储在自己的计算机系统上，但如果你想与朋友分享这些镜像，或是在另一台机器上使用它们，该怎么办呢？这就需要用到镜像注册表了。

镜像仓库是用于存储和共享容器镜像的集中式位置，它可以是公共的，也可以是私有的。Docker Hub 是一个任何人都可使用的公共仓库，也是默认的仓库。

虽然 Docker Hub 是一个常用的选择，但如今还有许多其他可用的容器注册表，包括亚马逊弹性容器注册表（ECR）、微软 Azure 容器注册表（ACR）和谷歌容器注册表（GCR）。你甚至可以在本地系统或组织内部运行私有注册表，例如 Harbor、JFrog 制品库、GitLab 容器注册表等。

### 注册中心和仓库

在使用注册中心时，你可能会听到注册中心和存储库这两个术语，仿佛它们可以互换使用。尽管二者相关，但并不完全是一回事。

注册中心是存储和管理容器镜像的集中式位置，而仓库是注册中心内一组相关容器镜像的集合。可以将其视为一个文件夹，你可以根据项目来组织镜像。每个仓库都包含一个或多个容器镜像。
**Git(业务源代码)一个仓库=一个项目，和远程仓库关联，只存储开发代码的以及对开发进行版本控制，Docker(运行环境+运行时+业务源代码) 一个仓库是一系列相关镜像(运行环境的所有文件，源代码)的集合，通过tag给不同的镜像打标签区分**

**业务代码版本管理->Git**
**业务开发/运行环境->Docker**


有以下代码进行辨析:

1. 克隆业务逻辑代码，包括Dockerfile

`git clone https://github.com/dockersamples/helloworld-demo-node`
2. 进入项目目录
`cd helloworld-demoo-node`
3. 根据业务逻辑代码中的Dockerfile构建镜像(一般Git仓库不会包括对应的环境文件，比如Python解释器，如果缺少，build会自动到Docker Hub上面拉取所需环境文件)
`docker build -t YOUR_DOCKER_USERNAME/docker-quickstart .`
*.表示当前文件夹*

**Git只存储业务源代码，Docker的build在根据Dockerfile创建镜像时，如果发现缺少某一个所需环境(比如python解释器)，他会自动到Docker hub上拉取对应的版本。**


4. 列出新创建的Docker镜像

`docker images`

5. 运行以下命令启动容器以测试镜像

`docker run -d -p 8080:8080 <YOUR_DOCKER_USERNAME>/docker-quickstart`



6. 使用docker tag命令为Docker镜像打标签。Docker标签可用于为镜像标注和设定版本.

`docker tag <YOUR_DOCKER_USERNAME>/docker-quickstart <YOUR_DOCKER_USERNAME>/docker-quickstart:1.0`

7. 最后，就可以使用docker push命令将新构建的镜像推送到你的 Docker Hub 仓库了：
`docker push <YOUR_DOCKER_USERNAME>/docker-quickstart:1.0`


## 什么是Docker Compose?

### 说明

如果你一直按照目前的指南操作，那么你一直在处理单容器应用。但现在你想做一些更复杂的操作——运行数据库、消息队列、缓存，或是各类其他服务。你是要把所有东西都安装在一个容器里吗？还是运行多个容器？如果运行多个容器，又该如何将它们全部连接起来？
容器的一个最佳实践是每个容器只做一件事，并把这件事做好。虽然这条规则有例外情况，但应避免让一个容器承担多项任务的倾向。**是不是和Linux的设计理念一模一样？**

你可以使用多条 `docker run` 命令来启动多个容器。但很快你会发现，你需要管理网络、将容器连接到这些网络所需的所有参数，还有更多操作。而当你完成操作后，清理工作也会变得稍显复杂。

借助 Docker Compose，你可以在单个 YAML 文件中定义所有容器及其配置。如果将该文件纳入代码仓库，任何克隆你仓库的人都能通过一条命令快速启动运行环境。

需要明确的是，Compose 是一个声明式工具——你只需完成定义即可使用。你并不总是需要从零开始重新构建所有内容。如果进行了修改，再次运行 docker compose up，Compose 就会整合你配置文件中的变更并智能地应用这些变更。

#### Dockerfile&Compose 文件的对比

Dockerfile 提供了构建容器镜像的指令，而 Compose 文件则定义了正在运行的容器。通常情况下，Compose 文件会引用 Dockerfile 来构建特定服务所使用的镜像。

### 实操

#### 使用compose启动应用程序

1. 安装并配置好Docker Desktop

2. 打开终端并从github上拉取业务源代码

`git clone https://github.com/dockersamples/todo-list-app `

3. 进入todo-list-app目录

`cd todo-list-app`

在这个目录中，你会找到一个名为compose.yaml的文件。这个 YAML 文件是所有核心配置所在！它定义了组成你应用程序的所有服务，以及它们的配置信息。每个服务都会指定自身的镜像、端口、卷、网络和其他运行所需的必要设置。花点时间查看这个 YAML 文件，熟悉它的结构吧。

4. 使用docker compose up 命令启动应用程序：

`docker compose up -d --build`

这里发生了不少事！有几件事要说明一下：

- 从 Docker Hub 下载了两个容器镜像——node 和 MySQL
- 已为你的应用创建了一个网络
- 已创建一个卷，用于在容器重启之间持久保存数据库文件
- 已启动两个容器并配置了所有必要参数

5. 一切都已启动并运行完毕后，你可以在浏览器中打开http://localhost:3000查看该网站。请注意，应用程序可能需要10到15秒才能完全启动。如果页面无法立即加载，请稍等片刻后刷新。你可以随意向列表中添加项目、勾选已完成的项目并删除项目。

6. 查看 Docker Desktop 图形用户界面，你可以看到容器，并进一步深入了解它们的配置。

#### 拆除应用
由于这个应用是用 Docker Compose 启动的，完成使用后很容易将其全部关闭。

1. 在CLI命令界面，使用docker compose dowmn来删除所有内容：
`docker compose down`

**默认情况下，当你拆除 Compose 堆栈时，不会自动删除卷。这样设计的初衷是，如果你重新启动该堆栈，可能希望保留这些数据。**

**如果你确实想要删除卷，请在运行 docker compose down 命令时添加 --volumes 标志：**
`docker compose down --volumes`

2. 或者，你可以使用 Docker Desktop 图形界面来删除容器，方法是选中应用程序堆栈，然后点击删除按钮。

**请注意，如果你在图形界面中删除 Compose 应用的容器，这只会删除容器本身。若你希望删除网络和卷，则需手动进行。**
