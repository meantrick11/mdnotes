# 创建并推送第一个镜像

## 说明
既然你已经更新了待办事项应用程序，现在就可以为该应用程序创建容器镜像并将其共享到 Docker Hub 上。要完成此操作，你需要执行以下步骤：
1. 使用Docker账号
2. 在Docker Hub上创建镜像仓库
3. 构建容器镜像
4. 将镜像推送到Docker Hub上

在深入实践指南之前，以下是几个你需要了解的核心概念。

## 核心概念

### 容器镜像
如果你是容器镜像新手，可以将其视为包含运行应用所需一切内容的标准化包，包括应用文件、配置和依赖项。这些包随后可以分发给他人并与他人共享。

### Docker Hub

要共享你的 Docker 镜像，你需要一个存储它们的地方。这就是镜像仓库的作用所在。虽然有许多镜像仓库，但 Docker Hub 是镜像的默认首选仓库。Docker Hub 既为你提供了存储自有镜像的空间，也让你能找到他人的镜像来运行，或将其用作自有镜像的基础。

## Docker 账号登录

要将镜像推送到 Docker Hub，你需要使用 Docker 账号登录。

1. 打开 Docker 面板。
2. 在右上角选择登录。
3. 如有需要，请创建一个账户，然后完成登录流程。

## 创建镜像仓库

现在你已经拥有账户，可以创建镜像仓库了。就像 Git 仓库用于存储源代码一样，镜像仓库用于存储容器镜像。
1. 前往[https://hub.docker.com/?_gl=1*19x9koz*_gcl_au*MTUwNDE3NTc0OC4xNzg2OTU5MjA3*_ga*MTk5ODE5Mjg1Mi4xNzg2OTU5MjA2*_ga_XJWPQMJYHQ*czE3ODY5NzE5NjAkbzQkZzEkdDE3ODY5NzI5MjIkajYwJGwwJGgw]Docker Hub。
2. 选择创建仓库。
3. 在创建代码仓库页面，输入以下信息：
    仓库名称 - getting-started-todo-app
    简短描述 - 如果你愿意，可以输入一段描述
    可见性 - 选择公开，以便其他人拉取你定制的待办事项应用
4. 选择创建以创建代码仓库。

##  构建并推送镜像

现在你已经有了一个代码仓库，接下来就可以构建并推送你的镜像了。有一点需要重点注意：你要构建的这个镜像是基于 Node 镜像扩展而来的，这意味着你无需安装或配置 Node、yarn 等工具，只需专注于打造应用程序的独特功能即可。

执行操作：
1. 要开始操作，请将项目克隆下来，或以 ZIP 文件形式下载到你的本地计算机。
`git clone https://github.com/docker/getting-started-todo-app`
项目克隆完成后，进入克隆操作创建的新目录：
`cd getting-started-todo-app`
2. 运行以下命令来构建项目，将DOCKER_USERNAME替换为你的用户名。
`docker build -t <DOCKER_USERNAME>/getting-started-todo-app .`
3. 要验证镜像是否本地存在，你可以使用 docker image ls 命令：
`docker image ls`
4. 要推送镜像，使用`docker push`命令，将<DOCKER_USERNAME>替换为自己的用户名：
`docker push <DOCKER_USERNAME>/getting-started-todo-app`
**Docker的push不需要像Git一样先关联本地+远程仓库，会自动识别本地Docker账号，如果对应的远程仓库正确，那么就会直接推送。**
## 回顾

在继续之前，花点时间思考一下这里发生了什么。短短几分钟内，你就构建出了一个封装应用的容器镜像，并将其推送到了 Docker Hub 上。

接下来，你需要记住以下几点：
    - Docker Hub 是查找可信内容的首选镜像仓库。Docker 提供了一系列可信内容集合，包括 Docker 官方镜像、Docker 认证发布商镜像以及 Docker 赞助的开源软件镜像，可直接使用或作为你自定义镜像的基础。
    - Docker Hub 提供了一个用于分发你自己应用程序的市场平台。任何人都可以注册账户并分发镜像。在你公开发布所创建的镜像时，私有仓库能确保你的镜像仅对授权用户开放访问。
