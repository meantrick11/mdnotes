# ORDER OF EXCUTE SQL QUERY
```SQL
Complete SELECT query
SELECT DISTINCT column, AGG_FUNC(column_or_expression), …
FROM mytable
    JOIN another_table
      ON mytable.column = another_table.column
    WHERE constraint_expression
    GROUP BY column
    HAVING constraint_expression
    ORDER BY column ASC/DESC
    LIMIT count OFFSET COUNT;
```

# SQL SELECT 完整语句：书写顺序 vs **真实执行顺序**
```
1. FROM + JOIN
2. WHERE
3. GROUP BY
4. 聚合计算 + HAVING
5. SELECT（包含DISTINCT）
6. ORDER BY
7. LIMIT OFFSET
```

## 逐条拆解每一层作用 + 执行逻辑
### 1. FROM mytable JOIN another_table
✅ **最先执行**
作用：确定数据源，把多张表通过 `JOIN ... ON` 关联，拼接出一张**临时中间数据表**。
> 先拿到所有原始关联数据，后续所有操作都基于这张临时表。

### 2. WHERE constraint_expression
✅ 第二步
作用：**过滤原始行**，从JOIN生成的临时表里剔除不满足条件的数据。
⚠️ 重点：
WHERE **不能使用聚合函数**（此时还没分组、没有聚合结果）；
过滤的是**原始单行数据**，不是分组之后的统计结果。

### 3. GROUP BY column
✅ 第三步
作用：对WHERE筛选完之后剩下的数据，按照指定字段进行分组，把值相同的行归为一组。

### 4. HAVING constraint_expression
✅ 第四步（分组完成后执行）
作用：**过滤分组之后的结果**
⚠️ 核心区分：
- WHERE：分组前，过滤原始行
- HAVING：分组后，可以使用聚合函数（`SUM、COUNT`等）筛选组别

### 5. SELECT DISTINCT column, AGG_FUNC(...)
✅ 第五步
作用：
1. 在分好的组上执行**聚合函数计算**（SUM/COUNT/AVG等）
2. 挑选需要展示的列，生成最终结果集
3. `DISTINCT`：去除结果集中重复行

> 很多人误以为SELECT最先执行，**完全错误**，SELECT是在筛选、分组完成后才挑选输出字段。

### 6. ORDER BY column ASC/DESC
✅ 第六步
作用：对SELECT输出的结果集，按照指定字段升序/降序排序。
> 可以使用SELECT里起的别名，因为此时结果列已经生成。

### 7. LIMIT count OFFSET count
✅ 最后执行
作用：分页；截取排序完成后的数据集，跳过OFFSET条，最多取出count条。

---

# 直观对比
## 书写顺序（你代码写的顺序）
```sql
SELECT → FROM → JOIN → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT
```
## 数据库真实执行顺序
```
FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT(DISTINCT) → ORDER BY → LIMIT
```

# 高频考点总结
1. **WHERE 在 GROUP BY 之前；HAVING 在 GROUP BY 之后**
2. WHERE 不能放聚合函数；HAVING 专门用来筛选聚合结果
3. ORDER BY 在 SELECT 之后，所以能识别字段别名
4. LIMIT 永远最后执行，先排序再分页
