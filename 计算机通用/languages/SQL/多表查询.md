# 多表拆查询

在 SQL 中，多表查询最核心的四种 JOIN 语句分别是 **INNER JOIN**、**LEFT JOIN**、**RIGHT JOIN** 和 **FULL JOIN**。它们本质上都是**集合运算**，用于将两个表（或结果集）根据指定的“连接条件”进行组合。

为了让你直观理解，我们先建立两个简单的示例表：

- **学生表 (Students)**：`id`, `name`
- **选课表 (Courses)**：`student_id`, `course`

**样本数据**：
学生表有：`1, 张三`；`2, 李四`；`3, 王五`。
选课表有：`1, 数学`；`1, 英语`；`3, 物理`。（注意：李四没选课，王五选了物理但我们的逻辑通常按ID匹配）

---

### 1. INNER JOIN（内连接）
**核心逻辑**：**取交集**。只返回两个表中**连接条件完全匹配**的行。只要有一方不匹配，该行数据就会被丢弃。

- **适用场景**：查询必须同时存在于两张表中的关联数据。例如：查询“有选课记录的学生名单”。
- **SQL 写法**：
  ```sql
  SELECT s.name, c.course
  FROM Students s
  INNER JOIN Courses c ON s.id = c.student_id;
  ```
- **返回结果**：张三（数学、英语）；王五（物理）。**李四没有返回**，因为他没选课。

---

### 2. LEFT JOIN（左外连接）
**核心逻辑**：**左表全保留 + 右表匹配项**。返回左表（`FROM` 后面的表）的**所有行**，即使右表中没有匹配，右表的字段会以 `NULL` 填充。

- **适用场景**：查询“所有学生及其选课情况，没选课的学生也要显示”。
- **SQL 写法**：
  ```sql
  SELECT s.name, c.course
  FROM Students s
  LEFT JOIN Courses c ON s.id = c.student_id;
  ```
- **返回结果**：张三（数学）、张三（英语）、李四（NULL）、王五（物理）。**左表全体成员保留**。

---

### 3. RIGHT JOIN（右外连接）
**核心逻辑**：**右表全保留 + 左表匹配项**。它是 `LEFT JOIN` 的镜像，返回右表（`JOIN` 后面的表）的**所有行**，左表无匹配则填 `NULL`。

- **适用场景**：极少单独使用，因为把右表写在前面再换 `LEFT JOIN` 效果完全一样。
- **SQL 写法**：
  ```sql
  SELECT s.name, c.course
  FROM Students s
  RIGHT JOIN Courses c ON s.id = c.student_id;
  ```
- **返回结果**：张三（数学）、张三（英语）、王五（物理）。注意，这里因为右表全是有效 student_id，所以看起来和 INNER JOIN 一样。但若右表有无人匹配的课程ID，左表字段会为 NULL。

---

### 4. FULL JOIN（全外连接）
**核心逻辑**：**并集**。返回左表和右表的**所有行**。无论哪一边缺失，缺失侧字段都用 `NULL` 填充。

- **适用场景**：数据对账、合并两个独立的清单。例如：合并“所有学生名单”和“所有课程名单”，查看完整对应关系。
- **SQL 写法**（MySQL 不原生支持，需用 `UNION` 模拟）：
  ```sql
  -- 标准 SQL 写法
  SELECT s.name, c.course
  FROM Students s
  FULL OUTER JOIN Courses c ON s.id = c.student_id;
  
  -- MySQL 模拟写法（LEFT JOIN + RIGHT JOIN 去重）
  SELECT s.name, c.course FROM Students s LEFT JOIN Courses c ON s.id = c.student_id
  UNION
  SELECT s.name, c.course FROM Students s RIGHT JOIN Courses c ON s.id = c.student_id;
  ```
- **返回结果**：张三（数学）、张三（英语）、李四（NULL）、王五（物理）。如果右表有无人选课的课程，也会显示 `NULL, 课程名`。

---

### 对比总结（面试常问）

| JOIN 类型 | 左表（Students） | 右表（Courses） | 返回行数特征 |
| :--- | :--- | :--- | :--- |
| **INNER** | 匹配才保留 | 匹配才保留 | **只多不少**（匹配成功才留） |
| **LEFT** | **全部保留** | 匹配保留，无则 NULL | 至少等于左表行数 |
| **RIGHT** | 匹配保留，无则 NULL | **全部保留** | 至少等于右表行数 |
| **FULL** | **全部保留** | **全部保留** | 等于两表并集行数 |

---

### 💡 三条避坑实战建议

1.  **永远优先使用 LEFT JOIN 代替 RIGHT JOIN**：`RIGHT JOIN` 完全可以用调换表顺序的 `LEFT JOIN` 替代，可读性更高，避免大脑逻辑混乱。
2.  **ON 与 WHERE 的区别**：`ON` 负责控制**表连接**方式；`WHERE` 负责对**连接后的结果**进行过滤。在 `LEFT JOIN` 中，若把对右表的过滤条件写在 `WHERE` 里，会把 `NULL` 过滤掉，效果等同于 `INNER JOIN`（这是新手最常见的错）。
   - ❌ 错误：`LEFT JOIN ... ON id=student_id WHERE course = '数学'`（会把没选课的李四过滤掉）。
   - ✅ 正确：若想保留左表全部，对右表筛选应写在 `ON` 里：`LEFT JOIN ... ON id=student_id AND course = '数学'`。
3.  **性能关注点**：多表 JOIN 时，尽量让驱动表（小表）在左边（配合 LEFT JOIN），并确保连接字段（如 `student_id`）建有**索引**，否则数据量大时会全表扫描，性能急剧下降。
