# 8. 错误与异常

对照官网：[8. Errors and Exceptions](https://docs.python.org/3/tutorial/errors.html)

有两类问题：**语法错误**（还没开始跑）和 **异常**（跑起来之后出了状况）。

---

## 8.1 语法错误

```python
while True print("Hello")
# SyntaxError: invalid syntax
```

箭头指到被解析到的位置。缩进不对、漏冒号、括号没闭合都属于这一类。必须改源码，没法用 `try` 接住「整个文件语法错误」（文件 import 失败时，对**调用方**表现为 `SyntaxError` 异常）。

---

## 8.2 异常长什么样

```python
10 * (1 / 0)
# ZeroDivisionError: division by zero

4 + spam * 3
# NameError: name 'spam' is not defined

"2" + 2
# TypeError: can only concatenate str (not "int") to str
```

最后一行是类型 + 说明。上面的 traceback 指出调用栈。内置异常类型见[文档](https://docs.python.org/3/library/exceptions.html)。

---

## 8.3 `try` / `except`

```python
while True:
    try:
        x = int(input("请输入数字: "))
        break
    except ValueError:
        print("那不是数字，再试一次")
```

流程：

1. 执行 `try` 块
2. 没异常 → 跳过 `except`
3. 有异常且类型匹配（或为其子类）→ 进对应 `except`
4. 不匹配 → 向外冒泡
5. 多个 `except` 从上到下匹配，**只进第一个命中的**

一个子句接多种：

```python
except (RuntimeError, TypeError, NameError):
    pass
```

```python
try:
    f = open("myfile.txt", encoding="utf-8")
    s = f.readline()
    i = int(s.strip())
except OSError as err:
    print("OS 错误:", err)
except ValueError:
    print("不能转成整数")
except Exception as err:
    print(f"未预期: {err}")
    raise          # 再抛出去，别把真正的 bug 吞掉
else:
    print("能转成", i)
    f.close()
```

`else` 只在 **try 没有异常** 时执行。把「成功之后的逻辑」放 `else`，避免 succeded 代码自己抛的异常被上面的 `except` 误伤。

`except Exception` 几乎能接住所有常规错误，但接不住 `SystemExit`、`KeyboardInterrupt`（它们继承 `BaseException`）。不要裸写 `except:`，会连 Ctrl+C 一起吞掉。

---

## 8.4 抛出异常

```python
raise NameError("HiThere")

raise ValueError  # 简写：raise ValueError()
```

`except` 里写 `raise` 不加参数，把**当前异常原样**继续往外传。

```python
try:
    raise NameError("HiThere")
except NameError:
    print("处理了一下")
    raise
```

---

## 8.5 异常链

处理 A 时又失败成 B，Python 会记下因果关系：

```python
try:
    open("不存在.txt")
except OSError as e:
    raise RuntimeError("打不开配置") from e
```

traceback 里会有 `The above exception was the direct cause of...`。`from None` 可以隐藏前一个异常（偶尔用于把底层错误换成更友好的类型）。

---

## 8.6 自定义异常

建一个继承 `Exception` 的类即可。大型项目会建模块级异常树：

```python
class Error(Exception):
    """本模块基类。"""

class InputError(Error):
    def __init__(self, expression, message):
        self.expression = expression
        self.message = message
```

捕获时写 `except InputError`，不要拿去接 `except Error` 之后还指望细分时顺序反了——一样是从上到下。

---

## 8.7 `finally` 与 `with`

```python
try:
    raise KeyboardInterrupt
finally:
    print("再见")
```

`finally` **一定执行**：有没有异常都走。若 `finally` 里 `return` 或再 `raise`，会覆盖 try 里的返回/异常。清理资源优先用 `with`，比手写 `finally: f.close()` 更不容易漏。

---

## 8.8 一组无关异常（3.11+）

`ExceptionGroup` 可以一次携带多个错误，配合 `except*`。入门项目很少需要，知道名字即可，用到再查官网 8.9。

给异常加备注（3.11+）：

```python
try:
    raise ValueError("坏数据")
except ValueError as e:
    e.add_note("出现在导入用户表时")
    raise
```

## 8.9 综合例子：安全读配置

```python
import json
from pathlib import Path

class ConfigError(Exception):
    pass

def load_config(path):
    p = Path(path)
    try:
        text = p.read_text(encoding="utf-8")
        data = json.loads(text)
    except FileNotFoundError as e:
        raise ConfigError(f"找不到 {p}") from e
    except json.JSONDecodeError as e:
        raise ConfigError(f"{p} 不是合法 JSON") from e
    if "host" not in data:
        raise ConfigError("缺少 host")
    return data
```

调用方只需要 `except ConfigError`，不必关心是文件问题还是 JSON 问题——除非他们想区分。
