# Working with Database Metadata

*通过对象映射对表的结构进行操作，比如table\colume...*
**使用Python的字典等功能实现对数据库的直接映射，如果使用3讲的text(SQL)方式是直接写SQL语句，那么将会失去兼容性，通过实例化MetaData对象，那么后续可以直接操作python内的对象进行查询等的操作，这也是使用SQLAIchemy的关键原因**


引擎和 SQL 执行功能已就绪，我们可以开始进行一些核心开发了。SQLAlchemy Core 和 ORM 的核心元素都是 SQL 表达式语言，它能让你流畅、可组合地构建 SQL 查询。**这些查询的基础是代表表、列等数据库概念的 Python 对象，这些对象统称为数据库元数据。**

SQLAlchemy 中用于数据库元数据的最常见基础对象被称为 MetaData、Table 和 Column。以下部分将说明这些对象在核心（Core）风格和对象关系映射（ORM）风格中的使用方式。

*和其他部分一样，Core 用户可以跳过 ORM 相关章节，但 ORM 用户最好能从两个角度熟悉这些对象。使用 ORM 时，这里讨论的 Table 对象是以更间接（同时也是完全 Python 类型化）的方式声明的，不过在 ORM 的配置中仍然存在 Table 对象。*

## 使用table对象设置元数据

当我们操作关系型数据库时，在数据库中我们从中查询数据的基本数据存储结构被称为表。在 SQLAlchemy 中，数据库的“表”最终由一个同名的 Python 对象 Table 来表示。

要开始使用 SQLAlchemy 表达式语言，我们需要先构建 Table 对象，用以表示所有我们需要操作的数据库表。Table 是通过编程方式构建的，既可以直接使用 Table 构造函数，也可以通过 ORM 映射类间接构建（详见 使用 ORM 声明式形式定义表元数据）。此外，还可以从现有数据库加载部分或全部表信息，这一方式被称为 **反射**。

无论采用哪种方法，我们始终从一个集合开始，这个集合将是我们放置表的地方，也就是MetaData对象。该对象本质上是一个围绕 Python 字典的外观（facade），它存储了一系列以字符串名称为键的Table对象。虽然 ORM 提供了一些获取该集合的选项，但我们始终可以选择直接创建一个，代码如下：
```python
from sqlalchemy import MetaData
metadata_obj = MetaData()
```

一旦我们获得了一个 MetaData 对象，就可以声明一些 Table 对象。本教程将从经典的 SQLAlchemy 教程模型开始，该模型包含一个名为 user_account 的表（例如用于存储网站用户信息），以及一个相关的 address 表，该表存储与 user_account 表中行相关联的电子邮件地址。在完全不使用 ORM 声明式模型的情况下，我们直接构建每个 Table 对象，通常会为每个对象分配一个变量，这也是我们在应用代码中引用表的方式：

```python
from sqlalchemy import Table, Column, Integer, String
user_table = Table(
    "user_account",
    metadata_obj,
    Column("id", Integer, primary_key=True),
    Column("name", String(30)),
    Column("fullname", String),
)
```

通过上面的示例，**当我们想要编写引用数据库中user_account表的代码时，我们将使用user_table这个Python变量来指代它**。

## Table组件

我们可以看到，用 Python 编写的 Table 结构与 SQL 的 CREATE TABLE 语句有相似之处；以表名开头，然后列出每一列，每一列都有名称和数据类型。我们上面使用的对象包括：

- Table - 代表一个数据库表，并将自身分配给 MetaData 集合。
- Column - 表示数据库表中的一列，并将自身分配给一个 Table 对象。Column 通常包含一个字符串名称和一个类型对象。父 Table 下的 Column 对象集合通常可通过位于 Table.c 的关联数组进行访问：
```python
user_table.c.name

user_table.c.keys()
```

- Integer、String——这些类代表 SQL 数据类型，可直接或实例化后传递给Column。上文我们希望为“name”列设置长度为“30”，因此实例化了String(30)。但对于“id”和“全名”列，我们未指定相关参数，因此可以直接传入类本身。

在接下来的小节中，我们将说明Table的一个基本功能，即在特定数据库连接上生成数据定义语言。但首先，我们要声明第二个Table。

## 声明简单的约束

示例 user_table 中的第一个 Column 包含 Column.primary_key 参数，这是一种简写方式，用于表明该 Column 应作为此表主键的一部分。主键本身通常是隐式声明的，由 PrimaryKeyConstraint 结构表示，我们可以在 Table 对象的 Table.primary_key 属性上看到它：
```
user_table.primary_key
PrimaryKeyConstraint(Column('id', Integer(), table=<user_account>, primary_key=True, nullable=False))
```

最典型地显式声明的约束是与数据库外键约束对应的ForeignKeyConstraint对象。当我们声明相互关联的表时，SQLAlchemy 不仅会利用这些外键约束声明的存在，使其在 CREATE 语句中发送到数据库，还会借助它们来构建 SQL 表达式。

仅涉及目标表中单个列的 ForeignKeyConstraint 通常通过 ForeignKey 对象以列级简写符号声明。下面我们声明第二个表 address，该表将包含一个指向 user 表的外键约束：
```python

from sqlalchemy import ForeignKey
address_table = Table(
    "address",
    metadata_obj,
    Column("id", Integer, primary_key=True),
    Column("user_id", ForeignKey("user_account.id"), nullable=False),
    Column("email_address", String, nullable=False),
)
```

*ForeignKey()表示外键约束*

上面的表还包含第三种约束，在 SQL 中这是“非空（NOT NULL）”约束，上文通过Column.nullable参数来表示。

**当然还可以有其他约束条件，请自行探索。**

### 向数据库生成DDL（Data Definition Language 数据定义语句）


它是 SQL 的一类语句，专门用来定义、修改、删除数据库的结构（schema），而不是操作表里的行数据。
常见 DDL 语句
1. CREATE TABLE：创建表（你截图里就有这个）
2. ALTER TABLE：修改表结构（增加字段、改字段类型）
3. DROP TABLE：删除表
4. CREATE INDEX：创建索引

我们构建了一个对象结构来表示数据库中的两个表，该结构从根MetaData对象开始，然后进入两个Table对象，每个对象都包含一组Column和Constraint对象。**这个对象结构将成为我们后续使用核心（Core）和对象关系映射（ORM）执行大多数操作的核心。**

利用这个结构，我们能做的第一件实用之事是向 SQLite 数据库生成 CREATE TABLE 语句，即 DDL，这样我们就能向其中插入数据并进行查询。我们已经具备了完成这一操作所需的全部工具，只需在 MetaData 上调用 MetaData.create_all() 方法，并将指向目标数据库的 Engine 传递给它即可：

```sql
>>> metadata_obj.create_all(engine)
BEGIN (implicit)
PRAGMA main.table_...info("user_account")
...
PRAGMA main.table_...info("address")
...
CREATE TABLE user_account (
    id INTEGER NOT NULL,
    name VARCHAR(30),
    fullname VARCHAR,
    PRIMARY KEY (id)
)
...
CREATE TABLE address (
    id INTEGER NOT NULL,
    user_id INTEGER NOT NULL,
    email_address VARCHAR NOT NULL,
    PRIMARY KEY (id),
    FOREIGN KEY(user_id) REFERENCES user_account (id)
)
...
COMMIT
```


上述 DDL 创建过程包含一些 SQLite 特有的 PRAGMA 语句，这些语句会在发出 CREATE 语句之前检查每个表是否存在。完整的步骤也包含在 BEGIN/COMMIT 语句对中，以适配事务性 DDL。

创建过程还会按正确顺序负责发出 CREATE 语句；上文提到，外键约束依赖于user表的存在，因此address表会被第二个创建。在更复杂的依赖场景中，外键约束也可在事后通过 ALTER 语句应用到表上。

MetaData 对象还包含一个MetaData.drop_all() 方法，该方法会以与生成 CREATE 语句相反的顺序发出 DROP 语句，从而删除架构元素。

**总体而言，MetaData的创建/删除功能适用于测试套件、小型和/或新建应用程序，以及使用短期数据库的应用程序。不过，对于长期管理应用程序数据库架构，基于 SQLAlchemy 构建的Alembic等架构管理工具可能是更优选择，因为它能够随着应用程序设计的变更，管理并协调逐步修改固定数据库架构的流程。**

## 使用ORM声明式定义表的元数据

前面的示例展示了对Table对象的直接使用，SQLAlchemy 正是通过该对象在构建 SQL 表达式时最终引用数据库表。如前所述，SQLAlchemy ORM 为Table的声明过程提供了一层外观，这一过程被称为Declarative Table。Declarative Table 过程实现的目标与上一节相同，即构建Table对象，同时在该过程中还会生成另一种对象，称为ORM 映射类（简称“映射类”）。映射类是使用 ORM 时 SQL 最基础的核心单元，在现代 SQLAlchemy 中，它也能很好地适用于以 Core 为核心的使用场景。

使用声明式表的一些优势包括：

- 一种更简洁且符合 Python 风格的列定义设置方式，其中可使用 Python 类型来表示将在数据库中使用的 SQL 类型
- 生成的映射类可用于构建 SQL 表达式，在许多情况下，这类表达式会保留PEP 484类型信息，而Mypy、IDE 类型检查器等静态分析工具会获取这些信息。
- 允许一次性声明表元数据以及在持久化/对象加载操作中使用的 ORM 映射类。

使用 ORM 时，我们声明 Table 元数据的过程通常与声明 映射 类的过程相结合。映射类是我们想要创建的任意 Python 类，该类后续会包含与数据库表中的列相关联的属性。实现这一目标的方式有多种，但最常见的方式被称为 声明式，它让我们能够同时声明用户自定义的类和 Table 元数据。

## 建立声明式基类

使用 ORM 时，MetaData 集合仍然存在，不过它本身与一个通常被称为 声明式基类 的 ORM 专属结构相关。获取新声明式基类最直接的方法是创建一个继承自 SQLAlchemy DeclarativeBase 的新类：

```python
from sqlalchemy.orm import DeclarativeBase
class Base(DeclarativeBase):
    pass
```
以上，Base 类就是我们所说的声明式基类。当我们创建以 Base 为父类的新类时，结合合适的类级指令，这些类会在创建时各自被设为新的 ORM 映射类，每个类通常（但不绝对）对应一个特定的 Table 对象。

声明式基类还指向一个名为registry的集合，它是SQLAlchemy ORM中核心的“映射器配置”单元。虽然很少直接访问，但该对象是映射器配置过程的核心，因为一组ORM映射类将通过此注册表相互协调。与MetaData的情况类似，我们的DeclarativeBase也为我们创建了一个registry（同样可以选择传入我们自己的registry），我们可以通过DeclarativeBase.registry类变量访问它。

### 声明映射类

在定义好Base后，我们现在可以根据新的类User和Address，为user_account和address表定义ORM映射类。下文将展示声明式映射的最新形式，这种形式通过特殊类型Mapped基于PEP 484类型注解驱动，该类型用于指定要映射为特定类型的属性：

```python
from typing import List
from typing import Optional
from sqlalchemy.orm import Mapped
from sqlalchemy.orm import mapped_column
from sqlalchemy.orm import relationship

class User(Base):
    __tablename__ = "user_account"
    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(30))
    fullname: Mapped[Optional[str]]
    addresses: Mapped[List["Address"]] = relationship(back_populates="user")
    def __repr__(self) -> str:
        return f"User(id={self.id!r}, name={self.name!r}, fullname={self.fullname!r})"

class Address(Base):
    __tablename__ = "address"
    id: Mapped[int] = mapped_column(primary_key=True)
    email_address: Mapped[str]
    user_id = mapped_column(ForeignKey("user_account.id"))
    user: Mapped[User] = relationship(back_populates="addresses")
    def __repr__(self) -> str:
        return f"Address(id={self.id!r}, email_address={self.email_address!r})"
```

上面的两个类，User 和 Address，现在被称为 ORM 映射类，可用于 ORM 持久化和查询操作，相关内容将在后续介绍。这些类的详细信息如下：

- 每个类都引用一个作为声明式映射过程一部分生成的 Table 对象，该对象通过向 DeclarativeBase.__tablename__ 属性赋值一个字符串来命名。类创建后，可从 DeclarativeBase.__table__ 属性访问此生成的 Table 对象。
- 如前所述，这种形式被称为声明式表配置。另一种可选的声明方式是直接构建Table对象，并将其直接赋值给DeclarativeBase.__table__。这种方式被称为命令式表的声明式用法。
- 如前所述，这种形式被称为声明式表配置。另一种可选的声明方式是直接构建Table对象，并将其直接赋值给DeclarativeBase.__table__。这种方式被称为命令式表的声明式用法。

### 从 ORM 映射向数据库生成 DDL

由于我们的 ORM 映射类引用的是 Table 对象，这些对象包含在 MetaData 集合中，因此基于声明式基类生成 DDL 的过程与之前在 向数据库生成 DDL 中描述的过程相同。在我们的示例中，已经在 SQLite 数据库中生成了 user 表和 address 表。如果尚未生成这些表，我们可以直接利用与 ORM 声明式基类相关联的 MetaData，方法是从 DeclarativeBase.metadata 属性访问该集合，然后像之前一样使用 MetaData.create_all()。在这种情况下，会运行 PRAGMA 语句，但由于检测到表已存在，因此不会生成新表。

## 表映射

本节仅对表反射这一相关主题做简要介绍，即如何从现有数据库自动生成Table对象。想要继续编写查询的教程读者可以直接跳过本节。


为完善关于操作表元数据的章节，我们将演示本节开头提及的另一项操作，即表反射。**表反射指的是通过读取数据库的当前状态来生成Table及相关对象的过程。**在前几节中，我们一直在Python中声明Table对象，随后可选择向数据库发送DDL语句来生成此类模式；而反射过程则以现有数据库为起点，反向完成这两个步骤，并生成用于表示该数据库中模式的Python数据结构。

*使用 SQLAlchemy 配合现有数据库，并非必须使用反射。SQLAlchemy 应用程序在 Python 中显式声明所有元数据是完全常见的做法，这样其结构就能与现有数据库对应。元数据结构也无需包含本地应用程序运行所不需要的、现有数据库中的表、列或其他约束及构造。*
