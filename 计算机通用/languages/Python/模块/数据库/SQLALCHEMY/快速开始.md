# ORM 快速入门

## SQLAIchemy的执行流程

```
你的代码
  ↓
SQLAlchemy ORM（写法统一）
  ↓
数据库驱动（pg=psycopg，mysql=pymysql…）
  ↓
数据库（PG / MySQL / SQLite…）
```

底层驱动数据库连接的python库可能不同，但是都是连接数据库并对其进行操作，比如连接PostgreSQL数据库的python库为：psycopg，其需要首先初始化一个psycopg.Connection()连接，然后通过操作cnt.cursor()进行数据库的操作，以及可能使用cnt.transaction()进行特殊的管理。

## 声明模型(Python class->table mapping)

在这里，我们定义模块级的构造，这些构造将构成我们要从数据库中查询的结构。这种被称为声明式映射的结构，同时定义了一个Python对象模型，以及数据库元数据，后者描述了特定数据库中已存在或即将存在的真实SQL表。

```python
from typing import List
from typing import Optional
from sqlalchemy import ForeignKey
from sqlalchemy import String
from sqlalchemy.orm import DeclarativeBase
from sqlalchemy.orm import Mapped
from sqlalchemy.orm import mapped_column
from sqlalchemy.orm import relationship

class Base(DeclarativeBase):
    pass

class User(Base):
    __tablename__ = "user_account"
    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(30))
    fullname: Mapped[Optional[str]]
    addresses: Mapped[List["Address"]] = relationship(
        back_populates="user", cascade="all, delete-orphan"
    )
    def __repr__(self) -> str:
        return f"User(id={self.id!r}, name={self.name!r}, fullname={self.fullname!r})"

class Address(Base):
    __tablename__ = "address"
    id: Mapped[int] = mapped_column(primary_key=True)
    email_address: Mapped[str]
    user_id: Mapped[int] = mapped_column(ForeignKey("user_account.id"))
    user: Mapped["User"] = relationship(back_populates="addresses")
    def __repr__(self) -> str:
        return f"Address(id={self.id!r}, email_address={self.email_address!r})"
```

映射从一个基类开始，该基类在上方被称为Base，它是通过针对DeclarativeBase类创建一个简单的子类来生成的。

然后通过创建 Base 的子类来生成各个独立的映射类。一个映射类通常对应一张特定的数据库表，表名通过 __tablename__ 这个类级属性来指定。


接下来，通过添加包含名为Mapped的特殊类型注解的属性，来声明构成表的列。每个属性的名称对应于要成为数据库表一部分的列。每列的数据类型首先从与每个Mapped注解相关联的Python数据类型中获取；int对应INTEGER，str对应VARCHAR，以此类推。可空性取决于是否使用了Optional[]（或其等效的）类型修饰符。可在右侧的mapped_column()指令中使用SQLAlchemy类型对象来指定更具体的类型信息，例如上述User.name列中使用的String数据类型。可通过类型注解映射自定义Python类型与SQL类型之间的关联。

mapped_column() 指令用于所有需要更具体自定义的基于列的属性。除了类型信息外，该指令还接受多种参数，用于指定有关数据库列的特定细节，包括服务器默认值和约束信息（例如主键和外键中的成员身份）。mapped_column() 指令接受的参数是 SQLAlchemy Column 类所接受参数的超集，而 SQLAlchemy Core 会使用该类来表示数据库列。

**所有 ORM 映射类都要求至少有一个列被声明为主键的一部分，通常是在应作为主键组成部分的mapped_column()对象上使用Column.primary_key参数。**在上述示例中，User.id和Address.id列被标记为主键。

总而言之，在 SQLAlchemy 中，字符串表名与列声明列表的组合被称为表元数据。在SQLAlchemy 统一教程的使用数据库元数据部分，介绍了如何同时使用 Core 和 ORM 方法来设置表元数据。上述映射是所谓的带注释的声明式表配置的一个示例。


Mapped的其他变体也可用，最常见的是上文所示的relationship()结构。与基于列的属性不同，relationship()表示两个ORM类之间的关联。在上述示例中，User.addresses将User与Address关联，而Address.user将Address与User关联。relationship()这一结构在SQLAlchemy 统一教程的处理ORM关联对象部分进行了介绍。

最后，上述示例类包含一个 __repr__() 方法，该方法并非必需，但对调试很有用。映射类可以通过自动生成的 __repr__() 等方法结合数据类来创建。有关数据类映射的更多内容，请参见 声明式数据类映射。

## Create Engine

Engine是一个工厂，可以为我们创建新的数据库连接，还会将连接保留在连接池中以便快速复用。出于学习目的，为方便起见，我们通常使用SQLite内存数据库：
```python
>>> from sqlalchemy import create_engine
>>> engine = create_engine("sqlite://", echo=True)
```

## 生成CREATE TABLE语句

使用我们的表元数据和引擎，我们可以通过一种名为 MetaData.create_all() 的方法，一次性在目标 SQLite 数据库中生成我们的模式：

```python
 Base.metadata.create_all(engine)
BEGIN (implicit)
```

当你写class UserAccount(Base):，定义这个类的一瞬间（类加载阶段，不是实例化）Base 带了一个自定义元类 DeclarativeMeta，会拦截子类的定义过程。元类扫描类里面的__tablename__、Column(...)字段，在底层自动生成一个Table对象。
这个自动生成的Table对象，会自动注册到Base.metadata这个集合里面。metadata本质就是一张大清单，收集所有表定义。
执行Base.metadata.create_all(engine)
metadata 遍历自己内部保存的全部Table对象，向数据库发送CREATE TABLESQL 语句，生成截图那一堆 SQL。
注意：子类本身不会直接被 create_all 扫描；扫描的是 metadata 里面收集到的 Table 对象。子类只是载体，元类帮你把 Table 提取出来放到 metadata 注册表。

PRAGMA main.table_...info("user_account")
...
PRAGMA main.table_...info("address")
...
CREATE TABLE user_account (
    id INTEGER NOT NULL,
    name VARCHAR(30) NOT NULL,
    fullname VARCHAR,
    PRIMARY KEY (id)
)
...
CREATE TABLE address (
    id INTEGER NOT NULL,
    email_address VARCHAR NOT NULL,
    user_id INTEGER NOT NULL,
    PRIMARY KEY (id),
    FOREIGN KEY(user_id) REFERENCES user_account (id)
)
...
COMMIT


## 创建对象并持久化

我们现在已经准备好向数据库中插入数据了。我们通过创建User和Address类的实例来完成这一操作，这些类已经通过声明式映射流程自动生成了__init__()方法。随后我们通过一个名为Session的对象将这些实例传入数据库，该对象会借助Engine与数据库进行交互。这里使用了Session.add_all()方法来一次性添加多个对象，而Session.commit()方法则会将所有待处理的更改刷新到数据库中，随后提交当前的数据库事务——每当使用Session时，该事务始终处于进行状态。

```python
from sqlalchemy.orm import Session

with Session(engine) as session:
    spongebob = User(
        name="spongebob",
        fullname="Spongebob Squarepants",
        addresses=[Address(email_address="spongebob@sqlalchemy.org")],
    )
    sandy = User(
        name="sandy",
        fullname="Sandy Cheeks",
        addresses=[
            Address(email_address="sandy@sqlalchemy.org"),
            Address(email_address="sandy@squirrelpower.org"),
        ],
    )
    patrick = User(name="patrick", fullname="Patrick Star")
    session.add_all([spongebob, sandy, patrick])
    session.commit()
```

Session创建，底层是惰性连接，只有在add_all等操作的时候才正式建立连接，同理session.commit()底层是调用的对应驱动库的commit，将数据更新到数据库中。


*建议以如上所示的 contextmanager 风格使用Session，即使用 Python with: 语句。Session 对象代表活动的数据库资源，因此最好在完成一系列操作后将其关闭。在下一节中，我们将保持Session处于打开状态，仅作演示之用。*

## 简单的SELECT

有了数据库中的一些数据，下面是发出 SELECT 语句以加载某些对象的最简单方式。要创建 SELECT 语句，我们使用select() 函数创建一个新的 Select 对象，然后通过 Session 调用它。在查询 ORM 对象时，常用的方法是 Session.scalars() 方法，该方法会返回一个 ScalarResult 对象，该对象将遍历我们选择的 ORM 对象：

```python
from sqlalchemy import select

session = Session(engine)

stmt = select(User).where(User.name.in_(["spongebob", "sandy"]))

for user in session.scalars(stmt):
    print(user)
```

session.scalars的执行逻辑：
```
session.scalars(stmt)
    ↓
1. Session把select语句交给内部Connection（SQLAlchemy Core层）
    ↓
2. Connection 获取底层 psycopg DBAPI connection
    ↓
3. 拿到 dbapi_cursor = dbapi_connection.cursor()
    ↓
4. dbapi_cursor.execute(编译后的SQL, 参数元组)   # ←就是你说的cursor.execute
    ↓
5. 获取游标结果，ORM把数据库行数据 → 组装成 User 对象
    ↓
6. scalars：只取结果集**第一列**（这里第一列就是User实体对象），返回迭代器
```

## 带JOIN的查询

同时对多个表进行查询非常常见，在 SQL 中，JOIN 关键字是实现这一操作的主要方式。Select 构造通过 Select.join() 方法创建连接：
```python
stmt = (
    select(Address)
    .join(Address.user)
    .where(User.name == "sandy")
    .where(Address.email_address == "sandy@sqlalchemy.org")
)
sandy_address = session.scalars(stmt).one()
print(sandy_address)
```
等价于下面的SQL语句；
```sql
SELECT address.id, address.email_address, address.user_id
FROM address JOIN user_account ON user_account.id = address.user_id
WHERE user_account.name = ? AND address.email_address = ?
[...] ('sandy', 'sandy@sqlalchemy.org')
```

因为如下

```python
class Address(Base):
    __tablename__ = "address"
    id = Column(Integer, primary_key=True)
    email_address = Column(String, nullable=False)
    user_id = Column(Integer, ForeignKey("user_account.id"))

    # 关键：这个就是 Address.user
    user = relationship("UserAccount", back_populates="addresses")
```
Address.user 不是普通字段，是 **relationship()对象 **，它内部记住了：
关联目标表：user_account
外键对应：Address.user_id ↔ UserAccount.id
当你写 .join(Address.user)，传给 join 方法的是这个 relationship 对象，不是表名。SQLAlchemy 自动从 relationship 定义提取出外键映射，自动拼接出上面的JOIN ON

上述查询展示了多个使用 AND 自动串联的 WHERE 条件，同时也展示了如何利用 SQLAlchemy 的类列对象来创建“相等”比较——这种方式会重写 Python 方法 ColumnOperators.__eq__()，从而生成一个 SQL 条件对象。

## 进行修改

Session对象结合我们的ORM映射类User和Address，会在对象发生更改时自动追踪这些变更，这些变更会在下次Session刷新时触发对应的SQL语句执行。下面，我们先执行一条SELECT语句查询“patrick”的记录，随后修改与“sandy”关联的一个邮箱地址，并为“patrick”新增一个邮箱地址。

```python
stmt = select(User).where(User.name == "patrick")
patrick = session.scalars(stmt).one()
patrick.addresses.append(Address(email_address="patrickstar@sqlalchemy.org"))
sandy_address.email_address = "sandy_cheeks@sqlalchemy.org"

session.commit()
```

注意，当我们访问patrick.addresses时，会发出一条SELECT语句。这被称为懒加载。有关使用不同SQL用量访问相关项的各种方式的背景信息，可在加载器策略中了解。

## 部分删除

凡事皆有终结之时，我们数据库中的部分行也是如此——这里快速演示两种不同的删除方式，具体使用哪种方式取决于实际场景，二者都很重要。

### 级联删除

首先，我们将从“sandy”用户中删除一个Address对象。当Session下一次刷新时，这将导致该行被删除。这种行为是我们在映射中配置的，称为级联删除。我们可以使用Session.get()通过主键获取sandy对象的引用，然后对该对象进行操作：

```python
sandy = session.get(User, 2)
sandy.addresses.remove(sandy_address)
```

等效语句：
```sql
BEGIN (implicit)
SELECT user_account.id AS user_account_id, user_account.name AS user_account_name, user_account.fullname AS user_account_fullname
FROM user_account
WHERE user_account.id = ?
[...] (2,)
SELECT address.id AS address_id, address.email_address AS address_email_address, address.user_id AS address_user_id
FROM address
WHERE ? = address.user_id
[...] (2,)
```


上面的最后一条 SELECT 是懒加载操作，目的是加载sandy.addresses集合，以便我们可以移除sandy_address成员。还有其他方法可以执行这一系列操作，且不会生成如此多的 SQL 语句。

我们可以选择通过Session.flush()方法，为目前已设置为待修改的数据生成 DELETE SQL 语句，而不提交事务：
`session.flush()`

### 顶级删除

接下来，我们将彻底删除“patrick”用户。对于单独对对象执行的顶级删除操作，我们使用Session.delete()方法；该方法实际上不会执行删除，而是将对象设置为在下次刷新时删除。该操作还会根据我们配置的级联选项级联到相关对象，在本例中，会关联到相关的Address对象：

```python
session.delete(patrick)
```

```sql
SELECT user_account.id AS user_account_id, user_account.name AS user_account_name, user_account.fullname AS user_account_fullname
FROM user_account
WHERE user_account.id = ?
[...] (3,)
SELECT address.id AS address_id, address.email_address AS address_email_address, address.user_id AS address_user_id
FROM address
WHERE ? = address.user_id
[...] (3,)
```

在这种特定情况下，Session.delete() 方法会发出两条 SELECT 语句，却不会发出 DELETE 语句，这可能有些出人意料。这是因为当该方法去检查对象时，发现patrick对象已过期，而这种过期发生在我们上次调用Session.commit()时，发出的 SQL 语句是为了从新事务中重新加载行。这种过期机制是可选的，在日常使用中，对于那些不适用该机制的场景，我们通常会将其关闭。

为了说明被删除的行，这里展示一下提交操作：
```python
>>> session.commit()

```
```sql
DELETE FROM address WHERE address.id = ?
[...] (4,)
DELETE FROM user_account WHERE user_account.id = ?
[...] (3,)
```
