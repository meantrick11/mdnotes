## 简单尝试

与psql相比，Psycopg 存在一种可能令人意外的行为：默认情况下，任何数据库操作都会启动一个新事务。因此，在调用Connection.commit()之前，连接的任何游标所做的更改都不可见，并且这些更改会被Connection.rollback()丢弃。同一连接上的后续操作将启动一个新事务。

如果在有未完成事务的情况下关闭连接，系统不会向服务器发送 COMMIT 命令，服务器随后会丢弃该连接。某些中间件（如 PgBouncer）也会丢弃处于事务状态的连接，因此，在完成对连接的操作前，最好先提交或回滚事务。

```python
conn = psycopg.connect()

# Creating a cursor doesn't start a transaction or affect the connection
# in any way.
cur = conn.cursor()

cur.execute("SELECT count(*) FROM my_table")
# This function call executes:
# - BEGIN
# - SELECT count(*) FROM my_table
# So now a transaction has started.

# If your program spends a long time in this state, the server will keep
# a connection "idle in transaction", which is likely something undesired

cur.execute("INSERT INTO data VALUES (%s)", ("Hello",))
# This statement is executed inside the transaction

conn.close()
# No COMMIT was sent: the INSERT was discarded.
```

上述连接中并没有使用Connection.commit()进行提交事务，所以所作的更改不会写入磁盘中，且消失。

### 使用连接上下文with


```python
with psycopg.connect() as conn:

    cur = conn.cursor()

    cur.execute("SELECT count(*) FROM my_table")
    # This function call executes:
    # - BEGIN
    # - SELECT count(*) FROM my_table
    # So now a transaction has started.

    cur.execute("INSERT INTO data VALUES (%s)", ("Hello",))
    # This statement is executed inside the transaction

# No exception at the end of the block:
# COMMIT is executed.
```

使用python的with，可以帮你省去手动Connection.commit()&connection.close()，进而更专注内部的cursor操作。

**如果执行正常，那么会自动commit()+close()，如果有报错则会connection.rollback()+close()**


## 自动提交事务
可通过 autocommit（可作为连接属性或 connect() 参数）暂停手动提交要求。运行无法在事务内执行的操作时可能需要此设置，例如 CREATE DATABASE、VACUUM、对使用事务控制的 存储过程 执行 CALL。

**PostgreSQL中的事务不能嵌套，并且有些操作要求自己是顶层事务比如CREATE TABLE，VACUUM等，即不能手动BEGIN包裹，所以需要开启autocommit即将所有操作都直接传递给数据库进行自动包裹，数据库会自动识别是否需要自己是顶层事务，如果是则不再隐式begin包裹事务，如果不是，才会begin包裹**

```python
with psycopg.connect(autocommit=True) as conn:

    cur = conn.cursor()

    cur.execute("SELECT count(*) FROM my_table")
    # This function call now only executes:
    # - SELECT count(*) FROM my_table
    # and no transaction starts.

    cur.execute("INSERT INTO data VALUES (%s)", ("Hello",))
    # The result of this statement is persisted immediately by the database

# The connection is closed at the end of the block but, because it is not
# in a transaction state, no COMMIT is executed.
```

## 事务上下文

一种更透明的确保交易在正确时间完成的方法是使用 with Connection.transaction() 创建一个事务上下文。进入上下文时，会启动一个事务；离开上下文时，会提交事务，如果代码块内引发异常，则会回滚事务


继续上面的示例，如果你想使用自动提交连接，但仍希望将选定的命令组封装在原子事务中，可以使用transaction()上下文：

```python
with psycopg.connect(autocommit=True) as conn:  #设置自动提交，每条操作都会执行

    cur = conn.cursor()

    cur.execute("SELECT count(*) FROM my_table")
    # The connection is autocommit, so no BEGIN executed.
    #手动管理多个操作为同一个事务，需要transaction()
    with conn.transaction():
        # BEGIN is executed, a transaction started

        cur.execute("INSERT INTO data VALUES (%s)", ("Hello",))
        cur.execute("INSERT INTO times VALUES (now())")
        # These two operation run atomically in the same transaction

    # COMMIT is executed at the end of the block.
    # The connection is in idle state again.

# The connection is closed at the end of the block.
```

## 资深经验

1. 使用连接块：with psycopg.connect(...) as conn；
2. 使用自动提交连接，可将 autocommit=True 作为 connect() 参数传入，或设置属性 conn.autocommit =True。
3. 仅在需要时使用with conn.transaction()代码块来管理事务。

```python
import psycopg

DSN = "dbname=test user=postgres"

# 业务事务：默认非 autocommit，用 with 自动管理
def transfer_money(from_id, to_id, amount):
    with psycopg.connect(DSN) as conn:
        with conn.cursor() as cur:
            cur.execute(
                "UPDATE accounts SET balance = balance - %s WHERE id = %s",
                (amount, from_id)
            )
            cur.execute(
                "UPDATE accounts SET balance = balance + %s WHERE id = %s",
                (amount, to_id)
            )
    # 无异常 -> 自动 COMMIT；有异常 -> 自动 ROLLBACK，异常继续往外抛

# 维护任务：需要 autocommit
def run_vacuum(table_name):
    with psycopg.connect(DSN, autocommit=True) as conn:
        with conn.cursor() as cur:
            cur.execute(f"VACUUM {table_name}")
```
## 嵌套事务

PostgreSQL不支持嵌套事务，但内部事务通过SAVEPOINT进行保存点嵌套，其实不是真正的事务嵌套，只有外层才有Begin进行事务start


事务块也可以嵌套（内部事务块通过SAVEPOINT实现）：在内部块中引发的异常有可能被处理，从而不会完全导致外部操作失败。以下是一个示例，其中一系列操作与数据库交互：允许操作失败；最终我们还希望存储成功处理的操作数量。

```python
with conn.transaction() as tx1: # 真实BEGIN，主事务
    num_ok = 0
    for operation in operations:
        try:
            with conn.transaction() as tx2: # 生成SAVEPOINT，不是BEGIN
                unreliable_operation(conn, operation)
        except Exception:
            logger.exception(f"{operation} failed")
        else:
            num_ok +=1
    save_number_of_successes(conn, num_ok)
# 退出tx1，执行真正COMMIT
```

## 事务状态

每个Transaction对象都会公开一个status属性，用于查看交易的当前状态。这对于调试、记录日志或实现自定义交易管理逻辑可能会很有用。

status属性是一个psycopg.Transaction.Status枚举值：请查看其文档以了解可能的取值。


```python
以下是使用status属性的几个示例：

from psycopg import Rollback

# Successful transaction
with conn.transaction() as tx:
    assert tx.status == tx.Status.ACTIVE
    conn.execute("INSERT INTO data VALUES (%s)", ("Hello",))
assert tx.status == tx.Status.COMMITTED

# Transaction rolled back with an error
try:
    with conn.transaction() as tx:
        conn.execute("INSERT INTO data VALUES (%s)", ("World",))
        1 / 0  # Causes an exception
except ZeroDivisionError:
    pass
assert tx.status == tx.Status.ROLLED_BACK_WITH_ERROR

# Explicit rollback
with conn.transaction() as tx:
    conn.execute("INSERT INTO data VALUES (%s)", ("Test",))
    raise Rollback()
assert tx.status == tx.Status.ROLLED_BACK_EXPLICITLY

# Force rollback
with conn.transaction(force_rollback=True) as tx:
    conn.execute("INSERT INTO data VALUES (%s)", ("Temp",))
assert tx.status == tx.Status.ROLLED_BACK_EXPLICITLY
```
