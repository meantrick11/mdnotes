# 模板字符串传参

Psycopg支持Python的官方标准的PEP750，也就是模板字符串查询

`cursor.execute(t"SELECT * FROM mytable WHERE id = {id}")`


举个例子：

```python
cursor.execute(
    t"INSERT INTO mytable (first_name, last_name) VALUES ({first_name}, {last_name})"
)
```

上述使用模板字符串的传参方式等同于以下使用占位符传参的方式：

```python
cursor.execute(
    "INSERT INTO mytable (first_name, last_name) VALUES (%s, %s)",
    (first_name, last_name),
)
```

前者遍历的一点就是Python变量名直接在SQL语句中使用，而不是后置传递

**使用模板字符串，除参数值之外，我们也可以很方便地对查询语句的其他部分做参数化处理，例如表名或者字段名：**
```python
cursor.execute(
    t"INSERT INTO {table_name:i} (first_name, last_name) VALUES ({first_name}, {last_name})"
)
```
:i = identifier（标识符）。表名、列名属于 SQL 标识符，不能用普通参数绑定，需要客户端转义后直接拼接进 SQL 字符串。

**两种传参方式：模板字符串+分开传参，只要不直接使用+，%进行拼接字符串，都可以达到安全传参**


## 格式说明符（Format specifiers）
可以在占位符中使用 `:`，为模板字符串插值指定格式说明符，例如 `{id:b}`。Psycopg 支持两类格式说明符：一类规定**如何把参数传给数据库服务端**；另一类规定**如何在客户端组装SQL片段**，效果和使用`psycopg.sql`对象类似。

## 参数格式说明符（传给服务端）
- `s`：自动参数格式，等价传统查询里的`%s`。**不写格式说明符时默认就是`s`**。
- `b`：使用**二进制格式**传递参数，等价传统写法`%b`。
- `t`：使用**文本格式**传递参数，等价传统写法`%t`。

## SQL查询组装说明符（客户端本地拼接SQL片段）
> ⚠️这一类是在客户端把内容直接拼进SQL字符串，不是服务端参数绑定
- `i`：代表**SQL标识符**，如表名、列名。传入的值必须是字符串，或是`sql.Identifier`对象。
- `l`：代表**字面量值**，会在客户端直接合并到SQL语句。用于PostgreSQL本身**不支持参数化**的语句场景。
- `q`：代表一段SQL代码片段，原样嵌入SQL。传入值必须是另一个模板字符串，或是`sql.SQL` / `Composed`实例。

---
### 关键理解区分
1. **`:s / :b / :t`（参数类）**
数据不会拼进SQL文本，走PostgreSQL协议传给服务端，**防注入，普通业务值用这个（默认:s，一般不用显式写）**。

2. **`:i / :l / :q`（组装类，client‑side）**
在Python客户端直接拼入SQL字符串：
- `:i`：表/列名，做标识符转义（加双引号）；
- `:l`：字面量，会给字符串加单引号转义；
- `:q`：直接原样嵌入SQL片段，**完全不转义，风险最高，只能传安全预构造的SQL片段，绝对不能接收用户输入**。

### 简单示例
```python
# :s 默认，可以省略 :s
t"SELECT * FROM tbl WHERE id = {id}"

# :i 标识符（表名）
t"SELECT * FROM {tbl:i} WHERE id = {id}"

# :l 字面量，客户端拼接字面量
t"SET timezone = {tz:l}"

# :q 嵌入另一段安全SQL片段
part = t"WHERE status = 1"
t"SELECT * FROM users {part:q}"
```

> 踩坑提醒：
> - 不要拿`:l`处理普通用户输入，优先用默认`:s`参数绑定；
> - `:q`只能传入程序内部生成的SQL片段，绝对不能放用户输入，会直接SQL注入。
